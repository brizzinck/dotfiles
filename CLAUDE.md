# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

Personal dotfiles for an Arch Linux / Hyprland / Wayland setup, managed with **GNU Stow**. Running `stow .` from the repo root symlinks everything into `$HOME`, mirroring the directory structure. Non-config files are excluded via `.stow-local-ignore`.

## Setup

```bash
git clone --recursive <repo>
git submodule update --init --recursive
chmod +x install.sh && ./install.sh
```

`install.sh` does a full machine bootstrap: pacman packages, AUR (via yay), Flatpak apps, Go/NPM/Rust toolchains, Oh My Zsh, Docker setup, SSH key generation, then runs `stow .` to link the dotfiles and `browsers/apply.sh` to copy the browser settings. Root-level system changes (packages, `/etc`, timers, fstab, grub) are applied separately by `sudo ./apply-system.sh`; `./doctor.sh` verifies the result.

After modifying dotfiles, re-apply with:
```bash
cd ~/dotfiles && stow .
```

## Architecture

### Config layout
All configs live under `.config/` following XDG Base Dir. Root-level files (`.zshrc`, `.gitconfig`) stow directly to `$HOME`.

### Monitor management
Static Hyprland rules in `.config/hypr/monitors.lua` (loaded by `hyprland.lua` with `dofile`; `scripts/lid.sh` re-applies the panel rule from the same table): `HDMI-A-1` 2560x1440@144 at `0x0`, the laptop panel `eDP-1` 2880x1800@120 scaled 1.5 at `0x1440` (below the external one), plus a `preferred, auto` fallback for any other output. Hyprland applies them on hotplug, so there is no kanshi, no polling script and no monitor daemon.

### Hyprland config (Lua)
`.config/hypr/hyprland.lua` (+ `monitors.lua`) is the only Hyprland config; there is no `hyprland.conf` (`doctor.sh` checks that it is absent and that the running instance loaded the Lua file). hyprlock, hypridle and the screensaver stay hyprlang. In a Lua config `hyprctl keyword` is gone and `hyprctl dispatch` takes a Lua expression: scripts call `.local/bin/hyprd` (legacy dispatcher names, e.g. `hyprd focuswindow address:0x..`) or `hyprctl eval '<lua>'`. Binds are `hl.bind("SUPER + X", hl.dsp..., { description = "..." })` (descriptions feed the cheatsheet, the hub and `docs/keymap.md`; no commas). `hyprctl binds -j` reports Lua binds as dispatcher `__lua`, so nothing can be read back from it: `hyprland.lua` wraps `hl.bind` and records every dispatcher in a registry, and `hyprctl eval 'df_bind_run("SUPER+Return")'` replays one (mods in SUPER CTRL ALT SHIFT order, key as in the live table, case-insensitive). The hub uses that for its keybind rows (`kind bind`) and for the leader. Hyprland 0.55/0.56 runs a `catchall` bind next to the matching bind and on a lone modifier press (hyprwm/Hyprland#15063), so the repeat modes (`resize`, `mouse`) leave through `leave_on_other_key()`, which ignores the event while one of the mode's own keys or a modifier is held.

### Theme system
Idle (`.config/hypr/hypridle.conf`): dim at 150 s, at 300 s a clock-only hyprlock screensaver (`screensaver.conf`, started by `scripts/screensaver.sh`, no password; any input dismisses it via hypridle on-resume + `SIGUSR1`), panel off (`dpms`) at 1200 s. The machine never suspends or locks by itself, and nothing is killed. All listeners are skipped while media plays or an automation Chrome runs (`idle-allowed.sh`; Wayland/DBus inhibitors are honoured too). `SUPER+Escape` is still the real password lock.

The palette is **Everforest v2** with two switchable variants: **black** (default, pure `#000000` backgrounds) and **night** (near-black `#0a0e0c` content background; bar, lock screen, screensaver and the Hyprland background stay `#000000`). fg, accents and ANSI 0-15 are shared. Source of truth: `themes/palette/everforest.json` (tokens) with the human-readable `themes/palette/palette.md` (token roles, per-app mapping, owner steps). `themes/palette/render.py` (stdlib Python, `PYTHONPYCACHEPREFIX=/tmp/pycache python3 themes/palette/render.py`, `--check` for doctor) renders every `templates/*.tmpl` for both variants into the committed `themes/generated/{black,night}/`; a new app only needs a new template. The active variant is the symlink `~/.local/state/theme/current -> themes/generated/<variant>`, and `theme black|night|toggle|status|init` (`.local/bin/theme`, hub row "Theme: black / night") flips it, reloads ghostty (SIGUSR2), alacritty, every tmux server of the user and nvim, then runs the hooks in `.config/theme/hooks.d/` (`10-hyprland` reload + configerrors check, `20-waybar` SIGUSR2, `30-dunst` `dunstctl reload`, `40-swayosd` restart, `50-qt`). A missing link is recreated as black by `install.sh`, `.zshrc`, tmux.conf and the first Hyprland autostart line.

Window look (`hyprland.lua` + the fragment): solid calm colours, no gradient and no shadow. Active border `green_soft`, inactive `line` (almost invisible; the gaps separate tiles), group border and active groupbar tab `purple_soft`, blocked grouping `yellow_soft`. Hyprland renders `round(border_size * scale)` physical pixels and rounds every box to whole pixels, so `border_size` (2 = 2 px on HDMI-A-1, 3 px on eDP-1) and the gaps (4 = 4 / 6 px) must be even to stay crisp at scale 1.5 (odd sizes round up: 3 -> 5 px); `rounding_power = 2`. A two-colour gradient on a 2-3 px stripe bands visibly and was the pixelated look. How each app follows the variant: `hyprland.lua` `dofile`s the black fragment (fallback) and then `current/hyprland.lua` inside `pcall` (a missing or broken fragment is skipped with a notification, black stays); hyprlock and the screensaver (hyprlang) `source` the black fragment and then `current/` (a missing sourced file is a config error, hence the fallback); waybar, wofi, swayosd and both GTK versions `@import` a repo symlink `theme-black.css` plus `theme.css` -> `current/...`; rofi `@import`s the same pair of paths; dunst reads `dunstrc.d/40-theme-black.conf` and `50-theme.conf` drop-ins; btop (`themes/everforest-v2.theme`) and qt6ct (`colors/everforest.conf`) are symlinks to `current/`; lazygit merges `current/lazygit.yml` through `LG_CONFIG_FILE` (set by `.zshrc`, tmux and hub); lazydocker uses ANSI names, so it follows the terminal palette. Literals that cannot follow (pango spans in `waybar/config`, workmux icons) hold token hex and are checked by `doctor.sh`. Generated but applied by hand: `everforest-<variant>.tdesktop-theme` (Telegram), `obsidian.css`, `claude-theme.json`; GTK/Qt apps pick up a switch at their next start. Owner steps are in `themes/palette/palette.md`. `themes/static/everforest-black/` only holds a pointer note now; the other directories in `themes/static/` (rose-pine, dracula, catppuccin-mocha, ...) and `themes/templates/` (matugen, wallust, pywal) are unused leftovers of the old HyprDynamicMonitors setup.

Wallpaper (W2): the owner's two-tone art is a committed vector, `themes/palette/templates/wallpaper.svg.tmpl` (potrace trace; figure `green_soft` on `bg_oled`) rendered into `themes/generated/{black,night}/wallpaper.svg`; no raster is ever committed (the source PNG stays in `~/pics/walls/`, the re-trace recipe is in the header of the script). `.config/hypr/scripts/wallpaper.sh apply|render|status [--dry-run] [--force]` reads `current/wallpaper.svg`, renders one PNG per output from `hyprctl monitors -j` at its native PHYSICAL size with `rsvg-convert` into `~/.cache/wallpaper/<output>-<WxH>-<hash>.png` (the 16:9 art is fitted whole and centred, so on the 16:10 panel the rest is the same black; never cropped) and keeps exactly one `swaybg -o NAME -i FILE -m fill` per output (only changed instances restart). It runs from the autostart, the `monitor.added` hook, `SUPER+O` (`--force`) and the theme hook `60-wallpaper.sh`; doctor `wallpaper` checks it.

### Bar (waybar)
Two bar objects per output in one waybar process (`.config/waybar/config` includes `modules.jsonc` and a state file each): **compact** (base bar, exclusive zone) and **full** (non-exclusive overlay with `margin-top: -28`, drawn over compact). `SUPER+B` = compact/full (`scripts/bar.sh mode toggle`, SIGUSR1 reaches only the full bar, so the exclusive zone and windows never move), `SUPER+CTRL+B` = hide/show everything (`bar.sh hide toggle`, a reload). State: `~/.local/state/waybar/{mode,hidden}`; `bar.sh render` writes `compact.jsonc`/`full.jsonc` (`start_hidden`) that the config includes, so the mode survives restarts, theme reloads (`bar.sh reload`) and logins (`bar.sh init` clears `hidden`). **Never send SIGUSR1 by hand**; a toggle leaves `$XDG_RUNTIME_DIR/waybar-bar/stale`, and the `monitor.added` hook runs `bar.sh sync --if-stale` so a new monitor gets the right mode. Signals (`pkill -o -u $(id -u) -RTMIN+N -x waybar`, `-o` so a script child that is still named waybar is not hit): 8 toggles drawer and summary, 9 updates, 15 vault; the recording module is a continuous script. Scripts print `class` = `normal|dim|enabled|warning|critical`, `style.css` maps them to palette tokens (green active/enabled, calm yellow_soft warning and red_soft critical tints without pill or bold, everything else grey; the AI module is never highlighted, an exhausted limit is normal; its text is `C 26·4  X –·100` = Claude and Codex % used, 5h·weekly, `–` = no data, from `ai-usage.sh`). Alert modules print nothing until relevant; `cache.sh` shares one run of the expensive ones (health, updates, ai) between the two bars; `toggles.sh` is the single source of the switch states. The compact -> full switch is animated by a GTK CSS opacity transition on the full bar (`style.css`): SIGUSR1 only moves that surface between layers, which never maps or unmaps it, so Hyprland layer rules and animations cannot fire (checked: no openlayer/closelayer events); drawers use waybar's own 220 ms revealer. Click grammar: L main, R menu, M quick binary action, scroll value; menus are fzf-menu based. Every tooltip ends with the same hint line, `L: x · M: y · R: z · Scroll: w` (that order, lowercase actions, idle buttons omitted). `WAYBAR_LOG_LEVEL=debug bar.sh restart` logs the GTK widget tree (`$XDG_RUNTIME_DIR/waybar-bar/waybar.log`). doctor checks bar-state, bar-layers (surfaces with the layer namespaces `waybar-compact` / `waybar-full` per monitor), bar-reserved, bar-css. **Watchdog**: `scripts/waybar-run.sh` is a supervisor, not an `exec`: waybar is its child and an abnormal exit (signal, non-zero status) restarts it after 1/2/5/10 s (`journalctl -t waybar-run` has status or signal), one low-urgency "Waybar crashed and was restarted" notification once it stayed up 5 s, and 5 crashes within 120 s end the loop with one "Waybar keeps crashing" notification (`bar.sh restart` starts it again). It checks (never blindly starts) the `ws-ipc-proxy.py` and `pinned-watch.py` daemons on each round, so a restart does not duplicate them. Status 0, SIGTERM/SIGINT/SIGHUP and a vanished Wayland socket are no crash; `bar.sh restart` first stops the supervisor with SIGTERM (pidfile `$XDG_RUNTIME_DIR/waybar-bar/supervisor.pid`, flock `supervisor.lock`; it forwards the SIGTERM to waybar) and then starts a new one, so `reload`/`hide` (SIGUSR2) and a restart never look like a crash; doctor `bar-watchdog`. Crash traces: `DEBUGINFOD_URLS` is already set (`/etc/profile.d/debuginfod.sh`, libdebuginfod comes with `libelf`; the `debuginfod` package, which is only the server and `debuginfod-find`, is not installed and not needed), so `coredumpctl debug waybar --debugger-arguments="-batch -ex 'set debuginfod enabled on' -ex 'thread apply all bt 25'"` symbolizes a good core. The waybar cores seen so far are `truncated` (1-2 MB, `coredumpctl list waybar`), so gdb stops with "Cannot access memory" and `coredumpctl info` shows `#0 n/a`: until a full core exists the only evidence is the signal in the journal and the `waybar.log` lines before it (the one SIGABRT caught while testing the watchdog came right after a burst of SIGUSR2 reloads).

The health badge (`custom/health`, `health.sh` over `failed.sh`) also puts the machine-readable `items` (failed units, restart-looping units, sysalert conditions, each with a one-line reason such as the last error line of the unit journal; the tooltip lists the same lines) into its JSON; the left click runs `scripts/health-details.sh`, a fzf-menu list over that same cached run (preview: `systemctl [--user] status` + last 30 journal lines; Enter: restart, stop, stop+disable, reset-failed, journal in less; hub row `failed-units`, leader `s f`), so badge and view cannot disagree. The badge runs through `health-badge.sh` (module signal 16), which stores the exact output it displays as `waybar-cache/health-shown.json`; the view lists that snapshot, marks items that cleared since as `cleared` with a note and pokes the badge (RTMIN+16) so it catches up. A stopped or disabled unit is inactive and never raises an alert, and so is a unit in a normal start job (D-Bus activated daemon, oneshot run by a timer: `activating`, 0 restarts): a unit counts as looping only after `min_restarts` (2) restarts while auto-restarting/activating, and alerts when that holds on two consecutive runs or at 5 restarts. The "reason" of a unit says what the journal really holds (the journal is readable for the owner; a unit that only logged systemd start/stop lines gets that wording, not "not readable"). The bredllm tunnels (`voicebox-tunnel`, `bredllm-reverse-socks`) were removed on the owner's request; their unit files are backed up in `~/.local/share/workstation-overhaul/bredllm-units-backup/`.

Pinned apps (right side of both bars, `group/pinned`): the list is `.config/waybar/pinned.tsv` (id, label, glyph, window-class regex, launch command, notification regex; Telegram, Zen, Chrome, Obsidian, YouTube Music, Bitwarden). **Adding an app = one row, then `bar.sh reload`**: `bar.sh render` runs `scripts/pinned.sh gen`, which writes `custom/pin#ID` per row plus the group into `~/.local/state/waybar/pinned.jsonc`, included by both bars. One daemon, `scripts/pinned-watch.py` (started by `waybar-run.sh`, restarted by the module script if it died, survives bar restarts), follows the Hyprland event socket (open/close/move/focus) and a read-only session-bus monitor of `org.freedesktop.Notifications.Notify`; it renders `$XDG_RUNTIME_DIR/pinned/<id>.json` (what the module prints) and pokes waybar with **RTMIN+14**. Classes: `dim` not running, `normal` running, `focused` in front (fg), `new` (soft `yellow_soft` text, no pill). A notification whose app_name or desktop-entry matches the row's regex sets `new/<id>` unless the app is focused; it works with do-not-disturb on (dunst paused still receives the call; no dunst rule is involved); focusing the app, middle click or the menu's "Mark read" clears it. Click grammar: L focus (repeat = next window of the app; launches it when it has no window), M mark read, R fzf-menu (windows, New window / Launch, Mark read, Close all windows; protected classes ask first). `pinned.sh check` (doctor `pinned`) verifies list, generated modules and daemon; `pinned.sh edit` opens the list. `SUPER+T` / `SUPER+S` / `SUPER+N` (Telegram, YouTube Music, Obsidian) call `pinned.sh click ID`, so a bind and the bar's left click focus, cycle and launch the same way (`pinned.sh click ID --dry-run` shows what it would do).

### Pointer (cursor)
Custom **Everforest-Cursor** (Bibata Modern vector art; fill `green` #abc682 (the former light `fg` fill looked like plain white Bibata), outline `bg_oled`, busy-cursor pies `bg_oled` (dark on the green disk; they are drawn at 80% opacity); hyprcursor SVG + XCursor of the same artwork, size 32 = 48 px on the 1.5 panel). It is a local package: `infrastructure/cursor/everforest-cursor-theme/PKGBUILD` (git source pinned by commit, colours from `themes/generated/black/pointer.json`), built as the owner by `infrastructure/cursor/build.sh` and installed with `pacman -U` into `/usr/share/icons` (so flatpaks see it) by `sudo ./apply-system.sh --only install`; `install.sh` runs the same build. `hyprland.lua` sets `HYPRCURSOR_THEME`/`XCURSOR_THEME` to it only when the theme directory exists, else `XCURSOR_THEME=Bibata-Modern-Ice` (Bibata stays installed as the fallback) and no `HYPRCURSOR_THEME`; Hyprland writes gsettings `cursor-theme`/`cursor-size` from those variables at login (`.config/gtk-3.0/settings.ini` has no cursor keys on purpose), `.local/share/icons/default/index.theme` inherits `Everforest-Cursor,Bibata-Modern-Ice,Adwaita`. `cursor-apply` switches a running session after the install (`--revert` goes back to Bibata, `--status` shows both). `hyprctl setcursor` also writes gsettings `cursor-theme`, so a test with another theme leaves it behind (it had become `Bibata-Modern-Amber`): `cursor-apply` is the only right way to switch the pointer, and doctor `cursor-gtk` fails when gsettings differs from the expected theme. The autostart runs `cursor-apply --boot` (waits up to 6 s until `hyprctl` answers, gsettings + `hyprctl setcursor`, one retry, result in `journalctl -t cursor-apply`) instead of a bare `hyprctl setcursor`; in Hyprland v0.56.2 the `hl.env` variables already reach the cursor manager on a clean start (it is created in `initServer` after the config ran; libhyprcursor reads `HYPRCURSOR_THEME`), so `--boot` is the safety net. The greeter's Hyprland uses the same `hl.env` selection. doctor: `cursor` (installed, complete, stamp current, fill = green, busy disk), `cursor-gtk`, `cursor-boot`, `cursor-env`.

### Launcher
**rofi** is only the app launcher (`$menu`, `SUPER+space`; `.config/rofi/`): it has no modes, so it gets the list grammar as far as rofi allows (`Ctrl+j/k` move, `Ctrl+d/u` page, `Esc` cancel, Cyrillic twins generated from `ROFI_OVERRIDES` in `layout.py`). wofi stays installed and is themed, but nothing binds it.

**Every other menu is the shared modal fzf** (V1b): `.config/fzf/vimfzf.sh` (sourced by scripts: `vimfzf ARGS`, `VF_PROMPT`, extra NORMAL-mode letters through `VF_NORMAL_BINDS` / the env `FZF_MENU_NORMAL_BINDS`) is a Telescope-like list: it opens in INSERT (typing filters, `Ctrl+j/k n/p`, `Ctrl+d/u`), `Esc` is NORMAL (`j/k g/G`, `i a /` back to INSERT, `q`/`Esc` quit; every other printable key is ignored; the mode tag `[I]`/`[N]` is in the prompt), ua/ru twins come from `lk_fzf_bind`, colours from `FZF_DEFAULT_OPTS_FILE` (T1a). `.local/bin/fzf-menu` is the dmenu replacement for keybinds (rows on stdin, choice on stdout, exit 1 = cancel; `-p`, `-m`, `--preview`, `--image`, `--index`, `--here`, any other fzf option passes through): it opens a `float.tui` ghostty, refocuses the previous window, closes the open menu on a second call, and keeps a hidden menu terminal (`fzf-menu --server`, parked on the special workspace `menu` by the `fzf-menu-server` window rule, started by `hyprland.start`) so a menu opens in about 40 ms (cold ghostty: about 0.4 s, the automatic fallback). `fzf-menu --self-test` drives the modal in a private tmux (doctor runs it). Image previews (clipboard, window switcher icons) use chafa through `.config/fzf/image-preview.sh`: fzf shows kitty graphics only as Unicode placeholders, so the script unwraps chafa's tmux-passthrough output (inside tmux it falls back to character cells). New menus: call `fzf-menu`, give NORMAL keys through `FZF_MENU_NORMAL_BINDS` and `--expect` Alt keys; never call `rofi -dmenu` (doctor checks).

### Dictation (D1b)
Offline voice typing: Voxtype (AUR `voxtype-bin`) + local Whisper, typed into the focused window; nothing leaves the machine. `.config/hypr/scripts/dictation.sh` is the only entry point (`toggle|start|stop|cycle|lang|model|backend|status|--follow|run|menu`), `voxtype.service` runs `dictation.sh run`. **Language**: default `ru` (tracked `.config/voxtype/config.toml` and the script when no state file exists), remembered in `~/.local/state/dictation/lang`; accepted values `ru`, `uk`, `en`, `auto` and comma lists such as `en,ru,uk` (auto-detect among them; `auto` cannot be mixed into a list). `SUPER+ALT+SHIFT+D` (and the waybar middle click) cycles ru -> uk -> en -> ru (anything else starts at ru), restarts the daemon with `try-restart --no-block` and shows ONE replacing notification (`Dictation: RU`, stack tag `dictation`); while recording or transcribing it refuses ("Dictation is busy"). `run` renders a runtime copy of the tracked config with the language and model, so the tracked file never changes. **Indicator** (`custom/dictation`, always visible while voxtype is installed): `󰍬 RU` grey (`dim`) idle, `󰍬 RU rec` red_soft (`critical`) recording, `󰔟 RU` yellow_soft (`warning`) transcribing; tooltip = state, language, model, backend, then `L: dictate · M: next language · R: menu`; right click = menu (toggle, next language, language list incl. `en,ru,uk`, model small / large-v3-turbo, "Backend: detect again"); hub rows `dictation*` and leader `a v/c/l/b`. **Backend** (no root, no PATH hack, no systemd drop-in): the package ships `/usr/lib/voxtype/voxtype-{vulkan,avx512,avx2,baseline}`; `run` execs the chosen variant directly. Vulkan when a real GPU works: a silent 1 s clip is transcribed once with the smallest installed model and the log must show `using Vulkan` (llvmpipe/lavapipe/swiftshader do not count); the result (backend, GPU name, reason) is cached in `~/.local/state/dictation/backend` and keyed on the Vulkan build, the ICD json files and the kernel, so an upgrade re-probes; no model yet = no probe and no cache; two automatic restarts of the unit (`NRestarts >= 2`) demote a crash-looping Vulkan daemon to CPU until `backend --probe`. CPU fallback by `/proc/cpuinfo` flags: avx512 (f, bw, vl, dq) > avx2 (avx2, fma) > baseline, skipping builds that are missing, last resort the `voxtype` on PATH. Env hooks for tests: `VOXTYPE_BIN` (replaces client and daemon binary), `VOXTYPE_LIBDIR`, `DICTATION_CPUINFO`. The client (`voxtype record start|stop`) only signals the daemon, so `/usr/bin/voxtype` (avx512) is fine for it. doctor `dictation-backend` (the daemon's `/proc/PID/exe` is the variant `backend --path` names; FAIL on a leftover runtime drop-in or `~/.local/share/voxtype/bin/voxtype`), `o1-tests` (independent of whether the package is installed: `VOXTYPE_BIN` points at a fake or at a missing file). **Model benchmark** (2026-10-17, AMD Radeon 860M Vulkan, `voxtype transcribe` per clip so every number includes process start and shader setup; clips: piper TTS ru/uk/en sentences of 2 to 4 s with known text, plus three 10 to 22 s public-domain human recordings from Wikimedia Commons; no microphone): small 0.38-0.56 s per clip (0.71 s for 22 s), large-v3-turbo 1.3-1.6 s (3x slower, 1.6 GB vs 466 MB); on CPU avx512 small takes 6-8 s and turbo 33-41 s, so Vulkan is 12-25x faster. Word error rate (digits counted as errors for both models): ru small 0.07 / turbo 0.17, uk small 0.35 / turbo 0.23, en 0.02 / 0.02; on the human clips small was as good or better in ru and uk (turbo dropped the URL in ru and garbled the uk sentence). Turbo is not clearly more accurate and sits at the speed limit (about 1.4 s for a 3 s clip), so the default stays `small`; `large-v3-turbo` (`ggml-large-v3-turbo.bin`, downloaded, 1.6 GB) is selectable from the menu or `dictation.sh model large-v3-turbo` (remembered in `~/.local/state/dictation/model`; `dictation.sh model small` goes back). The Telegram voice transcription keeps its own copy of `small` (`/srv/models`).

### Audio (PipeWire + WirePlumber + pipewire-pulse + EasyEffects under linger)
`loginctl enable-linger` is on (user services such as the MCP gateway start at boot), so the user manager of the owner starts `pipewire`, `wireplumber` and `pipewire-pulse` at boot, long before greetd gives the owner seat0 (the greeter user has its own manager and session). Until logind puts the `uaccess` ACL (`user:skalse:rw`) on `/dev/snd/*` at the owner's login, the ALSA probe fails (`Failed to get the verb HiFi`, `api.alsa.acp.device could not be loaded`); logind sets the ACL later without a udev event and WirePlumber never probes a failed card again, so both cards stayed on profile `off`: no hardware sink or source, default source `easyeffects_sink.monitor`, and the built-in mic worked only in apps that already held a stream (Telegram), not in flatpaks (Zen). WirePlumber's logind module only gates the bluez monitors (`support.logind`, `monitor.bluez.seat-monitoring`); the ALSA monitor has no seat handling, and keeping pipewire out of `default.target` would not help (socket activation by any early client starts it anyway). The fix is a heal step, not a dependency: `.local/bin/audio-ensure --boot` runs from the Hyprland autostart (waits for PipeWire and the first card, judges after 2 s), and when a card is on `off` although `~/.local/state/wireplumber/default-profile` holds a usable (`available`) profile for it, or no hardware sink/source exists, it restarts `wireplumber` once, re-checks and logs to `journalctl -t audio-ensure` (a notification only when the restart did not help). A healthy boot, a re-login and manual runs change nothing; `audio-ensure --check` is read-only (doctor `audio`, `audio-boot`). An HDMI card whose ports are all `not available` (no audio-capable display) legitimately stays `off`. Manual fix: `audio-ensure` (or `systemctl --user restart wireplumber`). Default source: the real microphone, never a `.monitor` and not `easyeffects_source`: the EasyEffects input chain in `~/.config/easyeffects/db` (rnnoise, pitch, autotune, autogain, device = EarPods) is not managed here, "process all inputs" is off, and pitch/autotune would alter the voice in calls; WirePlumber keeps `default.configured.audio.source` (Mic2 = headset jack, `not available` without a plug, so Mic1 = the built-in digital mic is the effective default). `mic-mute-all.sh status` (hub toggle row `mic-mute`, waybar) is silent and only reports through its exit code; only the real toggle notifies.

### MCP gateway and agents (M1)

Config = `.config/mcp/gateway.json` (mcp-proxy's own format; `${ENV}` placeholders only, so it holds no secret and mcp-proxy expands them from its environment); `.local/bin/mcp-gateway run` creates the 0600 token file once (`~/.local/state/mcp/gateway.token`, dir 0700), renders the effective config into `$XDG_RUNTIME_DIR/mcp-gateway/config.json` (minus servers that are not set up yet, e.g. `telegram` until `~/.local/state/mcp/telegram.token` exists) and execs mcp-proxy with the tokens in its **environment** (never argv, never a file the clients see). `mcp-gateway status|servers|url NAME|headers|token ensure|rotate|restart|logs|check`. ### Telegram sending (M1-send)
Agents can ask to send a Telegram message; nothing leaves without the owner's confirmation of that exact message. Off by default.
- **Path**: agent -> gateway server `telegram-send` (`.config/mcp/telegram-send.py`, stdio, owner uid, no secret, no Telegram code; tools `send_message(chat, text, reply_to, account)` and `status`, toolFilter allow exactly those two, gateway timeout 90 s; the gateway leaves it out of the effective config until `tgconfirm.service` or its socket exists) -> `/run/tgconfirm/req.sock` -> the **tgconfirm broker** (`infrastructure/mcp/confirm/broker.py`, system service, managed service user `tgconfirm`, mode 0666 socket + `SO_PEERCRED` owner-uid check) -> `POST /x-send` of telegram-mcp (`serve.py`, user `aimcp`, its own send token and send allowlist, same Telethon client; never an MCP tool, `check_env()` still demands exactly `read-only`). Answers: `sent (id N)`, `cancelled`, `timeout`, `disabled`, `rejected: <reason>`.
- **Per message**: the broker resolves the chat against the server-side send allowlist, then opens a popup (`popup.py` in ghostty as `tgconfirm`, class `float.confirm`: float, center, pin, `stay_focused`, `no_screen_share`) with the account, recipient, chat id, reply preview and the full text (scrollable, control and bidi characters shown as `<U+XXXX>`). The owner presses a random two-key code drawn in the popup (1 of ~400, ua/ru twins count, keys in the first 0.7 s ignored, any wrong key cancels, Esc or 60 s = cancelled); the broker never learns the code. Rate limit 5 popups / 10 min, one popup at a time, a locked screen refuses, journald audit (`tgconfirm:` / `telegram-send:` lines: account, chat id, length, sha256 prefix, result; never the text).
- **Switch**: `mcp-telegram-send on|off|toggle|status` (hub toggle row `tg-send`, leader `x m`, waybar `tgsend` glyph with the minutes left in the toggles summary and drawer; hidden while no broker runs). Enabling goes through the broker and shows its own popup, so an agent cannot switch it on silently; 60 minutes by default (`--ttl`, broker cap 120), the broker expiry plus a transient `mcp-telegram-send-off` user timer switch it off with a notification; turning it off needs no confirmation.
- **Secrets**: the send token exists only as TPM2 credentials of `telegram-mcp` and `tgconfirm` (`/etc/credstore.encrypted/{telegram-mcp,tgconfirm}.send_token`); `creds-install --ensure-send-token` generates it as root, so it is never in Bitwarden, in a file `skalse` can read, in argv or in this repo. `send_allowlist` (chat ids, not secret) lives in the Bitwarden item `MCP/telegram-mcp` and as a credential; it must stay a subset of `allowlist` (`mcp-telegram-setup chats` trims it). `mcp-telegram-setup send-chats [--account NAME]` is the picker (only `main` until M1b: several accounts = one telegram-mcp instance and credential set per account, the broker maps `account` to a port). The root part is `sudo ./apply-system.sh --only users,mcp`.
- **Threat model (honest)**: agents run as `skalse`, read every 0600 file of `skalse` and can inject keys with `wtype`/`wlrctl`/`hyprd`/`hyprctl eval`, so the popup cannot be unforgeable by itself. Defences: the send token is unreadable for `skalse`; the code is per message and random; the popup is invisible to screen capture; `mcp-guard` writes Claude Code `permissions.deny` rules for those tools and `grim` into `~/.claude/settings.json` (backup, `--dry-run`, `--remove`, `--check`; doctor INFO until run); `telegram-send` is registered for Claude Code only (`mcp-add` removes it from Codex); rate limit, audit, auto-off and the server-side send allowlist. **Residual risk**: Codex runs with `--dangerously-bypass-approvals-and-sandbox` and can still reach the gateway route with the gateway token (not registered, but not secret from `skalse`), and any agent that edits the Hyprland config or guesses the code in its one shot can get out one message per popup; every message still needs the popup code, and the defences target prompt injection from untrusted chat text, the realistic threat. Kill switch: Telegram > Settings > Devices (the session is still named "telegram-mcp (AI, read-only)" from before sending existed).
- Tests: `infrastructure/tests/mcp/run.sh` (`test_send_e2e.py`: real broker + fake popup + fake `/x-send` driven by the real switch and MCP server; `test_confirm.py`, `test_popup.py`, `test_telegram_serve.py`, `test_telegram_send.py`); doctor `mcp-send-route`.

### Layout-independent binds (us, ua, ru; Caps toggles)

Theme: `themes/generated/<variant>/obsidian.css` (template `obsidian.css.tmpl`: Obsidian's `--color-base-*`, backgrounds, text, accent, headings, code, graph) is linked as the snippet `vault-config/snippets/everforest.css` -> `~/.local/state/theme/current/obsidian.css` and enabled in `appearance.json` (Obsidian's own theme stays the default dark one); the theme hook `70-obsidian.sh` does `touch -h` on that link, which makes a running Obsidian reload the colours after `theme black|night|toggle`. `obsidian.vimrc` (hand-written: `jj`, display-line `j`/`k`, `Y` = `y$`, `unnamedplus`, Space sequences for the quick switcher, search, palette, sidebar, tabs, folds) + generated `vimrc-twins.txt` (`layout.py gen obsidian`) are concatenated into `vault-config/obsidian.vimrc`, linked as `<vault>/.obsidian.vimrc`. `apps/obsidian/apply.sh [--dry-run] [--no-download] [--vault PATH]` (called by `install.sh`, idempotent, doctor `obsidian*`) does all of it for every vault in Obsidian's list (or `--vault`, which also registers it in `~/.config/obsidian/obsidian.json`): installs/verifies the plugins, links config, snippet and vimrc, moves a replaced real `.obsidian` (and a foreign vimrc) to `~/.local/share/dotfiles-backups/obsidian/<time>-<vault>/` and copies its extra files (workspace, hand-installed plugins) into `vault-config` (it does not swap a real `.obsidian` while Obsidian runs). A vault is opened for the first time per machine with Obsidian's "Do you trust the author of this vault?" prompt: choose "Trust author and enable plugins". All vaults share one config (including `workspace.json`). Restart Obsidian after the first run. zsh `sudo-command-line` is NORMAL `gs` and `Ctrl+X s` (Hyprland grabs `Alt+S`, so no Alt key of the letter `s` reaches a terminal). The surfaces that cannot have vim keys or ua/ru twins are listed in the block "Audit" of `docs/keymap.md` (rows in `.config/keymap/static.tsv`).
- `browsers/` — Zen `user.js` (memory/cache prefs) and Chrome `chrome-flags.conf` (1 GiB disk cache). They must be copied into the flatpak sandboxes, so `browsers/apply.sh` (called by `install.sh`, merges, idempotent) does that instead of stow.
- `pkg/*.txt` — package lists written by a pacman hook; `infrastructure/` — system files installed by `apply-system.sh` / `apply-memory.sh`.

### Neovim
`.config/nvim/` is a git submodule pointing to a custom NvChad fork. Update with `git submodule update --remote`.

### Infrastructure
`infrastructure/systemd/` — `coredump-limits.conf` (installed by `apply-system.sh`) and legacy `hyprdynamicmonitors` user units (unused: monitors are static now).

`infrastructure/tlp/` — TLP drop-in configs (`/etc/tlp.d/`), not stowed (system path, outside `$HOME`, machine-wide rather than per-user). `61-battery-care.conf` caps battery charging; `install.sh` copies it into `/etc/tlp.d/` and enables `tlp.service` (copied, not symlinked, so it doesn't dangle if the installing user's account is later removed on a shared machine). Non-ThinkPad Lenovo hardware (`ideapad_laptop` driver) only supports a binary `Long_Life` charge mode (vendor-fixed ~55-60% cutoff) via the kernel's `charge_types` API — no exact percentage like ThinkPads' `charge_control_end_threshold`. To pick up edits without a full rerun: `sudo cp infrastructure/tlp/61-battery-care.conf /etc/tlp.d/ && sudo systemctl restart tlp`.

`infrastructure/memory/` — RAM safety net, copied (not stowed) into `/etc` by `install.sh`: zram swap (`zram-generator.conf`), sysctl tuning, zswap off (avoids double compression), journald cap. (`daemon.json` with log limits and the BuildKit GC cap now lives here too but is installed by `apply-system.sh`.) Apply (or re-apply after edits) without a full rerun: `./apply-memory.sh` (self-elevates with sudo, idempotent).

`apply-system.sh` — one idempotent root script for the whole system layer (sections `cleanup upgrade install remove config services greeter users mcp disk boot flatpak summary`; `--dry-run`, `--only <section>` or a comma list such as `--only users,mcp`, run in section order). It installs `infrastructure/{memory/earlyoom,memory/docker-daemon.json,pacman/*.hook,systemd/coredump-limits.conf,tlp/62-power.conf}` into `/etc`, edits `makepkg.conf`/`pacman.conf`/`fstab`/`grub`, and keeps `pkg/{native,aur,flatpak}.txt` current through a pacman hook (`/usr/local/bin/dotfiles-pkglist`, rendered from `infrastructure/pacman/dotfiles-pkglist.in`). Run: `sudo ./apply-system.sh` (preview: `./apply-system.sh --dry-run`).

## AI agent cockpit (Neovim + tmux)

`install.sh` is idempotent and user-agnostic: no usernames, home paths or e-mails are hardcoded.
Git identity lives in `~/.gitconfig.local` (written by `install.sh`, included from `.gitconfig`).
After `stow .` it runs `.config/nvim/scripts/bootstrap.lua` headless, which restores plugins from
`lazy-lock.json`, installs Mason tools and treesitter parsers, and writes the agent hooks
(`:AgentDashInstallHooks`) into `~/.claude/settings.json` / `~/.codex/hooks.json` with backups.

Neovim side (`lua/plugins/ai/*.lua`, all keys under `<leader>a`):
- `sidekick.nvim` — Claude/Codex/Gemini CLIs in persistent tmux windows, context prompts
- `agentic.nvim` — ACP quick chat (`claude-agent-acp`, `codex-acp`)
- `codediff.nvim` + `review.nvim` — post-hoc review, comments sent back to the agent
- MCP: no nvim plugin; the agents (Claude Code, Codex, the ACP adapters) use the local MCP gateway, see "MCP gateway and agents" above (mcphub.nvim and the unauthenticated mcp-hub on `*:37373` were removed in M1)
- `lua/agentdash/` — custom dashboard of sessions/subagents/tasks fed by agent hooks (`:AgentDash`, statusline segment)
- `workmux` (`.config/workmux/config.yaml`) — git worktree + tmux window per agent task, `<leader>aw*`

Installing new nvim plugins: use `nvim --headless "+Lazy! install" +qa`, never `Lazy sync`/`clean`
(they bump every pinned commit in `lazy-lock.json`).
