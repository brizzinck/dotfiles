# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

Personal dotfiles for an Arch Linux / Hyprland / Wayland setup, managed with **GNU Stow**. Running `stow .` from the repo root symlinks everything into `$HOME`, mirroring the directory structure. Non-config files are excluded via `.stow-local-ignore`.

## Setup

```bash
git clone --recursive <repo>
git submodule update --init --recursive
chmod +x install.sh && ./install.sh
```

`install.sh` does a full machine bootstrap: pacman packages, AUR (via yay), Flatpak apps, Go/NPM/Rust toolchains, Oh My Zsh, Docker setup, SSH key generation, then runs `stow .` to link the dotfiles and `browsers/apply.sh` to copy the browser settings. Root-level system changes (packages, `/etc`, timers, fstab, grub) are applied separately by `sudo ./apply-system.sh`; `./doctor.sh` verifies the result.

After modifying dotfiles, re-apply with:
```bash
cd ~/dotfiles && stow .
```

## Architecture

### Config layout
All configs live under `.config/` following XDG Base Dir. Root-level files (`.zshrc`, `.gitconfig`) stow directly to `$HOME`.

### Monitor management
Static Hyprland rules in `.config/hypr/monitors.lua` (loaded by `hyprland.lua` with `dofile`; `scripts/lid.sh` re-applies the panel rule from the same table): `HDMI-A-1` 2560x1440@144 at `0x0`, the laptop panel `eDP-1` 2880x1800@120 scaled 1.5 at `0x1440` (below the external one), plus a `preferred, auto` fallback for any other output. Hyprland applies them on hotplug, so there is no kanshi, no polling script and no monitor daemon.

### Hyprland config (Lua)
`.config/hypr/hyprland.lua` (+ `monitors.lua`) is the only Hyprland config; there is no `hyprland.conf` (`doctor.sh` checks that it is absent and that the running instance loaded the Lua file). hyprlock, hypridle and the screensaver stay hyprlang. In a Lua config `hyprctl keyword` is gone and `hyprctl dispatch` takes a Lua expression: scripts call `.local/bin/hyprd` (legacy dispatcher names, e.g. `hyprd focuswindow address:0x..`) or `hyprctl eval '<lua>'`. Binds are `hl.bind("SUPER + X", hl.dsp..., { description = "..." })` (descriptions feed the cheatsheet, the hub and `docs/keymap.md`; no commas). `hyprctl binds -j` reports Lua binds as dispatcher `__lua`, so nothing can be read back from it: `hyprland.lua` wraps `hl.bind` and records every dispatcher in a registry, and `hyprctl eval 'df_bind_run("SUPER+Return")'` replays one (mods in SUPER CTRL ALT SHIFT order, key as in the live table, case-insensitive). The hub uses that for its keybind rows (`kind bind`) and for the leader. Hyprland 0.55/0.56 runs a `catchall` bind next to the matching bind and on a lone modifier press (hyprwm/Hyprland#15063), so the repeat modes (`resize`, `mouse`) leave through `leave_on_other_key()`, which ignores the event while one of the mode's own keys or a modifier is held.

### Theme system
Idle (`.config/hypr/hypridle.conf`): dim at 150 s, at 300 s a clock-only hyprlock screensaver (`screensaver.conf`, started by `scripts/screensaver.sh`, no password; any input dismisses it via hypridle on-resume + `SIGUSR1`), panel off (`dpms`) at 1200 s. The machine never suspends or locks by itself, and nothing is killed. All listeners are skipped while media plays or an automation Chrome runs (`idle-allowed.sh`; Wayland/DBus inhibitors are honoured too). `SUPER+Escape` is still the real password lock.

The palette is **Everforest v2** with two switchable variants: **black** (default, pure `#000000` backgrounds) and **night** (near-black `#0a0e0c` content background; bar, lock screen, screensaver and the Hyprland background stay `#000000`). fg, accents and ANSI 0-15 are shared. Source of truth: `themes/palette/everforest.json` (tokens) with the human-readable `themes/palette/palette.md` (token roles, per-app mapping, owner steps). `themes/palette/render.py` (stdlib Python, `PYTHONPYCACHEPREFIX=/tmp/pycache python3 themes/palette/render.py`, `--check` for doctor) renders every `templates/*.tmpl` for both variants into the committed `themes/generated/{black,night}/`; a new app only needs a new template. The active variant is the symlink `~/.local/state/theme/current -> themes/generated/<variant>`, and `theme black|night|toggle|status|init` (`.local/bin/theme`, hub row "Theme: black / night") flips it, reloads ghostty (SIGUSR2), alacritty, every tmux server of the user and nvim, then runs the hooks in `.config/theme/hooks.d/` (`10-hyprland` reload + configerrors check, `20-waybar` SIGUSR2, `30-dunst` `dunstctl reload`, `40-swayosd` restart, `50-qt`). A missing link is recreated as black by `install.sh`, `.zshrc`, tmux.conf and the first Hyprland autostart line.

Window look (`hyprland.lua` + the fragment): solid calm colours, no gradient and no shadow. Active border `green_soft`, inactive `line` (almost invisible; the gaps separate tiles), group border and active groupbar tab `purple_soft`, blocked grouping `yellow_soft`. Hyprland renders `round(border_size * scale)` physical pixels and rounds every box to whole pixels, so `border_size` (2 = 2 px on HDMI-A-1, 3 px on eDP-1) and the gaps (4 = 4 / 6 px) must be even to stay crisp at scale 1.5 (odd sizes round up: 3 -> 5 px); `rounding_power = 2`. A two-colour gradient on a 2-3 px stripe bands visibly and was the pixelated look. How each app follows the variant: `hyprland.lua` `dofile`s the black fragment (fallback) and then `current/hyprland.lua` inside `pcall` (a missing or broken fragment is skipped with a notification, black stays); hyprlock and the screensaver (hyprlang) `source` the black fragment and then `current/` (a missing sourced file is a config error, hence the fallback); waybar, wofi, swayosd and both GTK versions `@import` a repo symlink `theme-black.css` plus `theme.css` -> `current/...`; rofi `@import`s the same pair of paths; dunst reads `dunstrc.d/40-theme-black.conf` and `50-theme.conf` drop-ins; btop (`themes/everforest-v2.theme`) and qt6ct (`colors/everforest.conf`) are symlinks to `current/`; lazygit merges `current/lazygit.yml` through `LG_CONFIG_FILE` (set by `.zshrc`, tmux and hub); lazydocker uses ANSI names, so it follows the terminal palette. Literals that cannot follow (pango spans in `waybar/config`, workmux icons) hold token hex and are checked by `doctor.sh`. Generated but applied by hand: `everforest-<variant>.tdesktop-theme` (Telegram), `obsidian.css`, `claude-theme.json`; GTK/Qt apps pick up a switch at their next start. Owner steps are in `themes/palette/palette.md`. `themes/static/everforest-black/` only holds a pointer note now; the other directories in `themes/static/` (rose-pine, dracula, catppuccin-mocha, ...) and `themes/templates/` (matugen, wallust, pywal) are unused leftovers of the old HyprDynamicMonitors setup.

### Bar (waybar)
Two bar objects per output in one waybar process (`.config/waybar/config` includes `modules.jsonc` and a state file each): **compact** (base bar, exclusive zone) and **full** (non-exclusive overlay with `margin-top: -28`, drawn over compact). `SUPER+B` = compact/full (`scripts/bar.sh mode toggle`, SIGUSR1 reaches only the full bar, so the exclusive zone and windows never move), `SUPER+CTRL+B` = hide/show everything (`bar.sh hide toggle`, a reload). State: `~/.local/state/waybar/{mode,hidden}`; `bar.sh render` writes `compact.jsonc`/`full.jsonc` (`start_hidden`) that the config includes, so the mode survives restarts, theme reloads (`bar.sh reload`) and logins (`bar.sh init` clears `hidden`). **Never send SIGUSR1 by hand**; a toggle leaves `$XDG_RUNTIME_DIR/waybar-bar/stale`, and the `monitor.added` hook runs `bar.sh sync --if-stale` so a new monitor gets the right mode. Signals (`pkill -o -u $(id -u) -RTMIN+N -x waybar`, `-o` so a script child that is still named waybar is not hit): 8 toggles drawer and summary, 9 updates, 15 vault; the recording module is a continuous script. Scripts print `class` = `normal|dim|enabled|warning|critical`, `style.css` maps them to palette tokens (green active/enabled, calm yellow_soft warning and red_soft critical tints without pill or bold, everything else grey; the AI module is never highlighted, an exhausted limit is normal; its text is `C 26·4  X –·100` = Claude and Codex % used, 5h·weekly, `–` = no data, from `ai-usage.sh`). Alert modules print nothing until relevant; `cache.sh` shares one run of the expensive ones (health, updates, ai) between the two bars; `toggles.sh` is the single source of the switch states. The compact -> full switch is animated by a GTK CSS opacity transition on the full bar (`style.css`): SIGUSR1 only moves that surface between layers, which never maps or unmaps it, so Hyprland layer rules and animations cannot fire (checked: no openlayer/closelayer events); drawers use waybar's own 220 ms revealer. Click grammar: L main, R menu, M quick binary action, scroll value; menus are fzf-menu based. Every tooltip ends with the same hint line, `L: x · M: y · R: z · Scroll: w` (that order, lowercase actions, idle buttons omitted). `WAYBAR_LOG_LEVEL=debug bar.sh restart` logs the GTK widget tree (`$XDG_RUNTIME_DIR/waybar-bar/waybar.log`). doctor checks bar-state, bar-layers (surfaces with the layer namespaces `waybar-compact` / `waybar-full` per monitor), bar-reserved, bar-css.

The health badge (`custom/health`, `health.sh` over `failed.sh`) also puts the machine-readable `items` (failed units, restart-looping units, sysalert conditions, each with a one-line reason such as the last error line of the unit journal; the tooltip lists the same lines) into its JSON; the left click runs `scripts/health-details.sh`, a fzf-menu list over that same cached run (preview: `systemctl [--user] status` + last 30 journal lines; Enter: restart, stop, stop+disable, reset-failed, journal in less; hub row `failed-units`, leader `s f`), so badge and view cannot disagree. The badge runs through `health-badge.sh` (module signal 16), which stores the exact output it displays as `waybar-cache/health-shown.json`; the view lists that snapshot, marks items that cleared since as `cleared` with a note and pokes the badge (RTMIN+16) so it catches up. A stopped or disabled unit is inactive and never raises an alert, and so is a unit in a normal start job (D-Bus activated daemon, oneshot run by a timer: `activating`, 0 restarts): a unit counts as looping only after `min_restarts` (2) restarts while auto-restarting/activating, and alerts when that holds on two consecutive runs or at 5 restarts. The "reason" of a unit says what the journal really holds (the journal is readable for the owner; a unit that only logged systemd start/stop lines gets that wording, not "not readable"). The bredllm tunnels (`voicebox-tunnel`, `bredllm-reverse-socks`) were removed on the owner's request; their unit files are backed up in `~/.local/share/workstation-overhaul/bredllm-units-backup/`.

Pinned apps (right side of both bars, `group/pinned`): the list is `.config/waybar/pinned.tsv` (id, label, glyph, window-class regex, launch command, notification regex; Telegram, Zen, Chrome, Obsidian, YouTube Music, Bitwarden). **Adding an app = one row, then `bar.sh reload`**: `bar.sh render` runs `scripts/pinned.sh gen`, which writes `custom/pin#ID` per row plus the group into `~/.local/state/waybar/pinned.jsonc`, included by both bars. One daemon, `scripts/pinned-watch.py` (started by `waybar-run.sh`, restarted by the module script if it died, survives bar restarts), follows the Hyprland event socket (open/close/move/focus) and a read-only session-bus monitor of `org.freedesktop.Notifications.Notify`; it renders `$XDG_RUNTIME_DIR/pinned/<id>.json` (what the module prints) and pokes waybar with **RTMIN+14**. Classes: `dim` not running, `normal` running, `focused` in front (fg), `new` (soft `yellow_soft` text, no pill). A notification whose app_name or desktop-entry matches the row's regex sets `new/<id>` unless the app is focused; it works with do-not-disturb on (dunst paused still receives the call; no dunst rule is involved); focusing the app, middle click or the menu's "Mark read" clears it. Click grammar: L focus (repeat = next window of the app; launches it when it has no window), M mark read, R fzf-menu (windows, New window / Launch, Mark read, Close all windows; protected classes ask first). `pinned.sh check` (doctor `pinned`) verifies list, generated modules and daemon; `pinned.sh edit` opens the list.

### Pointer (cursor)
Custom **Everforest-Cursor** (Bibata Modern vector art; fill `green` #abc682 (the former light `fg` fill looked like plain white Bibata), outline `bg_oled`, busy-cursor pies `bg_oled` (dark on the green disk; they are drawn at 80% opacity); hyprcursor SVG + XCursor of the same artwork, size 32 = 48 px on the 1.5 panel). It is a local package: `infrastructure/cursor/everforest-cursor-theme/PKGBUILD` (git source pinned by commit, colours from `themes/generated/black/pointer.json`), built as the owner by `infrastructure/cursor/build.sh` and installed with `pacman -U` into `/usr/share/icons` (so flatpaks see it) by `sudo ./apply-system.sh --only install`; `install.sh` runs the same build. `hyprland.lua` sets `HYPRCURSOR_THEME`/`XCURSOR_THEME` to it only when the theme directory exists, else `XCURSOR_THEME=Bibata-Modern-Ice` (Bibata stays installed as the fallback) and no `HYPRCURSOR_THEME`; Hyprland writes gsettings `cursor-theme`/`cursor-size` from those variables at login (`.config/gtk-3.0/settings.ini` has no cursor keys on purpose), `.local/share/icons/default/index.theme` inherits `Everforest-Cursor,Bibata-Modern-Ice,Adwaita`. `cursor-apply` switches a running session after the install (`--revert` goes back to Bibata, `--status` shows both). The autostart runs `cursor-apply --boot` (waits up to 6 s until `hyprctl` answers, gsettings + `hyprctl setcursor`, one retry, result in `journalctl -t cursor-apply`) instead of a bare `hyprctl setcursor`; in Hyprland v0.56.2 the `hl.env` variables already reach the cursor manager on a clean start (it is created in `initServer` after the config ran; libhyprcursor reads `HYPRCURSOR_THEME`), so `--boot` is the safety net. The greeter's Hyprland uses the same `hl.env` selection. doctor: `cursor` (installed, complete, stamp current, fill = green, busy disk), `cursor-boot`, `cursor-env`.

### Launcher
**rofi** is only the app launcher (`$menu`, `SUPER+space`; `.config/rofi/`): it has no modes, so it gets the list grammar as far as rofi allows (`Ctrl+j/k` move, `Ctrl+d/u` page, `Esc` cancel, Cyrillic twins generated from `ROFI_OVERRIDES` in `layout.py`). wofi stays installed and is themed, but nothing binds it.

**Every other menu is the shared modal fzf** (V1b): `.config/fzf/vimfzf.sh` (sourced by scripts: `vimfzf ARGS`, `VF_PROMPT`, extra NORMAL-mode letters through `VF_NORMAL_BINDS` / the env `FZF_MENU_NORMAL_BINDS`) is a Telescope-like list: it opens in INSERT (typing filters, `Ctrl+j/k n/p`, `Ctrl+d/u`), `Esc` is NORMAL (`j/k g/G`, `i a /` back to INSERT, `q`/`Esc` quit; every other printable key is ignored; the mode tag `[I]`/`[N]` is in the prompt), ua/ru twins come from `lk_fzf_bind`, colours from `FZF_DEFAULT_OPTS_FILE` (T1a). `.local/bin/fzf-menu` is the dmenu replacement for keybinds (rows on stdin, choice on stdout, exit 1 = cancel; `-p`, `-m`, `--preview`, `--image`, `--index`, `--here`, any other fzf option passes through): it opens a `float.tui` ghostty, refocuses the previous window, closes the open menu on a second call, and keeps a hidden menu terminal (`fzf-menu --server`, parked on the special workspace `menu` by the `fzf-menu-server` window rule, started by `hyprland.start`) so a menu opens in about 40 ms (cold ghostty: about 0.4 s, the automatic fallback). `fzf-menu --self-test` drives the modal in a private tmux (doctor runs it). Image previews (clipboard, window switcher icons) use chafa through `.config/fzf/image-preview.sh`: fzf shows kitty graphics only as Unicode placeholders, so the script unwraps chafa's tmux-passthrough output (inside tmux it falls back to character cells). New menus: call `fzf-menu`, give NORMAL keys through `FZF_MENU_NORMAL_BINDS` and `--expect` Alt keys; never call `rofi -dmenu` (doctor checks).

### Login screen (greetd + Quickshell)
`infrastructure/greetd/` (repo-only; `sudo ./apply-system.sh --only greeter` copies it to `/etc/greetd`, `/usr/local/lib/greeter`, `/usr/local/bin`): greetd runs `greeter-session` as user `greeter`, which starts a minimal Hyprland (`hyprland.lua`, same `monitors.lua` copied from the session) running the Quickshell greeter in `greeter/` (`Greeter.qml` singleton = state, auth and keys; `OutputView`/`FormPane`/`BottomBar` views; `users.json`; `Theme.qml` links to `themes/generated/black/greeter-palette.qml`, rendered from `themes/palette/templates/greeter-palette.qml.tmpl`) through `run-qs` (10 s watchdog: no `greeter-alive` marker = kill and fall back to tuigreet). `greeter-session` starts `/usr/bin/Hyprland -c ...` directly, never `start-hyprland` (that wrapper restarts a crashed compositor in `--safe-mode` and would never return, so the fallback would be skipped; `doctor.sh` checks this) and ends a compositor without a live greeter after 25 s; any exit without the `greeter-ok` marker lands in tuigreet. Look = hyprlock. Only the owner (`users.json` keeps `@OWNER@`, rendered by `apply-system.sh`; large, monogram S in a green ring, `main`) and an "Other user..." entry that asks for a typed name are shown; no autologin, no photos. The form is on the monitor under the pointer, the other monitor shows the clock; layout pill US/UA/RU; F2 sessions, F12 power; vim keys by physical scancode (`docs/keymap.md`). The session starts through `/usr/local/bin/hypr-login` (the user's login+interactive shell runs `start-hyprland`, so `.zshrc` exports and the autostart incl. `vault.sh session-start` are as before). The F2 "Shell" session is `/usr/local/bin/shell-login` (`infrastructure/greetd/shell-login`: finds the terminal, puts the VT back into text mode, `exec`s the owner's login shell with `-l -i`, log in `~/.local/state/greeter-shell.log`); **a session `cmd` in `users.json` must be ONE argv element**, because greetd runs `sh -c "exec <argv joined by spaces>"` and loses the quoting of a `sh -c '...'` array (that was why the old Shell session ended in the same second; doctor checks it). Root can log in under "Other user...": greetd uses its own PAM service `greetd-login` (`[general] service` in `config.toml`, `infrastructure/greetd/pam/greetd-login` = the package's `/etc/pam.d/greetd` without `pam_securetty`, which fails for root because greetd sets no `PAM_TTY` before authenticating; the packaged file is a pacman backup file and stays untouched); `hypr-login` gives root a root shell instead of Hyprland. The greeter shows greetd errors as English text (`Greeter.errorText`: a PAM service error is not a wrong password). Text consoles: `Ctrl+Alt+F1..F6` are also Hyprland binds (greeter and session) that call logind `Seat.SwitchTo`, next to Hyprland's native XF86Switch_VT keysyms; logind starts `autovt@ttyN` (alias of `getty@`, doctor `tty-console`). `apply-system.sh` only runs `systemctl enable greetd` + `disable getty@tty1`, never `--now` (greetd `Conflicts=getty@tty1`): the owner reboots to switch. Rollback from TTY2: `sudo systemctl disable greetd && sudo systemctl enable getty@tty1 && sudo reboot`; emergency: GRUB `systemd.mask=greetd.service`; text greeter only: the one-line `command =` swap at the top of `/etc/greetd/config.toml`. Tests: `infrastructure/greetd/lint.sh` (qmllint), `GREETER_SELFTEST=1 GREETER_DEMO=1 QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software qs -p infrastructure/greetd/greeter`, `GREETER_DEMO=1 qs -p infrastructure/greetd/greeter` (floating window, fake greetd, password `demo`), `sudo greetd --config /etc/greetd/config-test.toml` (VT3, real PAM, dry-run session but a real Shell session, root login possible; Ctrl+Alt+F1 returns). `doctor.sh` checks the repo side always and the installed side as INFO until greetd is enabled. `/etc/greetd/config.toml` is a pacman backup file: after a greetd upgrade a `config.toml.pacnew` can appear (the doctor `pacnew` check then fails); delete it and rerun `--only greeter`.

### Audio (PipeWire + WirePlumber + pipewire-pulse + EasyEffects under linger)
`loginctl enable-linger` is on (user services such as the planned MCP gateway start at boot), so the user manager of the owner starts `pipewire`, `wireplumber` and `pipewire-pulse` at boot, long before greetd gives the owner seat0 (the greeter user has its own manager and session). Until logind puts the `uaccess` ACL (`user:skalse:rw`) on `/dev/snd/*` at the owner's login, the ALSA probe fails (`Failed to get the verb HiFi`, `api.alsa.acp.device could not be loaded`); logind sets the ACL later without a udev event and WirePlumber never probes a failed card again, so both cards stayed on profile `off`: no hardware sink or source, default source `easyeffects_sink.monitor`, and the built-in mic worked only in apps that already held a stream (Telegram), not in flatpaks (Zen). WirePlumber's logind module only gates the bluez monitors (`support.logind`, `monitor.bluez.seat-monitoring`); the ALSA monitor has no seat handling, and keeping pipewire out of `default.target` would not help (socket activation by any early client starts it anyway). The fix is a heal step, not a dependency: `.local/bin/audio-ensure --boot` runs from the Hyprland autostart (waits for PipeWire and the first card, judges after 2 s), and when a card is on `off` although `~/.local/state/wireplumber/default-profile` holds a usable (`available`) profile for it, or no hardware sink/source exists, it restarts `wireplumber` once, re-checks and logs to `journalctl -t audio-ensure` (a notification only when the restart did not help). A healthy boot, a re-login and manual runs change nothing; `audio-ensure --check` is read-only (doctor `audio`, `audio-boot`). An HDMI card whose ports are all `not available` (no audio-capable display) legitimately stays `off`. Manual fix: `audio-ensure` (or `systemctl --user restart wireplumber`). Default source: the real microphone, never a `.monitor` and not `easyeffects_source`: the EasyEffects input chain in `~/.config/easyeffects/db` (rnnoise, pitch, autotune, autogain, device = EarPods) is not managed here, "process all inputs" is off, and pitch/autotune would alter the voice in calls; WirePlumber keeps `default.configured.audio.source` (Mic2 = headset jack, `not available` without a plug, so Mic1 = the built-in digital mic is the effective default). `mic-mute-all.sh status` (hub toggle row `mic-mute`, waybar) is silent and only reports through its exit code; only the real toggle notifies.

### Layout-independent binds (us, ua, ru; Caps toggles)
Rule: every key binding must work while the ua or ru layout is active. Hyprland needs nothing (`resolve_binds_by_sym = false`, binds match layout 1 = us). For everything else, **never hand-type Cyrillic twins**: the single physical-key map is `.config/layout/keymap.tsv`, and `.config/layout/layout.py gen` (stdlib Python, `PYTHONPYCACHEPREFIX=/tmp/pycache`) writes the committed per-tool files: `ghostty/layout-keys.conf` (Alt+physical key sends ESC + us letter: ghostty drops Alt for a Cyrillic character), `tmux/tmux-layout.conf` (twins of every letter bind, read from `tmux list-keys`: rerun after adding tmux binds), `zsh/layout-keys.zsh` (`layout_dup_meta`, `layout_dup_keys` for vi-mode), `layout/layout-keys.sh` (`lk_rofi` for rofi `-kb-custom-N`, `lk_fzf_bind` / `lk_fzf_keys` for fzf letter binds; `vimfzf.sh` uses them for the whole NORMAL mode), `rofi/layout-keys.rasi`, and the nvim `lua/configs/layout_data.lua` (langmap + langmapper.nvim). New fzf letter binds go through `lk_fzf_bind` (or `FZF_MENU_NORMAL_BINDS`, which the library twins itself); rofi custom keys use `$(lk_rofi 'Alt+x')` (the launcher only).

### Infrastructure
`infrastructure/systemd/` — `coredump-limits.conf` (installed by `apply-system.sh`) and legacy `hyprdynamicmonitors` user units (unused: monitors are static now).

`infrastructure/tlp/` — TLP drop-in configs (`/etc/tlp.d/`), not stowed (system path, outside `$HOME`, machine-wide rather than per-user). `61-battery-care.conf` caps battery charging; `install.sh` copies it into `/etc/tlp.d/` and enables `tlp.service` (copied, not symlinked, so it doesn't dangle if the installing user's account is later removed on a shared machine). Non-ThinkPad Lenovo hardware (`ideapad_laptop` driver) only supports a binary `Long_Life` charge mode (vendor-fixed ~55-60% cutoff) via the kernel's `charge_types` API — no exact percentage like ThinkPads' `charge_control_end_threshold`. To pick up edits without a full rerun: `sudo cp infrastructure/tlp/61-battery-care.conf /etc/tlp.d/ && sudo systemctl restart tlp`.

`infrastructure/memory/` — RAM safety net, copied (not stowed) into `/etc` by `install.sh`: zram swap (`zram-generator.conf`), sysctl tuning, zswap off (avoids double compression), journald cap. (`daemon.json` with log limits and the BuildKit GC cap now lives here too but is installed by `apply-system.sh`.) Apply (or re-apply after edits) without a full rerun: `./apply-memory.sh` (self-elevates with sudo, idempotent).

`apply-system.sh` — one idempotent root script for the whole system layer (sections `cleanup upgrade install remove config services disk boot flatpak summary`; `--dry-run`, `--only <section>`). It installs `infrastructure/{memory/earlyoom,memory/docker-daemon.json,pacman/*.hook,systemd/coredump-limits.conf,tlp/62-power.conf}` into `/etc`, edits `makepkg.conf`/`pacman.conf`/`fstab`/`grub`, and keeps `pkg/{native,aur,flatpak}.txt` current through a pacman hook (`/usr/local/bin/dotfiles-pkglist`, rendered from `infrastructure/pacman/dotfiles-pkglist.in`). Run: `sudo ./apply-system.sh` (preview: `./apply-system.sh --dry-run`).

## AI agent cockpit (Neovim + tmux)

`install.sh` is idempotent and user-agnostic: no usernames, home paths or e-mails are hardcoded.
Git identity lives in `~/.gitconfig.local` (written by `install.sh`, included from `.gitconfig`).
After `stow .` it runs `.config/nvim/scripts/bootstrap.lua` headless, which restores plugins from
`lazy-lock.json`, installs Mason tools and treesitter parsers, and writes the agent hooks
(`:AgentDashInstallHooks`) into `~/.claude/settings.json` / `~/.codex/hooks.json` with backups.

Neovim side (`lua/plugins/ai/*.lua`, all keys under `<leader>a`):
- `sidekick.nvim` — Claude/Codex/Gemini CLIs in persistent tmux windows, context prompts
- `agentic.nvim` — ACP quick chat (`claude-agent-acp`, `codex-acp`)
- `codediff.nvim` + `review.nvim` — post-hoc review, comments sent back to the agent
- `mcphub.nvim` — one MCP endpoint (`localhost:37373`) shared by all agents; servers in `.config/mcphub/servers.json`
- `lua/agentdash/` — custom dashboard of sessions/subagents/tasks fed by agent hooks (`:AgentDash`, statusline segment)
- `workmux` (`.config/workmux/config.yaml`) — git worktree + tmux window per agent task, `<leader>aw*`

Installing new nvim plugins: use `nvim --headless "+Lazy! install" +qa`, never `Lazy sync`/`clean`
(they bump every pinned commit in `lazy-lock.json`).
