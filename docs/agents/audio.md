# Audio (PipeWire, WirePlumber, EasyEffects)

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Audio (PipeWire + WirePlumber + pipewire-pulse + EasyEffects under linger)
`loginctl enable-linger` is on (user services such as the MCP gateway start at boot), so the user manager of the owner starts `pipewire`, `wireplumber` and `pipewire-pulse` at boot, long before greetd gives the owner seat0 (the greeter user has its own manager and session). Until logind puts the `uaccess` ACL (`user:skalse:rw`) on `/dev/snd/*` at the owner's login, the ALSA probe fails (`Failed to get the verb HiFi`, `api.alsa.acp.device could not be loaded`); logind sets the ACL later without a udev event and WirePlumber never probes a failed card again, so both cards stayed on profile `off`: no hardware sink or source, default source `easyeffects_sink.monitor`, and the built-in mic worked only in apps that already held a stream (Telegram), not in flatpaks (Zen). WirePlumber's logind module only gates the bluez monitors (`support.logind`, `monitor.bluez.seat-monitoring`); the ALSA monitor has no seat handling, and keeping pipewire out of `default.target` would not help (socket activation by any early client starts it anyway). The fix is a heal step, not a dependency: `.local/bin/audio-ensure --boot` runs from the Hyprland autostart (waits for PipeWire and the first card, judges after 2 s), and when a card is on `off` although `~/.local/state/wireplumber/default-profile` holds a usable (`available`) profile for it, or no hardware sink/source exists, it restarts `wireplumber` once, re-checks and logs to `journalctl -t audio-ensure` (a notification only when the restart did not help). A healthy boot, a re-login and manual runs change nothing; `audio-ensure --check` is read-only (doctor `audio`, `audio-boot`; the EasyEffects steps follow, see "Mic chain"). An HDMI card whose ports are all `not available` (no audio-capable display) legitimately stays `off`. Manual fix: `audio-ensure` (or `systemctl --user restart wireplumber && systemctl --user try-restart easyeffects`: the `default` metadata lives in the WirePlumber process, so its restart drops EasyEffects' per-stream targets and running recorders would stay on the raw microphone until EasyEffects, which re-moves every stream when it starts, is restarted too; `audio-ensure` does both). **Mic chain (AUDIO2, 2026-10-18)**: every microphone goes through EasyEffects 8 (RNNoise only) before any app hears it. **Routing**: the default source stays the best REAL microphone (never a `.monitor`, never `easyeffects_source`, which has `priority.session` 0 and is ignored by EasyEffects as a default); EasyEffects runs with `useDefaultInputDevice=true` (follows the default, no watcher, no restart on hotplug) and `processAllInputs=true` (moves every `Stream/Input/Audio` without its own target into `easyeffects_source`; monitors excluded). Idle = no links and no CPU (inactivity timer, 10 s). When EasyEffects dies the apps fall back to the raw default microphone by themselves (WirePlumber does not pick a metadata target that no longer exists) and EasyEffects re-moves them when it returns (verified live: probe linked straight to the hardware source while the unit was stopped, relinked into `easyeffects_source` within 1 s of the start; unit restarted 2 s after a SIGKILL). **Priorities** (`.config/wireplumber/wireplumber.conf.d/52-mic-priority.conf`): USB microphone 2600 > Bluetooth headset loopback source 2010 (WirePlumber's own value) > built-in codec mic 1000 (lowered from 2009) > USB webcam microphone 900 (by name, including BRIO, StreamCam and Kiyo, and by udev form factor `webcam` on a USB device, which is how a USB audio device with a video-class interface is tagged; the form-factor rule is unverified on a node until a webcam is plugged in) > `easyeffects_source` 0 (a USB dock or monitor audio interface with an unconnected line-in still counts as a USB microphone, 2600: pick the real one in the input picker); the headset jack is a route switch inside the built-in node (port `analog-input-mic`), so EasyEffects' input name does not change. Stored choices would beat priorities (a node in `default.configured.audio.source[.N]` scores above every `priority.session` below 15000), so `audio-ensure --boot` clears the pin and the whole source history at every login (`ee-ctl auto` = `pw-metadata -n default -d 0 default.configured.audio.source`; sink keys stay), a manual pick (input picker, pavucontrol) pins the source for the rest of the session, the input picker's first row "Automatic (best microphone)" (hub `mic-auto`, leader `a i`) clears it at once, and input picks no longer run `pactl move-source-output` (a stream moved by hand gets a hardware target and leaves EasyEffects). **Managed state**: the preset is `.config/audio/easyeffects-mic.json` (`mic-clean`: `rnnoise#0`, `enable-vad=false` because the old `enableVad=true` gated quiet word onsets, wet 0, gains 0; no gate, no autogain (the old `reference=6` pumped room noise), no limiter, NO pitch/autotune; EasyEffects' UI "Save" over `mic-clean` writes through the link into the repo file), linked as `~/.local/share/easyeffects/input/mic-clean.json` by `ee-ctl prepare` (a per-file link, because stowing the directory would fold `~/.local/share/easyeffects` into the repo); EasyEffects' own KConfig rc (`~/.config/easyeffects/db/easyeffectsrc`) is local runtime state and no longer in the repo: `ee-ctl prepare` writes only the managed keys with `kwriteconfig6` before every start (service mode, `processAllInputs`, `excludeMonitorStreams`, inactivity timer, `useDefaultInputDevice`, empty `inputDevice`, `plugins=rnnoise#0`, `listenToMic=false`, empty blocklist, last preset), never an output-side key (`processAllOutputs` and output plugins are a deferred PERF item), and `ee-ctl load` loads the preset after every start. **Unit** `easyeffects.service` (`.config/systemd/user/`, no `[Install]` on purpose: `WantedBy=default.target` would start it at boot under linger, without Wayland and before the seat ACL): `ExecCondition` on the Wayland socket (a logout does not crash-loop it), `ExecStartPre=ee-ctl quit-stray` (an EasyEffects started by hand from the launcher after a tray Quit runs outside the unit and would make `prepare` refuse and the unit crash-loop to failed: it is asked to quit with `quit_app`, SIGTERM after 5 s; "outside the unit" = the LAST cgroup component of the process is not exactly `easyeffects.service` (an `app-...-easyeffects.service` scope of a hand-started one does not count), and closing one is logged (`journalctl -t ee-ctl`) and notified once, because `prepare` rewrites the managed keys of settings the owner may have changed in that window) then `ExecStartPre=ee-ctl prepare`, `ExecStartPost=ee-ctl load --wait 15`, `ExecStop=easyeffects --quit` (verified only while an instance runs; after a clean tray Quit systemd runs it with no instance, which has not been tried), `Restart=on-failure` after 2 s, 5 failures in 120 s end up failed (health badge), `PartOf=pipewire.service`; started by `audio-ensure --boot`. The old direct `hl.exec_cmd("easyeffects ...")`, the dead XDG autostart file and the tracked rc files were removed; the old pitch/autotune/autogain setup is backed up in `~/.local/share/dotfiles-backups/easyeffects/<time>/` (delete when happy). **`ee-ctl`** (`.local/bin/ee-ctl`, Python stdlib, the only code that talks to EasyEffects): `socket|prepare|load|ns on|off|toggle|status|auto|start|restart|quit-stray` (`ns status [--quiet]`, `status [--json]`; `status` also lists `raw_streams`: capture streams linked straight to a hardware microphone, which bypass EasyEffects, e.g. an app pinned to a device that is not its input or a `node.dont-move` stream; voxtype and the probes are meant to be raw and left out). A reply is read without waiting for a newline (one short line; `get_global_bypass` sends a bare digit) and a hung EasyEffects costs at most `EE_TIMEOUT` (1 s) per probe, so the waybar scripts and the hub never stall. The control socket is `EasyEffectsServer` (QLocalServer, newline-terminated commands; `get_global_bypass` answers a bare digit without a newline, `1` = on, `2` = off): Qt refuses `/run/user/1000` (mode 0710 from the `usr clipboard-acl` traverse ACL), so it lives in `/tmp/runtime-$USER/`, and `ee-ctl` only trusts a socket and a parent dir owned by this uid with no group/other write. **Noise suppression toggle** (D7): `ee-ctl ns toggle` flips the bypass of the rnnoise plugin over the socket (instant, no relink, session only: every EasyEffects start reloads the preset = on; global bypass is not used because it also bypasses the output pipeline); hub toggle row `mic-ns`, leader `a e`, waybar drawer child `custom/sw-ns` (the leader summary lists it only when it is OFF or the chain is broken, class `warning`, no warning during the first 60 s after the Hyprland session started while EasyEffects does not answer yet ("EasyEffects is starting"; a switched-off suppression still warns at once), and `ee-ctl load` pokes the bar when the chain is up, never as an "enabled" switch; hidden without EasyEffects). **`audio-ensure`** modes: no flag = heal cards as before (the decision looks at CARDS only: a pin on `easyeffects_source`, which wiremix or pavucontrol can set, is no card failure and never restarts WirePlumber or sends the "cards did not come up" notification; every mode clears that pin with `ee-ctl auto`, other pins stay in fix mode; after any WirePlumber restart a running EasyEffects is restarted too), then the EasyEffects steps (start a stopped unit, check, one restart; no notification); `--boot` = the same after waiting for PipeWire and additionally clears the source pin and notifies once only when the chain still fails after the restart, worded by the problem class (a broken chain: "noise suppression is not running, apps get the raw mic"; only the A line, i.e. the default source is easyeffects_source with no pin to clear: "the default microphone is EasyEffects' own output (priority rule missing?)"; an A line never triggers an EasyEffects restart, it runs `ee-ctl auto` in every mode) (healthy boot logs one line `mic chain ok: <hw source> -> easyeffects (RNNoise) -> apps`); `--check` also carries the class A line "default source is easyeffects_source although a microphone exists"; `--ee [--verbose]` is the read-only chain check (class C: unit not active, socket, preset != mic-clean, global bypass, rc keys, old pitch/autotune/autogain plugins; class I = info only: manual pin, noise suppression switched off, a stored per-app capture target in `stream-properties`, EasyEffects reading a node that is not the default, capture streams linked straight to a hardware microphone; exit 0/1, 3 = not applicable); `--mic` (raw probe, now with `-P '{ node.dont-move = true }'` so EasyEffects cannot take it) and `--mic --chain` (records `easyeffects_source` while `pw-dump` proves the links `<default microphone> -> ee_sie_* -> easyeffects_source -> recorder`, prints `via <hw node>`, exit 4 = chain not linked to the default microphone). Live check on this machine: raw probe range about +-1500, chain probe about +-245 on the same background. **Dictation stays RAW** (D4): `dictation.sh run` exports `PIPEWIRE_PROPS='{ node.dont-move = true }'` (pipewire-alsa honours it: verified with arecord, linked straight to the hardware source while EasyEffects ran); the stream still follows the default source. Offline A/B (voxtype `small`, one 22 s public-domain LibriVox clip per language, pink and brown noise at SNR 15 and 5 dB, RNNoise through ffmpeg `ladspa` with VAD threshold 0, pseudo-reference = `large-v3-turbo` transcript of the clean clip, one word = about 0.03 WER, numbers in `~/.local/share/workstation-overhaul/audio2-scratch/results.tsv`): mean WER SNR 15 raw 0.196 / denoised 0.183, SNR 5 raw 0.290 / denoised 0.284, but clean speech got worse (ru +0.025, uk +0.088, en 0) and pink noise at 5 dB much worse in ru (+0.28) and uk (+0.15), so the flip rule (denoised <= raw at both SNRs and <= +0.02 on clean in all three languages) is not met and Whisper hears the unprocessed signal (consistent with the literature: single-channel enhancement artefacts rarely help a noise-robust ASR). **Bluetooth** (not testable without the owner's headset, gate G3): a connected headset becomes the default input (2010 beats the built-in 1000) and any recording switches it to HFP until about 10 s after the last recording; whether WirePlumber's autoswitch sees a recording through EasyEffects' plugin nodes is UNVERIFIED (owner step in MORNING.md; fallback: a rule giving `~bluez_input.*` priority 950 so it is used only when picked). Apps that pin a device by name (Telegram set to "Built-in ... Analog Stereo") are processed only while that device is EasyEffects' input: choose Default or Easy Effects Source in their settings. Alternative denoiser: DeepFilterNet (`deepfilternet-ladspa` from extra, `plugins_order ["deepfilternet#0"]`, better quality, about 40 ms latency, several times the CPU) is not enabled. Latency: RNNoise works on 10 ms frames plus about one PipeWire quantum (about 20-35 ms), fine for calls. Doctor: `audio-ee-files`, `audio-ee-chain`, `audio-mic` and `audio-ee-signal` (each records 1.5 s, statistics only, which lights the microphone indicator, so they run only with `./doctor.sh --live` or `DOCTOR_LIVE=1` and are INFO otherwise; the probes skip a Bluetooth default source unless `AE_PROBE_BT=1`), `audio-dictation-raw` (read only: `dictation.sh` exports the property and the running daemon's `/proc/PID/environ` carries it; no config rewrite, no transcription probe), `audio-tests` (`--quick`: the fast sections, under 3 s) next to `audio`, `audio-boot`, `audio-mic`, `audio-hda-ucm`; tests `infrastructure/tests/audio/run.sh` (fake EasyEffects server and fake pactl/pw-dump/systemctl; `--quick` for doctor). Hub rows `mic-ns` (toggle, `a e`), `mic-auto` (`a i`), `audio-chain` (`f e`, `audio-ensure --ee --verbose`). Manual fix: `ee-ctl restart` or `audio-ensure`. `default.configured.audio.source` exists only while a manual pick does. `mic-mute-all.sh status` (hub toggle row `mic-mute`, waybar) is silent and only reports through its exit code; only the real toggle notifies. **Built-in mic on the LENOVO 83HY (IdeaPad Slim 5 16AKP10, 2026-10-17)**: the laptop mic is a digital mic on the Conexant SN6140 HDA codec (card 1, pin 0x1a "Mic at Int Top", `Internal Mic Boost`), not on the Ryzen ACP. The ACP PDM capture (card 2 `acp-pdm-mach`, `hw:2,0` S32_LE only, no mixer controls) is unconnected: raw capture is a constant rail (-2^31 with 5 distinct values), while `hw:1,0` carries a real varying signal. alsa-ucm-conf's HDA profile (`HDA/HDA.conf`: `AcpCardId` found = `Define.DeviceMic "Mic2"`, `HiFi-acp.conf`: `Mic1` with `CapturePCM "hw:${var:AcpCardId}"`) assumes the DMIC is on the ACP, so `Mic1` (the default source) was the dead PDM and the codec's own mic was never offered; dictation then transcribed DC as Whisper hallucinations ("Субтитры ..."). Fix: `.config/wireplumber/wireplumber.conf.d/51-hda-no-ucm.conf` sets `api.alsa.use-ucm = false` for `alsa_card.pci-0000_04_00.6`, so the classic card profile `output:analog-stereo+input:analog-stereo` exposes `alsa_input.pci-0000_04_00.6.analog-stereo` (port `analog-input-internal-mic`, headset jack = port `analog-input-mic`) and `alsa_output.pci-0000_04_00.6.analog-stereo`; the old UCM names (`HiFi__Mic1__source`, `HiFi__Speaker__sink`) are gone. Revert = delete the file + `systemctl --user restart wireplumber`. `audio-ensure --mic` records 1.5 s from the default source into a 0700 tmpfs dir, deletes it, prints only statistics and exits 0 live / 1 constant non-zero (dead or railed) / 2 digital silence (the codec mic reports exact zeros in quiet rooms, so silence is never a failure) / 3 no microphone; doctor `audio-mic` (INFO when no mic) and `audio-hda-ucm`. `/etc/modprobe.d/{lenovo-mic,conexant-fix}.conf` (`options snd-hda-intel model=lenovo`) only hit the first HDA instance, the GPU HDMI card 0, and are harmless leftovers.
