# Docs and tools in the repo

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Docs and tools in the repo (not stowed)
- `doctor.sh` — read-only health check of the approved workstation state (PASS/FAIL per item: managed users `users-*`, lock screen, idle screensaver, hypr-env, ucode, timers, earlyoom, docker GC, pacman cache, pacnew, failed units, zram, Hyprland Lua files/verify/config errors/loaded config, hub bind rows, leader menu, fzf-menu self-test, no rofi dmenu left, waybar, stow links, `selfcopy-tests`). `doctor.sh` and `apply-system.sh` run from a private temp copy that is removed on exit, Ctrl+C and SIGTERM (trap + re-raise, also for a signal that arrives before the wrapper knows the copy's pid: it is forwarded as soon as the pid is set; as root always `/tmp`, never `$TMPDIR`; `infrastructure/tests/selfcopy/run.sh`). Test hygiene: a suite that points `XDG_CONFIG_HOME` at the repo's `.config` (pj, fzf-menu) must never let a real CLI write its config there (the real `glab` once created an untracked `.config/glab-cli` with token keys and failed doctor `stow-clean`): `tests/pj/bin/glab` is a logged-out fake (`bin-glab` is the logged-in one and comes first where wanted), both suites export `GLAB_CONFIG_DIR` / `GH_CONFIG_DIR` into their scratch dir, and `.gitignore` lists `.config/glab-cli/` and `.config/gh/`; `user-tools.sh --dry-run` no longer calls glab while it has no config. `python3 -I` ignores `PYTHONPYCACHEPREFIX` and `PYTHONDONTWRITEBYTECODE`, so every such call in the suites and doctor passes `-B` and the suites export `PYTHONDONTWRITEBYTECODE=1`; `infrastructure/tests/hygiene/run.sh` (doctor `hygiene-tests`) runs the fast suites that import repo Python and fails when a `.pyc` is left in the tree. Run `./doctor.sh` (`--fails` for failures only; `--live` adds the two microphone recordings).
- `docs/keymap.md` — every shortcut of every tool, fully generated by `keymap md --write` (see Shortcut reference above); never edit by hand.
- `apps/obsidian/` — Obsidian configuration (the notes stay in the private repo `brizzinck/obsidian`, cloned to `~/job/obsidian`, vault `knowledge/`, which ignores `.obsidian` and `.obsidian.vimrc`). `vault-config/` is the vault's `.obsidian` folder: every vault's `.obsidian` is a **directory symlink** to it (verified with a real Obsidian 1.14 via the debug port: manifests, snippets, plugin loading and settings writes all work through it), so Obsidian writes its settings straight into the dotfiles tree; its `.gitignore` keeps `workspace*.json`, downloaded plugin code (`plugins/*/*` except `data.json`), `themes/`, the snippet link and the built vimrc out of git. `plugins.tsv` pins the community plugins (id, GitHub repo, release tag, sha256 of `main.js` / `manifest.json` / `styles.css`: relative line numbers, PDF++, Vimrc Support) and `plugins.sh install|check|pin|list` downloads the release assets and verifies the hashes; **update a pin**: `apps/obsidian/plugins.sh pin ID TAG`, `apps/obsidian/plugins.sh install`, commit `plugins.tsv`. Theme: `themes/generated/<variant>/obsidian.css` (template `obsidian.css.tmpl`: Obsidian's `--color-base-*`, backgrounds, text, accent, headings, code, graph) is linked as the snippet `vault-config/snippets/everforest.css` -> `~/.local/state/theme/current/obsidian.css` and enabled in `appearance.json` (Obsidian's own theme stays the default dark one); the theme hook `70-obsidian.sh` does `touch -h` on that link, which makes a running Obsidian reload the colours after `theme black|night|toggle`. `obsidian.vimrc` (hand-written: `jj`, display-line `j`/`k`, `Y` = `y$`, `unnamedplus`, Space sequences for the quick switcher, search, palette, sidebar, tabs, folds) + generated `vimrc-twins.txt` (`layout.py gen obsidian`) are concatenated into `vault-config/obsidian.vimrc`, linked as `<vault>/.obsidian.vimrc`. `apps/obsidian/apply.sh [--dry-run] [--no-download] [--vault PATH]` (called by `install.sh`, idempotent, doctor `obsidian*`) does all of it for every vault in Obsidian's list (or `--vault`, which also registers it in `~/.config/obsidian/obsidian.json`): installs/verifies the plugins, links config, snippet and vimrc, moves a replaced real `.obsidian` (and a foreign vimrc) to `~/.local/share/dotfiles-backups/obsidian/<time>-<vault>/` and copies its extra files (workspace, hand-installed plugins) into `vault-config` (it does not swap a real `.obsidian` while Obsidian runs). A vault is opened for the first time per machine with Obsidian's "Do you trust the author of this vault?" prompt: choose "Trust author and enable plugins". All vaults share one config (including `workspace.json`). Restart Obsidian after the first run. zsh `sudo-command-line` is NORMAL `gs` and `Ctrl+X s` (Hyprland grabs `Alt+S`, so no Alt key of the letter `s` reaches a terminal). The surfaces that cannot have vim keys or ua/ru twins are listed in the block "Audit" of `docs/keymap.md` (rows in `.config/keymap/static.tsv`).
- `browsers/` — Zen `user.js` (memory/cache prefs) and Chrome `chrome-flags.conf` (1 GiB disk cache). They must be copied into the flatpak sandboxes, so `browsers/apply.sh` (called by `install.sh`, merges, idempotent) does that instead of stow.
- `pkg/*.txt` — package lists written by a pacman hook; `infrastructure/` — system files installed by `apply-system.sh` / `apply-memory.sh`.
