# Bar (waybar)

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Bar (waybar)
Two bar objects per output in one waybar process (`.config/waybar/config` includes `modules.jsonc` and a state file each): **compact** (base bar, exclusive zone) and **full** (non-exclusive overlay with `margin-top: -28`, drawn over compact). `SUPER+B` = compact/full (`scripts/bar.sh mode toggle`, SIGUSR1 reaches only the full bar, so the exclusive zone and windows never move), `SUPER+CTRL+B` = hide/show everything (`bar.sh hide toggle`, a reload). State: `~/.local/state/waybar/{mode,hidden}`; `bar.sh render` writes `compact.jsonc`/`full.jsonc` (`start_hidden`) that the config includes, so the mode survives restarts, theme reloads (`bar.sh reload`) and logins (`bar.sh init` clears `hidden`). **Never send SIGUSR1 by hand**; a toggle leaves `$XDG_RUNTIME_DIR/waybar-bar/stale`, and the `monitor.added` hook runs `bar.sh sync --if-stale` so a new monitor gets the right mode. Signals (`pkill -o -u $(id -u) -RTMIN+N -x waybar`, `-o` so a script child that is still named waybar is not hit): 8 toggles drawer and summary, 9 updates, 15 vault; the recording module is a continuous script. Scripts print `class` = `normal|dim|enabled|warning|critical`, `style.css` maps them to palette tokens (green active/enabled, calm yellow_soft warning and red_soft critical tints without pill or bold, everything else grey; the AI module is never highlighted, an exhausted limit is normal; its text is `C 26·4  X –·100` = Claude and Codex % used, 5h·weekly, `–` = no data, from `ai-usage.sh`; the Codex numbers also come live from `codex app-server` `account/rateLimits/read` (`codex-limits.py`, no tokens, in the background at most every 15 min), because the codex-hud cache only changes while Codex runs and missed resets). Alert modules print nothing until relevant; `cache.sh` shares one run of the expensive ones (health, updates, ai) between the two bars; `toggles.sh` is the single source of the switch states (`ns`, microphone noise suppression, is the one switch whose normal state is on: the summary lists it only when it is off or the chain is broken, class `warning`; see "Audio"); `toggles.sh summary [--alert]` (both bars, every 10 s) runs its probes once per 8 s through `cache.sh toggles 8 -- toggles.sh summary-raw` and derives the compact `--alert` text from the cached full JSON (class `dim` = all off = empty text), and every toggle action (`toggles.sh`, `power-profile.sh`, `lid.sh`, `keep-awake.sh`, `idle-toggle.sh`, `mcp-telegram-send`, the night-light and DND binds) deletes `$XDG_RUNTIME_DIR/waybar-cache/toggles.json` before its RTMIN+8 poke; `power-profile.sh get` asks the tlp-pd D-Bus API (`busctl --system get-property`, 4 ms) before `tlpctl get` (170 ms), never `/sys/firmware/acpi/platform_profile` first (tlp-pd balanced on battery shows `low-power` there). `media.sh --follow` kills its `playerctl --follow` child on TERM/INT/HUP/EXIT (it used to leave one orphan per waybar restart). The compact -> full switch is animated by a GTK CSS opacity transition on the full bar (`style.css`): SIGUSR1 only moves that surface between layers, which never maps or unmaps it, so Hyprland layer rules and animations cannot fire (checked: no openlayer/closelayer events); drawers use waybar's own 220 ms revealer. Click grammar: L main, R menu, M quick binary action, scroll value; menus are fzf-menu based. Every tooltip ends with the same hint line, `L: x · M: y · R: z · Scroll: w` (that order, lowercase actions, idle buttons omitted). `WAYBAR_LOG_LEVEL=debug bar.sh restart` logs the GTK widget tree (`$XDG_RUNTIME_DIR/waybar-bar/waybar.log`). doctor checks bar-state, bar-layers (surfaces with the layer namespaces `waybar-compact` / `waybar-full` per monitor), bar-reserved, bar-css. **Watchdog**: `scripts/waybar-run.sh` is a supervisor, not an `exec`: waybar is its child and an abnormal exit (signal, non-zero status) restarts it after 1/2/5/10 s (`journalctl -t waybar-run` has status or signal), one low-urgency "Waybar crashed and was restarted" notification once it stayed up 5 s, and 5 crashes within 120 s end the loop with one "Waybar keeps crashing" notification (`bar.sh restart` starts it again). It checks (never blindly starts) the `ws-ipc-proxy.py` and `pinned-watch.py` daemons on each round, so a restart does not duplicate them. Status 0, SIGTERM/SIGINT/SIGHUP and a vanished Wayland socket are no crash; `bar.sh restart` first stops the supervisor with SIGTERM (pidfile `$XDG_RUNTIME_DIR/waybar-bar/supervisor.pid`, flock `supervisor.lock`; it forwards the SIGTERM to waybar) and then starts a new one, so `reload`/`hide` (SIGUSR2) and a restart never look like a crash; doctor `bar-watchdog`. Crash traces: `DEBUGINFOD_URLS` is already set (`/etc/profile.d/debuginfod.sh`, libdebuginfod comes with `libelf`; the `debuginfod` package, which is only the server and `debuginfod-find`, is not installed and not needed), so `coredumpctl debug waybar --debugger-arguments="-batch -ex 'set debuginfod enabled on' -ex 'thread apply all bt 25'"` symbolizes a good core. The waybar cores seen so far are `truncated` (1-2 MB, `coredumpctl list waybar`), so gdb stops with "Cannot access memory" and `coredumpctl info` shows `#0 n/a`: until a full core exists the only evidence is the signal in the journal and the `waybar.log` lines before it (the one SIGABRT caught while testing the watchdog came right after a burst of SIGUSR2 reloads).

**Panel off = frozen layout state**: Hyprland finishes frame-driven work only inside a render pass, and a dpms-off output presents no frames (hypridle `dpms off` after 20 min idle). Two things therefore stay stale until the panel wakes: the closing fade of a layer (after `bar.sh restart` a `waybar-compact` ghost with `pid: -1` stays in `hyprctl layers`) and the fade-out of the Hyprland error bar (a config error from a reload creates it; the next error-free `hyprctl reload` or `hyprctl seterror disable` only queues the destroy, `ErrorOverlay::draw` finishes it). While the bar is up it reserves `(text height + 10 * scale) / scale` at the top of the focused monitor (two lines at 1.5 = 61 px), so `monitors[].reserved` reads 89 instead of 28, the bars and tiled windows sit 61 px lower (`solitaryBlockedBy` contains `CONFIGERROR`), and nothing in `configerrors` explains it. Waking the panel clears it by itself; doctor `bar-layers` / `bar-reserved` skip a dpms-off output (`bar-panel-off` INFO) and name the error bar when it is the reason on an awake one. Do not chase it with more `bar.sh restart` / reloads while the panel is dark.

The health badge (`custom/health`, `health.sh` over `failed.sh`) also puts the machine-readable `items` (failed units, restart-looping units, sysalert conditions, each with a one-line reason such as the last error line of the unit journal; the tooltip lists the same lines) into its JSON; the left click runs `scripts/health-details.sh`, a fzf-menu list over that same cached run (preview: `systemctl [--user] status` + last 30 journal lines; Enter: restart, stop, stop+disable, reset-failed, journal in less; hub row `failed-units`, leader `s f`), so badge and view cannot disagree. The badge runs through `health-badge.sh` (module signal 16), which stores the exact output it displays as `waybar-cache/health-shown.json`; the view lists that snapshot, marks items that cleared since as `cleared` with a note and pokes the badge (RTMIN+16) so it catches up. A stopped or disabled unit is inactive and never raises an alert, and so is a unit in a normal start job (D-Bus activated daemon, oneshot run by a timer: `activating`, 0 restarts): a unit counts as looping only after `min_restarts` (2) restarts while auto-restarting/activating, and alerts when that holds on two consecutive runs or at 5 restarts. The "reason" of a unit says what the journal really holds (the journal is readable for the owner; a unit that only logged systemd start/stop lines gets that wording, not "not readable"). The bredllm tunnels (`voicebox-tunnel`, `bredllm-reverse-socks`) were removed on the owner's request; their unit files are backed up in `~/.local/share/workstation-overhaul/bredllm-units-backup/`.

Pinned apps (right side of both bars, `group/pinned`): the list is `.config/waybar/pinned.tsv` (id, label, glyph, window-class regex, launch command, notification regex; Telegram, Zen, Chrome, Obsidian, YouTube Music, Bitwarden). **Adding an app = one row, then `bar.sh reload`**: `bar.sh render` runs `scripts/pinned.sh gen`, which writes `custom/pin#ID` per row plus the group into `~/.local/state/waybar/pinned.jsonc`, included by both bars. One daemon, `scripts/pinned-watch.py` (started by `waybar-run.sh`, restarted by the module script if it died, survives bar restarts), follows the Hyprland event socket (open/close/move/focus) and a read-only session-bus monitor of `org.freedesktop.Notifications.Notify`; it renders `$XDG_RUNTIME_DIR/pinned/<id>.json` (what the module prints) and pokes waybar with **RTMIN+14**. `pinned.sh gen` makes the first pin run `pinned.sh module ID` (prints the file and restarts a dead daemon: the one place that does) and every other pin `cat` the file (`cat "$XDG_RUNTIME_DIR/pinned/ID.json" 2>/dev/null || pinned.sh module ID`; the script is only the fallback while the file does not exist), so a poke costs 2 bash starts instead of 12. Classes: `dim` not running, `normal` running, `focused` in front (fg), `new` (soft `yellow_soft` text, no pill). A notification whose app_name or desktop-entry matches the row's regex sets `new/<id>` unless the app is focused; it works with do-not-disturb on (dunst paused still receives the call; no dunst rule is involved); focusing the app, middle click or the menu's "Mark read" clears it. Click grammar: L focus (repeat = next window of the app; launches it when it has no window), M mark read, R fzf-menu (windows, New window / Launch, Mark read, Close all windows; protected classes ask first). `pinned.sh check` (doctor `pinned`) verifies list, generated modules and daemon; `pinned.sh edit` opens the list. `SUPER+T` / `SUPER+S` / `SUPER+N` (Telegram, YouTube Music, Obsidian) call `pinned.sh click ID`, so a bind and the bar's left click focus, cycle and launch the same way (`pinned.sh click ID --dry-run` shows what it would do).
