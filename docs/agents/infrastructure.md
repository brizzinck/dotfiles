# Infrastructure (systemd, TLP, memory, apply-system, network)

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Infrastructure
`infrastructure/systemd/` — `coredump-limits.conf` and the stop timeouts (`stop-timeout.conf` = `DefaultTimeoutStopSec=20s` in `/etc/systemd/system.conf.d/`, `user-at-stop-timeout.conf` = `TimeoutStopSec=30s` for every `user@.service`; the owner's user manager gets 10 s per unit from the stowed `.config/systemd/user.conf.d/10-stop-timeout.conf`, and EasyEffects' `ExecStop` is bounded by `timeout`; a service that hung on SIGTERM held reboot and poweroff for up to 2 min, which looked like a dead reboot; `--only config` re-executes systemd when they change; doctor `stop-timeouts`) (installed by `apply-system.sh`) and legacy `hyprdynamicmonitors` user units (unused: monitors are static now).

`infrastructure/tlp/` — TLP drop-in configs (`/etc/tlp.d/`), not stowed (system path, outside `$HOME`, machine-wide rather than per-user). `61-battery-care.conf` caps battery charging; `install.sh` copies it into `/etc/tlp.d/` and enables `tlp.service` (copied, not symlinked, so it doesn't dangle if the installing user's account is later removed on a shared machine). Non-ThinkPad Lenovo hardware (`ideapad_laptop` driver) only supports a binary `Long_Life` charge mode (vendor-fixed cutoff, about 80 % on this unit) via the kernel's `charge_types` API — no exact percentage like ThinkPads' `charge_control_end_threshold`. To pick up edits without a full rerun: `sudo cp infrastructure/tlp/61-battery-care.conf /etc/tlp.d/ && sudo systemctl restart tlp`. `62-power.conf` sets platform profile, EPP and CPU boost for **all three** tlp-pd profiles, because TLP leaves a setting untouched when the active profile has no value for it (with only `CPU_BOOST_ON_BAT=0` the CPU stayed capped at 2.0 GHz on AC after a battery session until reboot). The suffix follows the profile, not the power source: `performance` -> `_ON_AC` (platform `balanced`, EPP `balance_performance`, boost 1), `balanced` -> `_ON_BAT` (`low-power`, `balance_power`, boost 1, the default on battery), `power-saver` -> `_ON_SAV` (`low-power`, `power`, boost 0). `dynamic_epp` stays off (kernel 7.1+: TLP's EPP writes fail with it on) and there is no `amd_prefcore` setting (no-op on 7.2). `apply-system.sh --only config` installs both drop-ins and runs `tlp start` only when one of them changed; doctor `tlp-power` compares the installed files with the repo (INFO while the old copy is installed) and the live boost / EPP / `dynamic_epp` with the active `tlpctl get` profile (the platform profile only as INFO: Fn+Q changes it behind TLP).

`infrastructure/memory/` — RAM safety net, copied (not stowed) into `/etc` by `install.sh`: zram swap (`zram-generator.conf`), sysctl tuning, zswap off (avoids double compression), journald cap. (`daemon.json` with log limits and the BuildKit GC cap now lives here too but is installed by `apply-system.sh`.) Apply (or re-apply after edits) without a full rerun: `./apply-memory.sh` (self-elevates with sudo, idempotent).

`apply-system.sh` — one idempotent root script for the whole system layer (sections `cleanup upgrade install remove config services net greeter users mcp disk boot flatpak summary`; `--dry-run`, `--only <section>` or a comma list such as `--only users,mcp`, run in section order). It installs `infrastructure/{memory/earlyoom,memory/docker-daemon.json,pacman/*.hook,systemd/coredump-limits.conf,tlp/6[12]-*.conf}` into `/etc`, edits `makepkg.conf`/`pacman.conf`/`fstab`/`grub`, and keeps `pkg/{native,aur,flatpak}.txt` current through a pacman hook (`/usr/local/bin/dotfiles-pkglist`, rendered from `infrastructure/pacman/dotfiles-pkglist.in`). Run: `sudo ./apply-system.sh` (preview: `./apply-system.sh --dry-run`).

`infrastructure/net/` — network exposure, applied by `sudo ./apply-system.sh --only net` (preview: `./apply-system.sh --dry-run --only net`; idempotent, each service is touched only when its own drop-in changed). Nothing is meant to listen on the LAN, and a default-deny firewall covers what does by accident (measured before: `0.0.0.0:8788` camoufox gateway, `*:2017` v2rayA web UI, `*:3488` ch-ui, LLMNR `:5355`). **Firewall = ufw** (installed; the rules live in `/etc/ufw` and one CLI manages them; with `MANAGE_BUILTINS=no` it only adds its own chains next to Docker's iptables-nft rules, whereas an `/etc/nftables.conf` starting with `flush ruleset` would delete Docker's NAT and forward tables on every nftables restart): default deny incoming, allow outgoing, deny routed, IPv6 on (`/etc/default/ufw`), logging low; ufw's own `before.rules` already accept loopback, established/related, the needed ICMP/ICMPv6, DHCP replies and the mDNS/SSDP multicast groups, so `infrastructure/net/ufw-rules.conf` (extra rules, one `ufw` argument list per line, only ever added) is empty and holds the commented, disabled examples for `tailscale0` and KDE Connect (1714-1764 tcp/udp, LAN only). `/etc/default/ufw` points `IPT_SYSCTL` at `/etc/ufw/dotfiles-sysctl.conf` (the stock file without its two `rp_filter` lines: strict reverse-path filtering can drop VPN/TUN traffic of v2rayA, Happ and Pritunl, and the machine runs on loose mode). The section also writes the marker `/etc/ufw/.dotfiles-net`, which switches doctor `net-exposure` from INFO to FAIL. There is no sshd; the firewall locks out nothing local. **Docker**: ufw and Docker both manage iptables. Container traffic to the internet keeps working (Docker's FORWARD rules apply after ufw's chains, which pass new connections through), and the host reaches published ports. Published ports bypass ufw's INPUT rules (DNAT traffic is forwarded, not input), so a port published on `0.0.0.0` stays open to the LAN despite the firewall: publish on `127.0.0.1:` (all current ones are) or filter in the `DOCKER-USER` chain; `net-exposure` flags a `docker-proxy` listener on a non-loopback address. A container that must reach a service of the host (`host.docker.internal`, the bridge gateway `172.x.0.1`) is blocked by default-deny INPUT: no compose file under `~/job` does that, and a container with `network_mode: host` (ch-ui, `td-clickhouse-ui`, `*:3488`) listens on the host itself, so ufw does cover it; the commented example in `ufw-rules.conf` shows the bridge allow (`allow in on docker0 ...`, `br-+` for compose networks). Stale hand-added rules (`1080/tcp` and `3128/tcp` were in `user.rules` before) are never removed silently: the section warns and doctor fails until they are deleted (`sudo ufw status numbered`, `sudo ufw delete N`) or added to `ufw-rules.conf`. **LLMNR off**: `/etc/systemd/resolved.conf.d/10-no-llmnr.conf` (`LLMNR=no`, `systemctl try-reload-or-restart systemd-resolved` only when it changed); MulticastDNS stays on (`.local` lookups, UDP 5353, allowlisted; with the firewall only the multicast group gets through). **v2rayA on loopback**: drop-in `/etc/systemd/system/v2raya.service.d/10-loopback.conf` with `Environment=V2RAYA_ADDRESS=127.0.0.1:2017` (the package's own variable, see `/etc/default/v2raya`; the packaged file is not edited), the unit is restarted only when it runs. The camoufox gateway (`~/job/youtube/skills/flow-render/scripts/camoufox_gateway.py`, user unit `camoufox-gateway`, not in this repo) defaults to `HOST=127.0.0.1` now, because every client (`flowpipe`, `flow_cli.py`, `run_out3.py`, the docs) uses `http://127.0.0.1:8788`; it takes effect on `systemctl --user restart camoufox-gateway`. **doctor `net-exposure`**: INFO until the section ran, then FAIL on a firewall that is not enabled/active/default-deny/IPv6, a drop-in that differs, an `ss -lntu` listener on a non-loopback address that `infrastructure/net/listeners.allow` does not list (TCP LISTEN and UDP below the ephemeral range; the list holds only `tcp 3488` ch-ui and `udp 5353` mDNS, each with its reason) and a stale ufw rule; the rule set itself needs root (`sudo ufw status verbose`). Logic in `infrastructure/net/exposure-check.sh`, tests `infrastructure/tests/net/run.sh` (doctor `net-tests`).
