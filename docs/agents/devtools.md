# Dev tools (db, api, ci, forge)

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Dev tools (DEV-d: databases, HTTP, forges, local CI)
Four launchers in `.local/bin` (Python 3 stdlib, absolute shebang `#!/usr/bin/python3 -I` because they receive secrets through `envs run`), one shared library `.config/devtools/devtools.py` (imports the `envs` script as a module for root discovery, TOML reading, the agent check, tool paths and the test-mode rules; per-run directories; keyboard-layout switch; TOML and YAML escapes). **Secrets only through envs**, no second store: project secrets with `envs run -e ENV`, global ones (GitLab token and host) with the global scope `envs run -g`. Nothing secret reaches argv, a repo file or a persistent file; the launchers refuse an agent (`refuse_agent`) wherever a value is involved (`db list|check`, `api check`, `ci list` stay names-only).
- **Global scope**: public `~/.config/envs/global.toml` plus user-owned global.local.toml keep legacy declarations/tool connections; private global.env adds inline reference declarations. `run -g --only A,B -- COMMAND` has no project binding/mise and uses only its separate global approval under agents. Canonical plain exports come only from secrets/env.sh; configurable wrappers use envs-wrap.zsh and never fetch during shell startup (see Dev environments).
- **`db`** (menu through `fzf-menu`; hub row `db`, leader `j d`, tmux `prefix b` popup in the pane's directory): connections are `[db.NAME]` tables: `driver` (mariadb, mysql, postgres, clickhouse, sqlite), exactly one location (`docker` = compose service of THIS project, `container` = name, `host` [+ `port`], `path` (sqlite, inside the project), `url` = a declared secret that holds the whole URL), `database`, `user` | `user_secret`, `password` = the NAME of a declared secret (a value is refused), `tunnel` (ssh host alias), `envs = [...]`, `read_only`. Every field is validated (regexes for host, database, user, tunnel, docker names, port 1-65535, sqlite path realpath inside the root, secrets must be declared); `db check [--all]`, `db list [--json]` (names only, no vault, no docker, 65 ms), `db add` (flags or prompts; declares the secret name, then tells you `envs set`), `db open NAME [-e ENV] [--ro|--rw] [--prod] [-g]`, `db cli NAME|docker:C`. The menu lists the cwd project, every bound project, the global scope and running DB containers without a config; keys (NORMAL letters, Alt twins, ua/ru from the library): Enter/`o` open, `r` read-only for the next open, `e` environment, `c` client inside the container, `a` add, `E` edit, `y` copy the URL without the password, `s` start a stopped container (asks; it prints `docker compose --project-directory ... up -d SERVICE`), `?`. **Open**: `exec envs run [-g] -e ENV --allow-missing -- db _open ...` (no vault at all when the connection needs no secret); the child resolves docker/container with read-only queries (`docker ps -a --format` with label fields, `docker port NAME PORT/tcp`; never `.Config.Env`; hosts publish an EPHEMERAL port, so it is looked up at every start; a stopped container stops with the compose command; a ClickHouse port that answers `GET /ping` with `Ok.` is the HTTP port of ch-ui and is refused, lazysql speaks the native protocol), builds the URL (percent-encoded), writes the per-run config `$XDG_RUNTIME_DIR/devtools/db-PID/config.toml` (dir 0700, file 0600; stale dirs of dead pids removed at start), appends the `[theme]` block of the active variant, `chdir`s into the run dir (no repo `.lazysql.toml` can load), switches the keyboard to us and execs `lazysql -config FILE --no-telemetry` with `LAZYSQL_NO_TELEMETRY=1 LAZYSQL_NO_UPDATE_CHECK=1 DO_NOT_TRACK=1 SQL_EDITOR=nvim`; the other injected secrets are removed from its environment. A protected environment opens read-only unless `--rw` (typed `rw` on a terminal). `db cli` runs `docker exec -it C sh -c '...'` with the root password read from the container's own environment INSIDE it (`MARIADB_ROOT_PASSWORD`, `POSTGRES_USER`; clickhouse-client prompts for a password) and no vault. **G3 result (checked on lazysql v0.7.0)**: with `URL = '${env:DB_URL}'` the connection form (`e` in the picker) shows the URL EXPANDED, password included. So the URL in the config holds placeholders only (`mysql://app:${pw}@127.0.0.1:32768/app`) and the values reach lazysql through its environment and `printf` commands (`Commands = [{ Command = 'printf %s "$DB_PW"', SaveOutputTo = 'pw' }]`; `${usr}` and `${q}` the same way); the form then shows `${pw}`, and no screen (picker, form after a failed connect, tree, table, help) and no `ps` line holds a value. A tunnel is `localhost:${port}` plus an `ssh -N -o ExitOnForwardFailure=yes -o BatchMode=yes -L ${port}:HOST:PORT ALIAS` command with `WaitForPort`. rainfrog stays the unused fallback.
- **`api`** (hub `api`, `api-test`; leader `j a`, `j t`; tmux `prefix a`): `api` = posting on the project's collection (`[api]` collection `api`, env_dir `api/env`, tests `api/tests`, all inside the project) with `--env base.env --env <env>.env` (those that exist) and a tmpfs `secrets.env` of `NAME=${NAME}` lines for the injected declared secrets, so `${API_TOKEN}` works in a request. posting runs with a SCRUBBED environment (`HOME TERM COLORTERM LANG LC_* XDG_* POSTING_* WAYLAND_DISPLAY DISPLAY`, PATH = the fixed safe dirs, `EDITOR=nvim`, the declared secrets) and the run dir as cwd (posting's settings read a `.env` of the cwd), so `env.secret.sh` exports and a repo `.env` never reach a template or script. Stowed `.config/posting/config.yaml` (checked on posting 2.11.1): `theme: everforest`, `layout: horizontal`, `use_host_environment: false`, `history.enabled: false` (the history keeps resolved URLs and response bodies on disk), `editor: nvim`. Outside a project posting opens `~/.local/share/posting/default`. `api test [FILES] [-e ENV] [--report]` = `hurl --test --color --variables-file RUN/vars.env --file-root ROOT --glob TESTS/**/*.hurl` with `HURL_SECRET_<NAME>` for each injected secret (hurl prints `***` for them in logs and reports, checked on 8.0.1), the plain variables of the env files (comments, `${...}` references and secret names dropped) and the run dir as cwd (no repo `.hurlrc`). `api init` writes the skeleton (refuses to overwrite) and a `.gitignore` line; `api check` flags a literal for a declared secret name in `api/env/*.env` and any `.env` inside the api directories.
- **`ci`** (hub `ci`; leader `j r`): detects `.github/workflows/*.yml` (act) or `.gitlab-ci.yml` (gitlab-ci-local) from the git top-level (both: `--system` or the picker); the menu lists the jobs (act `-l` table, `--list-csv`): Enter run, `a` everything (act: the `push` event), `w` workflow and event, `n` dry run (act `-n`, gcl `--preview`), `l` last log, `x` clean (act containers named `act-*` after a `[y/N]`, the `.gitlab-ci-local/` directory), `i` image-less gcl jobs in a container. `[ci]` in `.envs.toml`: `secrets = [declared names]` (default none) and `github_token = false` (act: `gh auth token` as `GITHUB_TOKEN`); with neither nothing touches the vault. act: `-s NAME` with NO value (it takes it from its environment), empty `--env-file/--secret-file/--var-file/--input-file` in the run dir, explicit cache paths, `--pull=false` (the first run pulls a medium catthehacker image, about 1-2 GB: `ci` asks once; stowed `.config/act/actrc` maps ubuntu-latest, 24.04, 22.04 and sets `--container-architecture linux/amd64`). gitlab-ci-local: `--variables-file RUN/variables.yml` (the only secrets file: 0600 on tmpfs, double-quoted escaped scalars, removed by the wrapper on exit, error, INT, TERM and HUP: tested). **Hostile-repo findings** (checked on act 0.2.89 and gitlab-ci-local 4.76.1): act reads `./.actrc` from its CWD, so both tools run from the tmpfs run dir with `-C` / `--cwd ../rel` (gcl wants a relative path) on the repository; gcl reads a repo `.gitlab-ci-local-env` (CLI defaults such as volumes or privileged) from the project itself, so `ci` stops on it unless you confirm (`--trust-env-file`). The log of the last run is `$XDG_RUNTIME_DIR/devtools/ci-last.log` (tmpfs: a job can echo a secret, so it is not under `~/.local/state`). gitlab-ci-local jobs WITHOUT an `image:` run ON THIS MACHINE (shell executor, the menu header says so; `i` switches to containers, default image ruby:3.1).
- **`forge`** (hub `forge`, `glab-ci`; leader `j f`, `j g` is `pj clone`): the host of `origin` decides: github.com -> gh-dash with a per-run config = stowed `~/.config/gh-dash/base.yml` (sections "My PRs", "Review requested", "Involved", issues "Assigned", "Created"; delta as diff pager; NO `theme:` key) + the active variant's `gh-dash-theme.yml` (one `theme:` key; tested), run from the run dir with an explicit `--config` so a repo `.gh-dash.yml` is not read; auth is gh's own. Any other host -> `envs run -g -- glab-tui` (`GITLAB_TOKEN` and `GITLAB_HOST` from `Env/global`; other injected global secrets dropped; cwd = the repository only when `origin` is the `GITLAB_HOST`, else the run dir; a repo with `.glab-tui/` or `.config/glab-tui/` asks `[y/N]` first; an ssh alias of GitHub such as `github.com-work` or a host whose `ssh -G` HostName is github.com goes to gh-dash). glab-tui's config is `infrastructure/dev/glab-tui-config.toml` copied once by `user-tools.sh` (not stowed: glab-tui rewrites it on Save View); its `u` self-update key cannot be remapped, so it is disarmed with a run-dir `gh` stub; a repo-local `.glab-tui/config.toml` can bind commands to keys (code, see above). zsh: `glab() { $_ENVS_BIN run -g --only GITLAB_TOKEN,GITLAB_HOST -- /usr/bin/glab "$@" }` (the token never sits in the shell or a glab config; `command glab` would fail because envs execs the command, not the shell), and `.zshrc` exports `LAZYSQL_NO_TELEMETRY=1 LAZYSQL_NO_UPDATE_CHECK=1` for hand runs. Hub row `glab-ci` = `envs run -g --only GITLAB_TOKEN,GITLAB_HOST -- /usr/bin/glab ci view` (the hub's terminal sits in `$HOME`: start it from a tmux pane in the repository).
- **Theme**: palette templates `lazysql.toml`, `posting.yaml`, `gh-dash-theme.yml`, `glab-tui.toml` (both variants committed under `themes/generated/`); lazysql and gh-dash get theirs through the launcher's run config, posting and glab-tui through stowed links (`~/.local/share/posting/themes/everforest.yaml`, `~/.config/glab-tui/themes/everforest.toml` -> `current/...`), so no theme hook is needed (each tool reads its theme at start). The tool directories (`~/.local/share/posting`, `~/.config/posting`, `~/.config/glab-tui`, `~/.config/gh-dash`) stay real directories (`install.sh` creates them) because the tools write their own state next to the linked files. The TUIs read characters themselves: no ua/ru twins; the launchers switch the keyboard to us at start (`hyprctl switchxkblayout all 0`, never restored; `DEVTOOLS_NO_LAYOUT=1` skips) and the audit row of `docs/keymap.md` names them.
- **Installs**: repo packages `hurl act glab python-pipx` (`apply-system.sh` / `install.sh` lists, hub install hints), the rest user-level and pinned in `infrastructure/dev/user-tools.sh [--dry-run] [--only NAME]` (the same pins go into `/srv/devtools` for td and yc with `--shared`, see "Users"; never sudo; each step skipped when the installed version is at least the pin; `install.sh` runs it after the toolchains; sysup's go / pipx / npm / cargo steps move the tools forward, the pins are the fresh-install floor): lazysql `go install ...@v0.7.0` (source builds have no telemetry collector; release builds ask once and send by default), gh-dash `go install github.com/dlvhdr/gh-dash/v4@v4.26.2`, posting `pipx install posting==2.11.1`, gitlab-ci-local `npm install -g --ignore-scripts gitlab-ci-local@4.76.1`, glab-tui `cargo install --locked --version 0.9.3 glab-tui-crate`, then `glab config set --global telemetry false` when glab has the key (unverified: glab is not installed here), then the one-time glab-tui config copy.
- **Threat model (honest)**: the base is envs': a same-uid process can read `/proc/PID/environ` of lazysql, posting, hurl, act or gitlab-ci-local while they run (lazysql holds the password in its environment as `DB_PW`) and can run `rbw get` while rbw is unlocked. Added: (a) gitlab-ci-local's variables file exists on tmpfs (0600) for the run; (b) what the tools run is CODE from the repository: act runs workflows in containers, gcl shell jobs on the host, posting scripts in posting's Python, a repo `.gh-dash.yml` is ignored but a repo `.glab-tui/config.toml` can bind commands (envs binding is about secrets, not about code: open only trusted repos); (c) `db cli` is full access inside the owner's own containers (docker group = root equivalent anyway); (d) gh keeps its plaintext `~/.config/gh/hosts.yml` token (agents use gh; doctor `gh-token-storage` is INFO; moving it is owner decision Q2); (e) lazysql release builds carry telemetry: avoided by the source build plus env and flag; (f) the self-update features of lazysql are irrelevant (go-owned binary); glab-tui's hard-wired `u` key downloads the latest release over `~/.cargo/bin/glab-tui` with `gh release download`, so `forge` puts a failing `gh` stub first on its PATH (FIX-DEVd).
- **FIX-DEVd (REVIEW-DEV-d, tests = section 15 of `tests/dev/run.sh` + envs 19.10/19.11 + sysup 11; each case fails on 404daa0)**: `db` refuses any `%` in `host` (an IPv6 scope id such as `::1%x];touch PWNED;#` reached lazysql's `sh -c` tunnel Command) and quotes the ssh line (`-L ${port}:'[::1]:5432' -- ALIAS`; an alias never starts with `-`); names, hosts and ESC sequences of a foreign `.envs.toml` are cleaned before printing and an invalid connection is a non-actionable `invalid: run db check` row. `api` reads env files only as plain files (no symlink, `O_NOFOLLOW`, regular, one hard link, inside the root) and refuses a collection/tests tree with a symlink that leaves the project; `api test --report` writes under `$XDG_STATE_HOME/api/<project>/report`. `ci`: `[ci] github_token` needs the binding (`envs bind`), `act` gets `--container-daemon-socket -` (opt-in `[ci] docker_socket = true`), `[ci] secrets` with a gitlab-ci-local pipeline that has `image:`/`services:` (or `--container-mode`) is refused because gcl puts every variable on the argv of `docker create` (allowed with `[ci] docker_secrets = true` / `--docker-secrets`, or when /proc is mounted hidepid=invisible; the apply-system option for that is still open, see MORNING), the `.gitlab-ci-local-env` gate runs before anything is listed, `.gitlab-ci-local/output` is deleted after a run with secrets. `envs run --only A,B` injects just those names (zsh `glab`, hub row). envs bindings: identity = lineage (the stored root commit still existing counts, so `git fetch --unshallow` keeps a binding; a fork shares it: lineage, not trust), a moved repository (old root gone, same root commit) rebinds with `y` and replaces the old row, other gone roots show `(gone)` and still need the typed name; rows written before identities existed learn it at first use (a different repo that took their path in between is accepted: `envs bind` again pins it). `sysup`: `SYSUP_TEST_HOME` counts only below /tmp, /var/tmp, /dev/shm; `npm -g update --ignore-scripts`; posting is exact-pinned from `infrastructure/dev/posting-requirements.txt` (hashes, `posting-lock.py`, `pip --require-hashes`; `pipx upgrade-all --skip posting`). Run dirs: every launcher removes dead `db-/api-/ci-/forge-<pid>` dirs; `.config/user-tmpfiles.d/devtools.conf` ages `ci-*`.
- **Tests** (`infrastructure/tests/dev/run.sh [--quick] [--keep] [--only=N]`; fakes in `tests/dev/bin` for lazysql, posting, hurl, act, gitlab-ci-local, gh-dash, glab-tui, glab, gh, docker (answers from a JSON file; read-only queries only), hyprctl, ssh; a fake `fzf-menu` in `bin-menu` for the non-UI sections; `WAYLAND_DISPLAY`, `DISPLAY` and `HYPRLAND_INSTANCE_SIGNATURE` are unset so a test can never open a window): sections 1 validation (every bad field incl. injection strings), 2+3 URL building (`urltest.py`: the password `p@ss:w/rd#?%` round-trips) and docker resolution (labels, ephemeral port, stopped, the ClickHouse HTTP `/ping` check against a local server), 4 `db open` end to end through the real envs with the fake vault, 5 agent refusal (`CLAUDECODE` and a copied `/bin/sh` named claude), 6 autodiscovery rows and `db cli`, 7 global connections and `db add`, 8 `api`, 9 `ci` (act argv, empty files, secrets by name, gcl file escaping and removal on success, failure, INT, TERM), 10 `forge` and the zsh `glab` function, 11/12 layout switch and the render check, 13u `user-tools.sh` with fake go/pipx/npm/cargo, and (full only) 13/14 the db menu and the ci picker in a private tmux with the real fzf-menu, 16 timing (`db list` 65 ms; the db menu draws its first frame in about 540 ms including the tmux start).
