# skw windows (workspace 8)

Topic file of the agent docs. `CLAUDE.md` holds the index and the rules that apply everywhere.

### skw windows (workspace 8)
- Every Hyprland `camoufox` window initially maps to `8 silent` (`camoufox-ws8` in `hyprland.lua`). Existing `float-camoufox` (float, centre, no initial focus) and `camoufox-render-unfocused` stay in force: automation keeps painting on the hidden workspace. There is no flash on the active workspace if the listener is unavailable. Non-Camoufox windows are ignored.
- `.local/lib/skw-shim/skw` precedes the real binary on PATH. `.zshenv` loads `.config/zsh/skw-shim.zsh` for every zsh, including `zsh -c` and `zsh -lc`; `.zshrc` loads it after mise and prompt/cd hooks restore precedence after mise refreshes PATH. Bash/Python subprocesses inherit this PATH. Already running shells/agents inherit their old PATH until a new zsh starts; absolute calls to `~/.local/bin/skw` bypass attribution. The real binary and the skw source repository are never modified.
- The shim recognises `CLAUDECODE`, `AI_AGENT`, and the `/proc` ancestor/interpreter checks copied from `envs.agent_context()` (keep both lists in sync). Agent `start`, `restart`, and `automation` calls atomically write private `$XDG_RUNTIME_DIR/skw-ws8/agent-NAME` files: epoch, agent name, verb. Global/command options and multiple `start` profiles are supported; the listener resolves name, numeric ID and UUID aliases from `ps`. If marker installation fails, a private `inhibit-NAME` record keeps placement conservative; without `XDG_RUNTIME_DIR` both programs use `/run/user/UID`. Manual launches record `human-REF` invalidation epochs so a pending intent is cancelled across aliases. `create` only creates a profile; it is not marked. Help calls are not marked. The shim removes itself and its aliases from PATH, refuses recursion, restores the caller's umask, then `exec`s the real CLI with unchanged arguments, stdio and exit status.
- `.local/bin/skw-ws8` (Python stdlib, `-I -B`) is the `skw-ws8.service` user daemon, started at boot like `crash-watch.service` and also by Hyprland autostart. It subscribes to socket2 before snapshotting existing windows; it never moves that snapshot. It reconnects after compositor restarts and uses that socket's instance signature for `hyprctl`/`hyprd`. A runtime lock prevents duplicate placers. Decisions go to `journalctl --user -u skw-ws8.service`: only the class, address and a fixed reason, never titles, URLs or profile names.
- On a new Camoufox window it resolves address → PID using `hyprctl clients -j`, then PID → profile/session using the real `skw ps --json` (`items[].session.pid/started_at`). It silently returns a window to `hyprctl activeworkspace -j` only if the session is not agent-marked and either this is its first window or it has no automation clients (`skw automation NAME --list --json`). The dispatcher is `hyprd movetoworkspacesilent WS,address:0x...`, which leaves focus unchanged. Session/first-window history survives listener restarts under `$XDG_RUNTIME_DIR/skw-ws8/`; duplicate open events are ignored. Missing/invalid metadata and failed queries leave windows on the hidden workspace. An unresolved event persistently removes the first-window exception from that PID and from sessions already started at the uncertainty cutoff. A final workspace check avoids overriding a window the owner already moved away from the managed desk.
- **Timestamp correction to the original design:** a marker written before `exec start` naturally precedes the new session's `started_at`. Comparing only `marker >= started_at` would expose agent windows. A fresh marker still tags an existing session; a previously unconsumed `start/restart` marker also binds once to the exact PID + `started_at`, and that binding persists. An old session observing a `restart` intent cannot consume it before the new session starts. A manual `start/restart` through the shim clears the pending marker; a consumed marker cannot bind a later session. This preserves mandatory `exec` and avoids extra skw calls in the shim. Attribution is fail closed when an old pending marker remains after an absolute-path launch bypassed the shim while the placer was down.
- Edges: manual Ctrl+N while an automation client is connected stays on 8; all windows of an agent-started session stay on 8, including later manual windows. If metadata is unavailable, a manual window may stay on 8. Existing windows are untouched when the service starts. Direct absolute-path agent launches bypass the shim; use `skw` from a fresh zsh. No browser/profile/client is started or stopped by this feature.
- Workspace override: export `SKW_WS8_WORKSPACE` (positive integer; default `8`) in the Hyprland launch environment and the user manager environment (`systemctl --user set-environment SKW_WS8_WORKSPACE=9`, then restart `skw-ws8.service`). The Lua rule and the service must receive the same value; reload the config after changing it. Deployment: `stow .`, `systemctl --user daemon-reload`, `systemctl --user enable --now skw-ws8.service`, one `hyprctl reload`.
- Checks: `skw-ws8 --check` / `./doctor.sh --only skw-ws8` (also part of full doctor). Missing skw is INFO; incorrect login-zsh PATH or a disconnected placer in a Hyprland session is FAIL. `infrastructure/tests/skw-ws8/run.sh [--quick]` uses fake skw/hyprctl/hyprd, a private socket2 and no display environment; it covers placement, markers, restarts, recursion, stdio, PATH and shim latency. It never contacts the real skw daemon or dispatches into the live compositor.
