# Login screen (greetd, Quickshell)

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Login screen (greetd + Quickshell)
`infrastructure/greetd/` (repo-only; `sudo ./apply-system.sh --only greeter` copies it to `/etc/greetd`, `/usr/local/lib/greeter`, `/usr/local/bin`): greetd runs `greeter-session` as user `greeter`, which starts a minimal Hyprland (`hyprland.lua`, same `monitors.lua` copied from the session) running the Quickshell greeter in `greeter/` (`Greeter.qml` singleton = state, auth and keys; `OutputView`/`FormPane`/`BottomBar` views; `users.json`; `Theme.qml` links to `themes/generated/black/greeter-palette.qml`, rendered from `themes/palette/templates/greeter-palette.qml.tmpl`) through `run-qs` (10 s watchdog: no `greeter-alive` marker = kill and fall back to tuigreet). `greeter-session` starts `/usr/bin/Hyprland -c ...` directly, never `start-hyprland` (that wrapper restarts a crashed compositor in `--safe-mode` and would never return, so the fallback would be skipped; `doctor.sh` checks this) and ends a compositor without a live greeter after 25 s; any exit without the `greeter-ok` marker lands in tuigreet. Look = hyprlock. Only the owner (`users.json` keeps `@OWNER@`, rendered by `apply-system.sh`; large, monogram S in a green ring, `main`) and an "Other user..." entry that asks for a typed name are shown; no autologin, no photos. The form is on the monitor under the pointer, the other monitor shows the clock; layout pill US/UA/RU; F2 sessions, F12 power; vim keys by physical scancode (`docs/keymap.md`). A wrong password keeps the text in the field (cursor at its end, shake + red outline + "Wrong password (n)"; typing clears the error, `Esc` clears the text). Show / hide password: eye button in the field, a "hidden / shown" pill in the bottom bar and `Ctrl+E` (physical E, scancode 26, so it works on ua/ru; free of Ctrl+H/J/K/L); `Greeter.revealed` is hidden by default and goes back to hidden after a login, when the user entry changes and 30 s after the last edit (`revealTimeoutMs`). `GREETER_TEST_SESSION=1` (the VT3 test) shows a yellow TEST MODE marker and, for a non-Shell session, does not launch anything: the greeter cancels the greetd session and says "Test mode: login OK, session not started" in green (`/usr/bin/true` used to make the greeter just come back empty). The session starts through `/usr/local/bin/hypr-login` (the user's login+interactive shell runs `start-hyprland`, so `.zshrc` exports and the autostart incl. `vault.sh session-start` are as before). The F2 "Shell" session is `/usr/local/bin/shell-login` (`infrastructure/greetd/shell-login`: finds the terminal, puts the VT back into text mode, `exec`s the owner's login shell with `-l -i`, log in `~/.local/state/greeter-shell.log`); **a session `cmd` in `users.json` must be ONE argv element**, because greetd runs `sh -c "exec <argv joined by spaces>"` and loses the quoting of a `sh -c '...'` array (that was why the old Shell session ended in the same second; doctor checks it). Root can log in under "Other user...": greetd uses its own PAM service `greetd-login` (`[general] service` in `config.toml`, `infrastructure/greetd/pam/greetd-login` = the package's `/etc/pam.d/greetd` without `pam_securetty` and with `pam_oo7` (unlocks the Secret Service with the login password), which fails for root because greetd sets no `PAM_TTY` before authenticating; the packaged file is a pacman backup file and stays untouched); `hypr-login` gives root a root shell instead of Hyprland. The greeter shows greetd errors as English text (`Greeter.errorText`: a PAM service error is not a wrong password). Text consoles: `Ctrl+Alt+F1..F6` are also Hyprland binds (greeter and session) that call logind `Seat.SwitchTo`, next to Hyprland's native XF86Switch_VT keysyms; logind starts `autovt@ttyN` (alias of `getty@`, doctor `tty-console`). `apply-system.sh` only runs `systemctl enable greetd` + `disable getty@tty1`, never `--now` (greetd `Conflicts=getty@tty1`): the owner reboots to switch. Rollback from TTY2: `sudo systemctl disable greetd && sudo systemctl enable getty@tty1 && sudo reboot`; emergency: GRUB `systemd.mask=greetd.service`; text greeter only: the one-line `command =` swap at the top of `/etc/greetd/config.toml`. Tests: `infrastructure/greetd/lint.sh` (qmllint), `GREETER_SELFTEST=1 GREETER_DEMO=1 QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software qs -p infrastructure/greetd/greeter`, `GREETER_DEMO=1 qs -p infrastructure/greetd/greeter` (floating window, fake greetd, password `demo`), `sudo greetd --config /etc/greetd/config-test.toml` (VT3, real PAM, dry-run session but a real Shell session, root login possible; Ctrl+Alt+F1 returns). `doctor.sh` checks the repo side always and the installed side as INFO until greetd is enabled. `/etc/greetd/config.toml` is a pacman backup file: after a greetd upgrade a `config.toml.pacnew` can appear (the doctor `pacnew` check then fails); delete it and rerun `--only greeter`.
