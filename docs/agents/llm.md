# Local LLM (llm, llama.cpp)

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Local LLM (DEV-e)
`llm` (`.local/bin/llm`, stdlib Python; `llm --help` is the full reference) runs **llama.cpp on the Radeon 860M through Vulkan, on demand**: nothing is resident at boot and nothing listens on TCP; the model is in memory (and on the GPU) only while it is used. Packages `llama-cpp` + `ggml-vulkan` (Arch extra; REPO_PACKAGES, `sudo ./apply-system.sh --only install`; updated by the normal pacman step of `sysup`). **`ggml-vulkan` is a separate package** and the Vulkan backend of whisper-cpp too: without it `llama-server` silently runs on the CPU (doctor `llm-pkg` fails on that). The packaged `llama-server.service` units (system and user, TCP 8080, `WantedBy=default.target`) are never enabled (doctor `llm-no-tcp`). Voxtype ships its own statically linked ggml and is unaffected; the Telegram `telegram-whisper.service` runs `-ng` with `PrivateDevices=yes`, so after `ggml-vulkan` is installed it loads the backend, finds no device and still transcribes (tested with `GGML_BACKEND_PATH` and `VK_ICD_FILENAMES=/nonexistent`: "ggml_backend_init returned NULL", transcription ok). Chain, the whisper pattern in the owner's user manager (`.config/systemd/user/`): `llm.socket` (`ListenStream=%t/llm/llm.sock`, `SocketMode=0600`, `DirectoryMode=0700`, `RemoveOnStop=yes`, enabled by `install.sh`, the only thing running at login) -> `llm-proxy.service` (`systemd-socket-proxyd --exit-idle-time=5min %t/llm-server/llama.sock`) -> `llm-server.service` (`StopWhenUnneeded=yes`, no `[Install]`, `ExecStart=llm _serve`, `ExecStartPost` waits up to 180 s for `GET /health` and stops waiting when the server died, so the first request is only forwarded once the model is loaded). Five idle minutes after the last connection the proxy exits, the server is unneeded and stops: the process, the Vulkan context and the GPU memory are gone (measured: GTT back to the baseline +-64 MB at the idle stop 5 min after the last request). `--sleep-idle-seconds` is not used (it keeps the Vulkan context). **Access**: unix socket only (`%t` is `/run/user/UID`, 0700), plus a bearer token (`--api-key-file ~/.local/state/llm/token`, 0600 in a 0700 dir, `llm token ensure|rotate|path`; `_serve` cannot write the state dir inside its sandbox, so the client or `install.sh` creates it first; `/health` is open like llama-server's); td, yc, aimcp, tgconfirm and web pages cannot reach it, doctor never connects to the socket (it would load the model). `llm status` reads systemd and a cached `--list-devices` (key: llama-cpp + ggml-vulkan versions, kernel, binary mtime).

**Server flags** (fixed in `llm _serve`; `.config/llm/server.conf` allows only `ctx` 8192, `threads` 4, `flash_attn` auto, `gpu_layers` all, plus a local `server.local.conf`; unknown keys are ignored with a journal warning): `--host %t/llm-server/llama.sock --api-key-file TOKEN -m MODEL -a ID -ngl all -fa auto -c 8192 -np 1 --cache-ram 0 --no-webui --no-slots --offline --reasoning off -t 4 -tb 4` (`--cache-ram` defaults to 8 GiB of RAM: it must be 0; never `-v` or `--log-prompts-dir`: selections and diffs must not reach the journal, checked with a sentinel; never `--port`). `llm _serve --dry-run` prints the argv, `_serve` removes a stale socket, logs `llm: model ID, devices: ...` and records the GTT before the load (`llm status` shows the delta). **Limits** of `llm-server.service`: `Nice=5 CPUWeight=50 IOWeight=50 CPUQuota=400% MemoryHigh=2G MemoryMax=4G MemorySwapMax=0 TasksMax=64 OOMScoreAdjust=500` (host RAM only: GPU memory is **not** charged to the memcg here, it is bounded by model + context + one slot), `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=strict`, `ProtectHome=read-only`, `ReadWritePaths=-%C` (Mesa shader cache), `ProtectKernelTunables/Modules/Logs`, `ProtectControlGroups/Hostname/Clock`, `RestrictAddressFamilies=AF_UNIX` (Vulkan needs no netlink: verified), `RestrictNamespaces`, `UMask=0077`; **no `PrivateNetwork`** (not permitted in the user manager: a journal warning at every start) and no `PrivateDevices` (needs `/dev/dri`). earlyoom `--prefer` has `llama-server`. `systemd-analyze --user security llm-server.service` = 5.3 MEDIUM.

**Models** (`.config/llm/models.tsv`: id, file, url pinned to the Hugging Face commit, sha256, size, role, note; the sha256/size are the LFS values checked against the HF API): `qwen3.5-2b` (**default**, `unsloth/Qwen3.5-2B-GGUF` Q4_K_M, 1.28 GB), `qwen3.5-4b` (quality, 2.74 GB), `gemma-4-e2b` (candidate for Ukrainian, 3.1 GB), `qwen3-4b-2507` (fallback if a Qwen3.5 hybrid op ever runs on the CPU, 2.5 GB), `qwen3.5-0.8b` (tiny). Files live in `~/.local/share/llm/models/` (0700), state in `~/.local/state/llm/{model,token,fetched/*.ok,devices.json,bench/}`. `llm models fetch [NAME...|--default|--all-candidates]` = `curl -fL -C -` into `<file>.part` (resumable, https only), size + sha256 check, atomic rename, a stamp (size, mtime, hash) so `llm models check`, `llm status` and doctor need no re-hash; a wrong hash deletes the download (exit 1); `install.sh` runs `--default` (AUTO1). `llm model [NAME|--pick]` switches (must be fetched; a loaded server is stopped and started again). One model at a time. Only the default is downloaded on this machine; the bake-off (`llm models fetch qwen3.5-4b gemma-4-e2b`, then `llm bench --cold --quality` per model) is the owner's decision.

**Client**: `llm [PRESET] [--to/--from LANG] [--json] [--no-stream] [--timeout S] [--max-tokens N] [--temperature T] [--dry-run] [TEXT...]` over `http.client` on the unix socket (OpenAI `/v1/chat/completions`, `chat_template_kwargs {"enable_thinking": false}`, `<think>`/`reasoning_content` never printed), streaming only when stdout is a terminal. **Callers pipe text on stdin, never argv** (the later IDEAS1 hotkeys do). Presets in `.config/llm/presets.toml`: `ask` (default), `translate` (`--to en|ru|uk`; auto: Cyrillic -> en, Latin -> ru), `fix` (punctuation, case, typos, same wording: for dictation), `rewrite`, `shorten`, `explain`, `commit-msg` (staged diff or stdin; the diffstat is always included, the diff is cut at 12000 characters with `[diff truncated]`; Conventional Commits, subject <= 72), `fix-layout`; the text is always the user message and the system prompts call it data. Output of translate/fix/rewrite/shorten/commit-msg has one wrapping code fence or pair of quotes stripped (pasted verbatim). Input limit 12000 characters. Exit codes 0 / 1 error / 2 usage / 3 not available (message = the exact fix) / 4 timeout / 130. `--dry-run` prints the request with the input LENGTH only (tested with a sentinel), also for `fix-layout`. **fix-layout is deterministic first**: `layout.py convert --from us|ua|ru --to us|ua|ru` (`convert_text()`, pure physical-key retyping incl. shift level and the ASCII positions, unknown characters unchanged; the Punto-like key of IDEAS1 reuses it) builds the candidates (as typed, us->ru, us->ua, ru->us, ua->us, deduplicated); a bigram guess (vowel check, a word of 3+ letters, score >= 0.3, lead >= 0.2) decides the obvious cases **without loading the model** (a hotkey answers in milliseconds, also with no package installed); only the unsure band asks the model for one digit under the grammar `root ::= [0-N]` (measured: the 2B model answers 0 for almost everything without the examples in the prompt, hence offline-first), and a missing or nonsense answer falls back to the guess. `llm chat` (REPL), `llm status [--json]`, `llm start` (preload), `llm stop` (unload now), `llm bench [--cold] [--quality]` (speed from the server `timings`; `--quality` runs `.config/llm/eval/`: chrF per direction ru/uk/en, layout rows, three commit diffs). Hub rows (`actions.d/dev-e.tsv`, group AI, the download row in Setup) and leader `SUPER+; x o` status, `x h` chat, `x z` unload, `x k` model, `x v` download; rows that need `llama-server` show the install hint (`llama-cpp ggml-vulkan`) until it is there. No hotkey, no GUI, no waybar module in this stage.

**Measured** (2026-10-18, AC power, the extracted `llama-cpp` 0.6.0 + `ggml-vulkan` 0.26.0 packages run through the real units, `LLM_SERVER_BIN` drop-in under `/run/user`; Radeon 860M RADV, default `qwen3.5-2b`): all 25/25 layers on the GPU, `graph splits = 2` (no op on the CPU), model + context 1.4 GiB projected; generation 52 t/s (target >= 35), prompt 670 t/s at 209 tokens (>= 600), warm one-sentence translate 0.6 s (<= 1.2), cold first token after a stop 1.5 s twice (<= 3; the very first start ever, which compiles the pipelines, answered a translate in 2.7 s), GTT +1.9 GB while loaded (<= 2.2), llm-server MemoryCurrent 200-240 MB (<= 1 GB), GTT back to the baseline after the idle stop, a Vulkan Voxtype `small` transcription loop running at the same time: both finish, the translate takes 0.7-1.0 s. Quality (chrF, 3 sentences each): ru-en 83, uk-en 68, en-ru 32, en-uk 41, ru-uk 83; layout 11/11, commit messages 3/3 (format, length, area). Pending for the owner: the same numbers with the installed packages, the 4B / gemma bake-off, concurrent dictation by voice.
