# Managed users (td, yc, service users)

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Users (managed child users: td, yc, later service users)
Registry: `infrastructure/users/managed.tsv` (user, profile, flags, accent, note; names and colours only, no secrets), parsed by `infrastructure/users/lib.sh` (sourced by `apply-system.sh`, `usr`, `doctor.sh`). Flags: `service` (no terminal, no picker entry, no dotfiles profile), `noacl` (the owner gets no ACL on that home), `nobecome` (no passwordless sudo or machinectl for the owner), `clipboard` (Wayland socket write access), `create` (apply-system creates the account: `/usr/bin/nologin`, password locked, home 0700; td and yc are never created, re-shelled or re-grouped). **M1 added `aimcp`** (the Telegram MCP service account) with one row `aimcp - service,noacl,nobecome,create purple ...`: no ACL for the owner, no passwordless `sudo -u` or `machinectl`, so the owner reaches it only with a sudo password (doctor `mcp-aimcp-sudo`). Passwords, shells and groups (wheel, docker) of td/yc are never changed by anything here.
- **Root layer** = `sudo ./apply-system.sh --only users` (step 4c renders `/etc/tmpfiles.d/vault-share.conf` and `/etc/vault-share/scopes.tsv` for the vault-share broker, see "Vault reorganisation") (`--dry-run` lists exactly which ACL entries go and prints the rendered sudoers/polkit text; `infrastructure/users/rollback.sh` undoes it). It (1) creates `create` accounts, (2) removes every `user:U` / `default:user:U` ACL entry of every managed user from the owner's home tree (the before-state of the top two levels is kept in `/var/lib/usr-managed/`), (2b) `infrastructure/users/home-acl.sh` (also behind `./apply-system.sh --dry-run`, doctor `home-acl` and the tests; `report|apply|check|restore`) strips the extended ACLs of the owner's home that nobody intended: any path with an ACL xattr but no named entry of somebody else (default-ACL skeletons that make new files 0650/0750, leftover masks, a default mask; `setfacl -b` leaves the group bits at the effective permission so nothing widens); every change of a path in the home (setfacl, chmod, the marker) runs AS THE OWNER (`setpriv --reuid --regid --init-groups --reset-env` from `/` with umask 077 (the owner's HOME/USER/LOGNAME, not root's), no PAM login stack like `runuser`; root only writes the before-state), the marker is created component by component without following a symlink, and a secret location whose real path leaves the home and the checkout is skipped; it keeps paths with a named entry of anybody else (listed), paths under `home-acl-keep.txt` (empty: no tool here sets an ACL on the home) and files of other uids (Docker volumes); before-state `/var/lib/usr-managed/home-acl-before-<time>.txt.gz` (only the stripped paths; `rollback.sh --home-acl-cleanup` runs ALONE, as the owner, over every snapshot oldest first, owned non-symlink paths only, no chown; the snapshots it used move to `restored-<time>/` so a second rollback never replays them over later changes), marker `~/.local/state/usr/home-acl-cleanup`; the same run removes the group/other bits of the secret locations in `secret-paths.txt` (`.ssh` (top: ssh-keygen writes *.pub 0644), `.gnupg`, `.local/state/mcp`, `.local/share/skw`, `.config/{secrets,rbw,Bitwarden*,gh}`, `.local/share/rbw`, `.claude/.credentials.json`, `env.secret.sh`, ...; `full` = everything below must stay owner-only, `top` = the 0700 directory is the lock because an app keeps creating files there with umask 022; before-modes in `secret-modes-before-<time>.txt`), and `install.sh` creates `env.secret.sh` 0600; doctor `home-acl` scans the top 5 levels plus the secret locations within 10 s (INFO until the marker exists, then FAIL with the fix `sudo ./apply-system.sh --only users`), (3) gives the owner `u:OWNER:rwx` + a default ACL on each managed home that has none (directories get mask rwx; 0600 files stay owner-only through the mask and are reached with `usr exec` / `usr edit`; `.ssh`/`.gnupg` untouched), (4) creates `/srv/dotfiles`, `/srv/nvim-shared` and `/srv/devtools` (owner:owner 755, so the commit hook and the tool installer need no password) and writes `/srv/devtools/.owner` (the owner's name, the trust anchor of the PATH rule below; `rollback.sh` never removes `/srv/devtools`), (5) installs `/etc/sudoers.d/50-usr-managed` (`OWNER ALL = (USR_MANAGED) NOPASSWD: ALL`, Runas list = managed users with `become`, never root; `Defaults>USR_MANAGED !sudoedit_checkdir` for `usr edit`) after `visudo -c -f`, and `/etc/polkit-1/rules.d/50-usr-managed.rules` (`org.freedesktop.machine1.host-shell` YES only for the owner's local active session and a listed target `user`) after `node --check`, (6) disables linger of interactive users, (7) publishes, links the profiles as each user and starts `usr nvim-sync` in the background (`USERS_NVIM_SYNC=skip|foreground`). `install.sh` runs it with the other safe sections; with no existing managed user that has a profile it only creates the two directories.
- **`usr`** (`.local/bin/usr`, stowed for the owner, published for the users): `list`, `menu`, `term USER [--attach|--shell]`, `exec USER [-C DIR] [--] CMD` (`sudo -n -u USER -i`), `edit USER PATH` (`sudoedit -u`), `files`, `logs`, `link USER [--dry-run|--restore]`, `sync [--worktree]`, `nvim-sync [--background|--force]`, `clipboard-acl`. Hub rows `actions.d/u7.tsv`, leader group `u`.
- **Terminals**: `SUPER+SHIFT+T` = `usr menu` (fzf-menu, V1b rule: Enter terminal, NORMAL `a` attach, `s`/Alt+Enter shell, `f` files, `l` logs); `SUPER+CTRL+T` stays reserved for M1. A window is `ghostty -e usr _session USER tmux`, which runs `machinectl shell -E TERM -E WAYLAND_DISPLAY=<owner socket> USER@ <shell> -lc 'exec tmux new-session -s term-<ns> -e WAYLAND_DISPLAY=... \; set-option destroy-unattached on'` (fallbacks if machinectl fails at once: `sudo -n -u`, then `su -`). Launched by hand only: closing the window ends the tmux session and its panes, no linger, no user services. Windows keep the ghostty class (safe-close still protects them); `vault-who.py` reads `machinectl shell USER@` on the pty, so SUPER+CTRL+U types USER's password there.
- **Shared dotfiles**: `usr sync` (run by `.githooks/{post-commit,post-merge,post-rewrite}` through `core.hooksPath` (`.githooks/pre-commit` is the gitleaks scan, see DEV-a), set by `install.sh`; hooks run detached, never fail a commit, skip linked worktrees) publishes the *committed* `~/dotfiles` (git archive of HEAD plus the submodules at their recorded commits, `private/` and `env.secret.sh` excluded by `infrastructure/users/publish.exclude`) with rsync into `/srv/dotfiles` (world-readable, public content only), `--worktree` publishes the working tree for a test. A managed user's profile (`infrastructure/users/profiles/cli.txt`: `.zshrc .gitconfig .config/{zsh,atuin,fzf,layout,tmux,nvim,git,lazygit,yazi,workmux,mise,devtools}`, `.local/bin/{theme,pj,envs,fzf-menu,bw-setup,db,api,ci,forge}` and, as FILE entries in the user's own real tool directories, `.config/{posting/config.yaml,act/actrc,gh-dash/base.yml,envs/global.toml,lazydocker/config.yml}`; no desktop configs) is linked with absolute symlinks by `usr link` running as that user; replaced files/links go to `~/.local/state/usr/backup-<time>/` (`--restore`). Per-user, never shared: `~/.zshrc.local` (accent marker in the prompt), `~/.tmux.local.conf` (accent in the status line), `~/.gitconfig.local` (identity), `~/.config/secrets/env.sh` (0600; canonical-only sourcing with guarded legacy fallback while absent), `~/.ssh`, `~/.claude*`. The owner's `~/.gitconfig.local` gets `safe.directory = /home/U/*` lines from `usr sync`. Selected `.claude`/`.gemini` children use the checked private publication; old clone parent links are backed up without dereferencing, unmatched links are inventoried and the clone is retained.
**Shared private layer (SECRETS C1-C2)**: `sudo ./apply-system.sh --only users` creates `/srv/private` as the publisher named by root-owned `/etc/usr-managed/devtools-owner`, group `dotfiles-private`, mode 0750. The dedicated group's supplementary members are exactly existing interactive managed users with profiles (td/yc); service users and the publisher are excluded. Named read-only access/default ACLs give effective 0640 files and 0750 directories/executables; descendants may retain the publisher's primary gid with owning-group ACL `---`. Root repairs metadata only; the root stays gated at 0700 during descendant repairs and exact group reconciliation, then reopens at 0750. `usr sync` holds the normal sync lock, publishes public content normally, then pins PRIVATE HEAD independently of the gitlink (also with `--worktree`), validates every tracked name/type, and scans the whole snapshot as staged additions against empty HEAD with default-only trusted gitleaks rules and redaction. Missing scanner/findings/errors fail closed. Private working content/rules/allow comments are never consulted. Only approved manifest subtrees are extracted; account settings, auth, histories/caches, symlinks and nested repositories stay out. `private/` and legacy exports never enter `/srv/dotfiles`.

`infrastructure/users/private-links.tsv` is the safe fallback; a committed private `links.txt` may select only `.claude/agents`, `.claude/skills`, `.gemini/config/skills` descendants, plus tracked `.claude/CLAUDE.md` / `.gemini/GEMINI.md`. Sources and destinations must match. Invalid/missing explicit entries abort the whole manifest. `usr link USER` keeps `.claude`/`.gemini` real directories and links only selected children from a certified publication. Known parent links into that same user's old clone are moved as links into 0700 backups; credentials are never traversed/copied. Five-column MANIFEST records retain original kind/target plus exact new target and public/private layer, with old three-column records accepted. Restore/pruning removes only exact managed links and preserves local edits; empty retired parents can be restored. Metadata-only no-follow inventory reports unmatched clone links; the clone is never deleted. `.published` records private revision, normalized manifest/policy hashes, scanner version/time only. Scanner failure retains the previous publication; a failed/interrupted copy removes certification until repaired. rsync updates multiple files in place, so the read-only tree is not an atomic snapshot switch. `~/.local/state/usr/private-status` records ready/failed/uncertified/not-configured; public publish completes and manual sync returns nonzero after private failure. Hooks remain detached.

**Canonical shell exports (SECRETS C3)**: `.config/zsh/secrets.zsh` sources only the passwd-home `~/.config/secrets/env.sh` after no-follow regular-file/single-link/owner/mode/ACL checks. A present unsafe canonical file never falls back. While canonical is absent, safe legacy `~/dotfiles/env.secret.sh` is sourced with one warning per shell. Unsafe source diagnostics never display assignments. Ancestors reject foreign owners/writers; the managed home's existing named publisher writer is allowed only through the root-owned publisher anchor. `usr secrets-migrate --self|USER [--dry-run]` copies bytes without parsing/displaying them, keeps a 0600 recoverable backup under `~/.local/state/usr/secrets-backups/`, atomically publishes without overwriting a concurrent canonical file and retains the original source inode as `original-env.secret.sh` beside the first backup; split filesystems retain that inode under ignored, stow-excluded 0700 `~/dotfiles/env.secret.backups/`. Both files present = retained/refused; unsafe paths/active ACL grants/hard links/symlinks = refused; migration removes fully masked inherited canonical ACL skeletons without reading values, while preserving existing ancestor publisher ACLs. User bootstrap initializes canonical only through this same checked helper; apply-system invokes migration as each target user before linking. File migration does not remove secrets already exported by running shells; new sessions acquire changed exports/group membership. The later `envs import -g` step classifies vault-bound versus deliberate plain exports.

- **Shared nvim**: the nvim fork's `lua/shared.lua` picks the plugin root, Mason root and lazy lockfile. Managed users read `/srv/nvim-shared/{lazy,mason}` when `/srv/nvim-shared/.ready` exists and they cannot write there; the owner keeps `~/.local/share/nvim` unless `NVIM_SHARED=/srv/nvim-shared` is set (`NVIM_SHARED=0` turns it off). A read-only config directory gets a per-user `lazy-lock.json` in the state dir that follows the committed pins; base46 cache, treesitter parsers, sessions stay per user. `usr nvim-sync` runs the committed config headless (`NVIM_BOOTSTRAP_ONLY=shared`: plugins + Mason only) and writes `.ready` (hash of lock + Mason list); Mason paths inside packages are `/srv/nvim-shared/...`. Managed users cannot install tools: ask the owner to add them to `lua/plugins/mason.lua` and run `usr nvim-sync`.
- **Clipboard**: `usr clipboard-acl` (Hyprland autostart) gives a `clipboard` user `--x` on `$XDG_RUNTIME_DIR` (traverse only), `rw` on the Wayland socket and an explicit empty ACL entry on every other socket there (PipeWire, the session bus, ...). Nothing a managed user runs needs PipeWire (checked). `copy-clipboard.sh` accepts the absolute `WAYLAND_DISPLAY` that `usr term` passes.
- **Shared dev tools (USERS-SYNC)**: td and yc get the same terminal tooling as the owner. **`/srv/devtools`** (owner:owner 755, read-only for them; created by the users section, filled by `infrastructure/dev/user-tools.sh --shared [--prefix DIR] [--dry-run] [--only NAME] [--check|--stamp]`, run as the owner, no sudo) holds the PINNED versions of `lazysql` and `gh-dash` (`go install` into `go/bin`), `posting` (a venv at `venv/posting` from `posting-requirements.txt` with `--require-hashes --no-deps`, rebuilt when the lock or the python minor changes), `gitlab-ci-local` (`npm install --prefix npm --ignore-scripts`), `glab-tui` and `workmux` (`cargo install --locked --version --root cargo`, built with the owner's toolchain) and the zsh plugin `fzf-tab` (a git checkout at a pinned commit in `share/`); `bin/` holds relative links to all of them. Exactly the pin (not "at least": nobody else writes there), `.ready` holds the stamp (pins + lock hash + python minor; `--check` is read-only and exits 1 with one line per stale tool, `--stamp` prints what the pins want); managed users never install or update there (no per-user rustup / cargo / go builds), and the owner keeps his own copies in his home. Refresh: `usr devtools-sync [--background] [--force]` (no-op while `--check` passes; `usr sync` starts it in the background after a publish when `/srv/devtools` exists, is writable and not current, sysup has a `devtools` step after `go`, both skipped quietly without the tree; it refreshes the managed users' seeded files afterwards (`usr _link --seeds-only`, never a full relink), which is what makes `fzf-tab` appear). **One installer at a time, no retry storm (FIX-USERS)**: `user-tools.sh --shared` holds `$PREFIX/.install.lock` (a second run, e.g. the owner's by hand while the background run `usr sync` starts is still working, waits up to 30 min and then finds the work done), runs from `/` with the system `python3` (`pyvenv.cfg home = /usr/bin` is part of "current") and without the caller's `GOFLAGS`, `RUSTFLAGS`, `CARGO_TARGET_DIR`, npm prefix, `MISE_*` or mise PATH entries (`go install -trimpath`), keeps the pip cache, and `--check` reads posting's version from the dist-info instead of running the venv's python as the owner; `usr sync` passes `--if-new`: the stamp of the last ATTEMPT is in `~/.local/state/usr/devtools-attempt.stamp` and the same pins are tried again automatically only after 6 h (`USR_DEVTOOLS_RETRY`), while a manual `usr devtools-sync` and sysup always try (the log is `~/.local/state/usr/devtools-sync.log`; the users section already starts the first fill, so there is no manual step). **PATH rule**: `.config/zsh/devtools.zsh` (sourced from `.zshrc` and from a managed block that `usr link` writes into the user's OWN `~/.zshenv`, `~/.profile` and `.bash_profile` / `.bash_login` when they exist, so `zsh -c`, `zsh -lc`, `ssh td@host CMD`, `usr exec` and `bash -lc` have it too; the bash block runs the zsh file with `DF_DEVTOOLS_PRINT=1` and appends what it prints) appends `/srv/devtools/bin` to PATH of a user who is NOT the tree's owner (so the owner is unchanged and the user's own installs win), and `shared_bin()` / `_shared_tool()` in `.config/devtools/devtools.py` add it to the lookup of `db api ci forge` (after `/usr/bin:/usr/local/bin:~/.local/bin` and the user-level dirs; `forge` also puts it on glab-tui's PATH) only while the tree is trustworthy: a real directory (no symlink) with a real `bin/`, owned by root or by the account named in the root-owned anchor `/etc/usr-managed/devtools-owner` (root:root 644, written by the users section; `.owner` in the tree, owned by that account, must agree: the account that owns the tree can always write a matching `.owner`, so on its own it only proves that nobody but root created the directory; without the anchor file, before the users section runs again, `.owner` decides as before; the account the anchor names never uses the tree, whoever owns it), the root, `bin/` and `.owner` not group/other-writable, `/srv` itself root's and not group/other-writable, and for the launchers the file a tool name really resolves to sits inside the tree, is owned like it and has no group/other-writable directory above it. A tree a managed user can write is never trusted. `_shared_tool()` returns the verified real file, not the `bin/` link. Test hooks: `DF_DEVTOOLS_TEST=1` with `DF_DEVTOOLS_ROOT` / `DF_DEVTOOLS_ME` / `DF_DEVTOOLS_ANCHOR` (zsh; the root must be below /tmp, /var/tmp, /dev/shm or `$TMPDIR` and hold a `.devtools-test` file), `DEVTOOLS_SHARED_ROOT` / `DEVTOOLS_TEST_UID` / `DEVTOOLS_ANCHOR` (python, verified envs test mode only, root below a fake-tool directory or the scratch runtime / state directory; verified test mode without an accepted root never falls back to the machine's real `/srv/devtools`, so the suites give the same result with or without it). Files `usr link` makes besides the profile list (`seed_user_files`; the repo's relative theme links break from `/srv/dotfiles`): absolute theme links into the user's own `~/.local/state/theme/current` for posting (`~/.local/share/posting/themes/everforest.yaml`), glab-tui and btop, the starting `~/.config/glab-tui/config.toml` and `~/.config/btop/btop.conf` copied once when missing (the tools rewrite them), and `fzf-tab` COPIED (not linked: a plugin directory owned by another account is "insecure" for compaudit) from the shared tree into `~/.oh-my-zsh/custom/plugins/fzf-tab` with a marker file `.from-devtools` holding the pinned commit (refreshed when the commit changes; a directory of the user without the marker, or a link of his own, is left alone). Every seed is recorded in `~/.local/state/usr/seeds.tsv`; a seed that replaces another link moves it to the same `backup-<time>` as the profile links (MANIFEST kind `seed-link`), and `usr link --restore` removes the seeded links that still point where we put them, the copies nobody edited and the fzf-tab copy, then puts the backups back (`--restore --dry-run` only prints). Also changed for managed accounts: a launcher's install hint says the owner installs it (`managed_account()`: the launcher runs from `/srv/dotfiles`); the global scope accepts `~/.config/envs/global.toml` when it resolves into the published tree owned by the owner (`_published_file()` in `envs`; `global.local.toml` and every other file must still be the user's own); the launchers fall back to a private `/dev/shm/devtools-run-UID` (0700, refused when planted, `ci-*` files older than a day removed there because it outlives the session) only when `XDG_RUNTIME_DIR` is unset and the user has no `/run/user/UID` (`usr exec`, sudo; a `usr term` window has one; an explicitly set but missing `XDG_RUNTIME_DIR` is created, not replaced); tmux `prefix m` (the owner-only hub) answers "not available for this user" instead of failing. **Not given to td / yc, and why**: `llm` (per-user user manager + socket units + GPU, td has no linger), `sysup`, `hub`, `keymap`, `cursor-apply`, `mcp-*`, `linux-pass` / `2fa-import` (the owner's vault and desktop; `vault-browse` is given read-only, see below), `ee-ctl` / `audio-ensure` / `obs-ctl` / `drives` / `lock-screen` / `hyprd` / `pinentry-themed` / `claude-statusline` (desktop), the desktop configs and the Hyprland scripts; `bw-setup` refuses for them (exit 4: no rbw configuration, no bw login); the cli profile links `vault-share` and `vault-browse` (read-only share mode over the owner's broker, see "Vault reorganisation" under Passwords and 2FA). System packages (atuin, mise, difftastic, carapace, hurl, act, glab, llama-cpp) come with `sudo ./apply-system.sh --only install` and are then on everyone's PATH; `lazygit` / `lazydocker` / the Go formatters stay each user's own `~/go/bin`. Names-only commands work for them without a vault (`envs status|check`, `db list`, `api check`, `ci list` once `act` is installed); value reads use the scoped broker and stop when the owner has not authorized/unlocked it. Owner steps: `sudo ./apply-system.sh --only install,users` (also writes the anchor and starts the fill; follow it with `tail -f ~/.local/state/usr/devtools-sync.log`, `usr devtools-sync` runs it again), then `usr link td && usr link yc` once so the `.zshenv` / `.profile` blocks and the fzf-tab copy appear, managed users do not configure their own vault accounts. Doctor `users-devtools` (INFO until `/srv/devtools` exists, then FAIL on a foreign owner / missing `.owner` / group-other-writable file / a stale or missing tool), `users-devtools-anchor` (INFO while the anchor file is missing, FAIL when it is not root:root 644 naming the owner); tests in `infrastructure/tests/users/run.sh` (dry-run argv, stamp, `--check` with a fake `go`, `devtools-sync`, the zsh and python trust matrices, profile and seeds) and section 17 of `infrastructure/tests/dev/run.sh`.
- Checks: `infrastructure/tests/users/run.sh` (offline: parser, rendered sudoers via visudo, polkit rule against a mock polkit, usr in scratch dirs, stubs for the picker/session, nvim root choice) and doctor `users-*` (INFO until the section ran, then FAIL on drift; `users-devtools` for the shared tool tree). No agent has sudo here: the root layer is applied by the owner.
