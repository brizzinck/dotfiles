# Shell and git conveniences

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Shell and git conveniences (DEV-a)
- **Secret scan (pre-commit)**: `.githooks/pre-commit` (same `core.hooksPath` as the `publish` hooks; `install.sh` also points the public nvim submodule at it) runs `gitleaks git --staged --redact` over what is staged (about 25 ms, default rules plus the allowlist in the root `.gitleaks.toml`, which is not stowed). It also runs in linked worktrees (agents commit there), and it fails closed: gitleaks missing or crashing blocks the commit (exit 3 = leak, any other status = "failed to run"). It guards against accidents and is not a lock: `git commit --no-verify` skips it, merge / rebase / cherry-pick / `git am` never run pre-commit (a branch committed with `--no-verify` merges onto master untouched), and anything that can edit files (every agent) can edit the hook (`core.hooksPath` is relative). `gitleaks:allow` comments and `.gitleaksignore` files are not honoured (the hook passes `--ignore-gitleaks-allow` and refuses a `.gitleaksignore`), and the allowlist is read from the COMMITTED `.gitleaks.toml` (`git show HEAD:.gitleaks.toml`), so a commit cannot allowlist its own finding: a false positive gets an exact `regexes` entry, committed alone, then the change. **`.githooks/pre-push`** (same `gitleaks-lib` helper, same committed config, fail closed, `--redact`) scans what a push sends: `<remote sha>..<local sha>` per pushed ref, `--not --remotes=<remote>` for a new ref, the whole history on a first push, nothing for a delete, and `-m` so a merge commit is diffed against every parent (a secret that exists only in a conflict resolution or an evil merge is found). That is what catches commits that never ran pre-commit (merge, rebase, cherry-pick, `am`, `--no-verify`); bypass `git push --no-verify`. Neither hook can stop an agent that edits them, so **the real backstop is GitHub secret scanning push protection** on `brizzinck/dotfiles` and `brizzinck/nvchad` (owner step, MORNING.md): it runs on GitHub's side, where no local process can switch it off. Managed users get no hook (a global `core.hooksPath` would override the hooks of their company repos), only the alias `git leaks` (staged scan). Hub row `secrets-scan` (leader `f g`) scans the whole history; doctor `gitleaks-hook`, `gitleaks-history` (scans with the COMMITTED `.gitleaks.toml` through `gl_history_scan` of `.githooks/gitleaks-lib`, so an uncommitted broad allowlist cannot silence it, and FAILs when that committed file has a `paths` / `commits` / `stopwords` allowlist, a `regexTarget` other than `secret`, a catch-all regex (`.*`, `.+`, `\S+`), `disabledRules`, a `[[rules]]` table (an entry with the id of a default rule replaces it) or no `useDefault = true`: `gl_cfg_problems`; the hooks and the history scan do not trust a committed file with any of these and use the default-only config instead). Every gitleaks call passes `-c` explicitly (the committed file when it is non-empty and has `useDefault = true`, else a temp config with only the default rules; never the working file): without `-c` gitleaks auto-loads `<source>/.gitleaks.toml` or `$GITLEAKS_CONFIG`, and an empty file there has no rules (a truncated committed config used to silence all three gates); the lint FAILs on an empty or missing committed config, and `cmd-notify`'s `gitleaks stdin` runs from `/` with the same default-only `-c`. Never run `gitleaks dir` on the repo root: it also reads the gitignored `env.secret.sh` and `private/`.
- **Shell history (atuin, local only)**: Ctrl+R lists the atuin database in the shared modal fzf (`[I]/[N] history>`, ua/ru twins and palette from vimfzf; the widget keeps the name `fzf-history-widget`, and the old zsh-history list stays as the fallback while the database is missing). **Tab / Shift+Tab** (NORMAL `l` / `h`) cycle the filter `global -> workspace (git repository, skipped elsewhere) -> directory -> session`, the header shows it, the preview shows exit status, duration, age, directory and the full command (multi-line commands survive); Enter puts the command on the line, never runs it. Rows and cycling come from `.config/fzf/atuin-history.sh` (`rows` uses `atuin search -r`: without a terminal atuin prints oldest first), the widget is `.config/zsh/history.zsh` (+ labels `atuin` / `complete` in `_df_vf_load` of `vi-mode.zsh`). There is NO `atuin init` and no daemon: `.config/zsh/cmd-hooks.zsh` stores line, directory and start time in preexec and forks ONE background job in precmd (`atuin history start --hook` then `history end` with exit status and duration; about 0.35 ms per command in the test, the upstream hook is 6 ms synchronous). atuin has no timestamp option, so the stored time is the FINISH time of a command (duration and exit are exact); `ATUIN_SESSION` is a fresh id per interactive shell (never inherited). No Up/`k`/`/` rebinding, no Atuin AI bind, autosuggestions keep zsh's history strategy. A leading space, a command with a literal secret (`DF_SECRET_CMD_RE`, matched lower-cased; variable references do not count) and a plain assignment with a literal value (`export X=value`, `typeset`, a bare `X=value`; a value with `$` is recorded) are never recorded; zsh's own `~/.zsh_history` keeps being written. The regex covers keyword assignments (`password=`, `token=`, `api_key=`, ...), header-style `"X-Api-Key: value"` inside quotes (a bare `password: x` as in `grep password: src/` or a commit message is NOT a secret), URL credentials (`scheme://user:pass@host`, not `$VAR@` and not `host:8080/pkg@v`), `mysql -pVALUE` (the mysql/mariadb family only: `find -path`, `ls -plah` stay), `login ... -p VALUE`, `bw unlock VALUE` and `bw login EMAIL PASSWORD` (`bw login EMAIL` alone is not a secret: the password is prompted), `curl -u|--user USER:PASS` (not `-u USER` and not `:$VAR`), `--password VALUE` (any value) and the token shapes `ghp_` `glpat-` `xox*` `sk-` `sk-proj-` `sk-ant-`. **Argv exposure**: atuin takes the command as an argument (`history start` has no stdin or env form), so a recorded command sits for a few ms in the world-readable `/proc/PID/cmdline` of the background job (no `hidepid`; td, yc, aimcp, tgconfirm are local users); the secret test, the assignment skip and `history_filter` keep the likely carriers out, the rest is the same exposure an external command's own argv always had. Config `.config/atuin/config.toml`: `auto_sync = false`, `sync_address` an unroutable `127.0.0.1:9`, no update check, `[ai]`, `[daemon]` and `[logs]` off (logs would create `~/.atuin`), `secrets_filter` and `history_filter` (= `(?is)` + `DF_SECRET_CMD_RE`, kept identical by the test: a second live layer, and what `atuin history prune` applies; the `s` flag because Rust's `.` skips a newline while zsh's ERE does not, so a command continued with a backslash + newline was hidden by zsh and recorded by atuin; the test also runs the filter as PCRE over every table row and says SKIP for the real-atuin part when atuin is not installed). The first interactive shell without a database imports `~/.zsh_history` once in the background (`flock` on `~/.local/state/atuin-import.lock`; `install.sh` does it too) and then runs `atuin history prune`, because the import itself is unfiltered (atuin's `secrets_filter` and `history_filter` only apply to live recording): without the prune an `export API_TOKEN=...` of the old file would be in Ctrl+R. td/yc get it through the cli profile (`.config/atuin`); their database is in their own home. The hook files are skipped for agent shells (`CLAUDECODE`).
- **Completion (carapace gap filler, fzf-tab on the modal look)**: `.config/zsh/completion.zsh` (after oh-my-zsh; skipped for agents). carapace (AUR `carapace-bin`) only fills the gaps: `compdef _df_carapace_default -default-` runs for commands without a zsh completion (lazygit, glab, k9s, hurl, tailscale, atuin, ...); the first Tab on one loads `~/.cache/zsh/carapace.zsh` (rebuilt when the binary is newer; the script is `carapace _carapace zsh` minus the `compdef` line and the PATH line, plus a lookup table of the 993 known commands) and calls `_carapace_completer` when it knows the command, else `_default`. Native completions (git, docker, systemctl, pacman, ssh, ...) are never replaced, a command that later gets a zsh completion stops using carapace by itself, startup cost is zero (`source <(carapace _carapace zsh)` overrides ~1000 completions and costs ~4 ms per shell). No bridges, no spec shims. fzf-tab (already a plugin) gets the vimfzf look through the lazily evaluated zstyle `fzf-flags` (`_df_vf_opts[complete]` from `vi-mode.zsh`) and `fzf-command _df_ftb_fzf` (passes `VF_ACT_NORMAL`): `[I] complete>`, typing filters, Esc = `[N]` with `j k g G v / i a q` and the ua/ru twins, Ctrl+j/k/d/u, Tab / Shift+Tab move, **Ctrl+L accepts and continues** (the continuous trigger; it was `/`, which has to keep typing in INSERT, and Alt+L belongs to tmux, whose root table passes Ctrl+L to fzf), F1 / F2 switch the group; group headers `[%d]`, `menu no`, `list-colors` from `LS_COLORS`, `cd` previews with `eza`.
- **difftastic next to delta**: delta stays `core.pager` and `interactive.diffFilter`; difftastic (`difft`) is for when the structure matters: `git dft` (difftool with the `difftastic` tool, `prompt = false`, any `git difftool` arguments), `git dlog` and `git dshow` (`-c diff.external=difft log/show -p --ext-diff`), and a second lazygit diff renderer in `.config/lazygit/config.yml` (`git.diffRenderers`: `delta` = `pager.sh`, `difftastic` = `extDiff` with `{{colorScheme}}`; `|` cycles; lazygit migrated the old `pagers:` key itself). Nothing changes by default; a missing `difft` shows an error only when the owner cycles to it (doctor `difftastic` is INFO then).
- **Long-command toast**: a command that ran at least `DF_CMD_NOTIFY_MIN` seconds (30, `0` = off in that shell) and finishes while its terminal is NOT in front shows a toast: summary `Finished in 1m 42s` / `Failed (exit 2) after 1m 42s`, body = the command (80 characters, one line, markup escaped) and the directory, app `terminal`, 15 s; a click (also `SUPER+ALT+X`, "Focus") focuses the window and, in tmux, switches the client to the session and selects the window and pane. The zsh side is `.config/zsh/cmd-hooks.zsh` (the settings are at its top, override them in `~/.zshrc.local`; same file as the atuin recording): one background `setsid -f` of `.config/hypr/scripts/cmd-notify.sh notify`, the command text in `$DF_CMD` (never argv). "In front" = the Hyprland active window is the terminal window of the shell AND (no tmux, or the pane is the active pane of the active tmux window), so a long build in another tmux window of the focused terminal does notify. A tmux inside a pane of another tmux is followed to the outer server (the inner client's parent chain ends in the outer `tmux: server`; the pane's shell holds the outer `$TMUX` / `$TMUX_PANE`): in front needs the inner AND the outer pane active, and a click selects the outer window (the inner pane stays as it is). The worker finds the window by walking the parent chain (of the shell, or of the tmux clients attached to the pane's session) to the first process that owns a window (`hyprctl clients -j`; several windows of one process, e.g. ghostty Ctrl+Shift+N: only the window titled `<session>:...` counts; without a title match the window cannot be named, so the shell counts as not in front and the toast has no Focus action: the focused sibling window never silences a toast; for a shell OUTSIDE tmux the pty route names the window first: the terminal's child tree lists every shell of the process, the prompt title (ghostty `title` shell feature) is the shell's directory with `$HOME` as `~`, so the shell's window is the one window with that title when no other shell of the process sits in the same directory AND every window of the process is titled with the directory of one shell of it (a window still showing the finished command, because the title update races the toast, or an ssh window that happens to show our path makes the route undecidable: toast, no Focus action); the outer-tmux walk runs only for a client that owns no window at all); a shell without a findable window still gets a toast, without the Focus action. Hyprland is `$HYPRLAND_INSTANCE_SIGNATURE` when it answers, else the newest live instance in `$XDG_RUNTIME_DIR/hypr` (tmux outlives Hyprland, its environment can be stale); no reachable Hyprland (td, yc, a TTY) = silent. Never for: agent shells (hooks not installed), ssh logins (`SSH_CONNECTION`), a command with a leading space, interactive programs (`DF_CMD_NOTIFY_IGNORE`, matched on the first word of the alias-expanded line (preexec's `$3`, so an alias like `lzd` works) after `sudo` / `doas` (with their options and option arguments: `-E`, `-u root`, `--user root`, `-Eu root`), `nice -n 10`, `env -u X`, `time -f F`, `command`, `nohup`, `exec`, `VAR=x`: nvim vim vi less man ssh tmux lazygit lazydocker htop btop yazi claude codex gemini top watch fzf hub). A command matching `DF_SECRET_CMD_RE` or flagged by `gitleaks stdin` shows as "(command hidden)". The toast stays in dunst's history, so desktop-ro's `notifications_history` hides the whole app `terminal` (`NOTIF_HIDE_APPS`): no agent reads typed command lines from it. Switch: hub toggle row "Long-command notifications" (leader `n l`; `cmd-notify.sh on|off|toggle|status`, state file `~/.local/state/cmd-notify/off`, read on every run so it is live without a shell restart). `cmd-notify.sh locate --pid PID` prints `address, tmux socket, session, window id, pane id, client tty, focused` (read-only; a later "jump to the agent's tmux pane" can reuse it). Test hooks: `CMD_NOTIFY_HYPRCTL`, `_HYPRD`, `_NOTIFY`, `_TMUX`, `_STATE`, `_DRY=1`.
