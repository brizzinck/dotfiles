# Telegram archive (tg-archive)

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Telegram archive (tg-archive)
Whole Telegram chats (channels, groups, forums) as local Markdown folders an agent can search and answer from: text, replies, forwards, reactions, every file the owner asked for, voice / video-note / audio / video **transcribed locally** with timestamps, video frames chosen by the agent and placed where the speech refers to them, OCR of photos and frames, text of PDFs and text files. One prompt: the Claude Code skill **`/tg-archive`** (`.config/tg-archive/skills/tg-archive/SKILL.md`); questions: **`/tg-ask`** (`.config/tg-archive/skills/tg-ask/SKILL.md`). Both are linked as `private/.claude/skills/<name> -> ../../../.config/tg-archive/skills/<name>` (`~/.claude/skills` is the private repo's folder; doctor `tg-skills`).

**Download inside the MCP service, no second session.** Telegram allows one live Telethon process per session, so the download is the MCP tool `export_history` of the existing read-only server (`infrastructure/mcp/telegram/chat_export.py`, registered by `serve.py` like `call_metadata.py`), with the same session, chat allowlist and gateway; nothing is sent to Telegram. `serve.py` `check_env()` accepts `read-only` or `read-only+` a subset of `LOCAL_FILE_TOOLS` = `download_media`, `export_history` (they read Telegram and write files below the export folder only; any other `+` tool, an empty `+` list or the `-` syntax refuses to start). `run` adds them (`TELEGRAM_EXPOSED_TOOLS=read-only+download_media,export_history`, `TELEGRAM_EXPORT_DIR` = `TELEGRAM_ALLOWED_ROOTS` = `/srv/telegram-export`, `TELEGRAM_SERVER_ROOTS_ONLY=1`) only while that folder is a writable directory, else stays plain read-only and unsets the root variables (upstream exits when an allowed root cannot be created). The unit has `ReadWritePaths=-/srv/telegram-export`. `apply-system.sh --only mcp` (`mcp_export_dir`) creates it `aimcp:aimcp 0700` with the ACL `u:OWNER:rwx` and the default ACL `u:aimcp:rwx,u:OWNER:rwx,m::rwx` on every directory (under a default ACL the service's `UMask=0077` does not apply), so the owner reads and empties it and nobody else can (doctor `tg-export`, INFO until created). The gateway `toolFilter` allows both names (19 tools); the test and doctor deny-pattern for write tools exempts exactly these two.

**export_history(chat_id, media=true, kinds='all' (or a comma list of photo, voice, video_note, video, gif, audio, document; unknown names refuse), max_seconds=40 (10..45: upstream cancels every tool after 55 s, `TELEGRAM_TOOL_TIMEOUT_SECONDS`; tg-archive asks for 40 and simply calls again after a `GEN-TIMEOUT`, at most 5 in a row), max_file_mb=4000, restart=false)**: per call, the history after `state.last_id` oldest first (`iter_messages(min_id, reverse=True, wait_time=0)`; flood waits sleep up to `TELEGRAM_FLOOD_SLEEP_THRESHOLD`) appended to `<id>/messages.jsonl` (normalised records: id, date UTC, edited, from {id, name, username}, author, out, text as Telethon Markdown, action {type + scalar fields}, reply_to, topic, forwarded {name, id, date, post}, grouped_id, views, forwards, replies, reactions, media {kind, file, name, mime, size, duration, width, height, title, performer, url/title/description for link previews, poll question/answers/votes, geo, contact, dice}), then queued files into `<id>/media/<msgid>-<safe name>`, **8 at a time** (`PARALLEL`; one file is a chain of 512 KiB round trips, a single stream gave 0.3-5 MB/s on a 500 Mbit/s line; the first 300 queued messages are looked up per call): photos with `download_media`; documents of 8 MB and more over a **connection pool** (`Pool`: `CONNECTIONS` = 8 extra `MTProtoSender`s to the file's DC, one `upload.getFile` of 512 KiB in flight on each, written with `pwrite`; on the home DC with the session's auth key + `InvokeWithLayer(InitConnection(help.getConfig))`, on another DC the first connection imports an exported authorization like Telethon's borrowed sender and the others reuse its key; the pool is kept between calls; a CDN redirect marks the document for the single stream, a lost connection drops the pool; after the deadline the file is cut back to its contiguous prefix), smaller ones with `iter_download` in 512 KiB requests; everything into `.part`, resumed by the next call (offset cut to whole requests: Telegram needs `offset % limit == 0`). Measured before the pool: about 1.3 MB/s per file stream whatever the line, 4-5 MB/s with 8 files at once. `state.json` (saved every 200 messages and after every file, so a cancelled call loses nothing) keeps last id, message count, `pending`, `done`, `skipped` (too big, gone), `failed` (exception class; `restart` retries), `excluded` (kinds the caller did not ask for: no download, their `.part` deleted, reconsidered after `restart`). A link preview with a picture is kind `webpage` (checked before `photo`, which also answers for previews). Stickers, polls, geo etc. have no file. One export per chat at a time (asyncio lock). **Hardening after review** (2026-10-23): the deadline counts from the start of the tool (lookups included); a pooled file keeps a `Progress` (contiguous prefix of landed 1 MiB requests) and the `.part` is cut back to it in a `finally` on EVERY exit (deadline, server error, cancellation by the upstream 55 s timeout), so a resumed file never has a hole; a pool flood wait that would outlast the deadline stops the worker (`StopSlice`); transient errors (flood, timeout, lost connection, `ServerError`, `RpcCallFail`) leave the file queued and count `attempts`, after `MAX_ATTEMPTS` = 8 it is failed; before each file `shutil.disk_usage` must leave `MIN_FREE` = 2 GiB (else `disk_low`, the file stays queued); the owner can write the export folder, so nothing follows a planted link: `safe_dir` refuses a symlinked chat or media folder, every file is opened with `O_NOFOLLOW` (`.part`, `messages.jsonl`, `state.json` read and its `.tmp`), photos are fetched to memory and written the same way, renames and unlinks never follow; `refetch='ids'` removes those files and queues them again. The first pool version (before the hardening) left zero-filled gaps in 3 big videos of the first archived channel (3-6 blocks of 512 KiB each); tg-archive now finds such files. Returns `{chat_id, title, kind, dir, new_messages, messages_total, history_complete, media_pending, media_done, media_skipped, media_failed, bytes, done, next}`.

**`tg-archive`** (`.local/bin/tg-archive`, stdlib Python; `--help` is the reference): `chats [QUERY]` (gateway `list_chats`, titles with control/bidi characters shown as `<U+XXXX>`), `run CHAT... [--files KINDS] [--max-file-mb N] [--no-media] [--refresh] [--lang L] [--no-process] [--detach] [--folder NAME]` (`--files` default `photo,video,video_note,voice`, the owner's choice: APKs, archives and PDFs are listed as not downloaded, a later `--files all` fetches them; `--max-file-mb` is the tool's `max_file_mb`: the big videos are most of the time, in the first archived channel 3 videos were 72% of 8.25 GB; the progress line shows MB/s and the bytes left with an estimate), `export`, `process [--retry]`, `frames [--all] [--json]`, `render CHAT|--all`, `list`, `status`, `path`. It talks to the gateway itself (`mcp-gateway url telegram` + `mcp-gateway headers`, MCP streamable HTTP, never prints the token; `TG_ARCHIVE_GATEWAY` is the test hook), calls `export_history` until `done`, then **imports**: `messages.jsonl` is renamed to `importing-<ns>.jsonl` (an interrupted import is picked up next time) and merged by id into `.raw/messages.jsonl` (last wins: `--refresh` updates edits), files are COPIED (so they belong to the owner, not to aimcp) and the export copies removed; `.part` files stay for the next call. A title resolves through archived chats, then the allowlisted chat list; an id, `@username` or `t.me` link is passed through. **Not connected** (exit 4): a title that is not in the list, or upstream's answer for a chat outside the allowlist (`Access to chat ... is restricted by privacy policy (TELEGRAM_ALLOWED_CHAT_IDS)`: plain text, NOT an `isError`, so before 2026-10-23 it surfaced as "export_history returned no status"), prints the owner's steps: join the chat in Telegram (the MCP never joins; `mcp-telegram-setup`'s picker lists the 300 most recent dialogs, so pin an old one), `mcp-telegram-setup chats` (tick, Enter, Y, sudo), run again. **Settings** (`.raw/settings.json`: media, files, max_file_mb, lang): written at the first slice of a run; a later run, `process` and `status` use them, a flag given again changes them (`--files` / `--max-file-mb` turn files on after `--no-media`). `requeue_ids` (after `import_media`, so a finished file waiting in the export is not missing) sends what the choice now wants and the service will not fetch by itself as `refetch` (at most 1000 ids per call, no history re-read): kinds left out before (`excluded`), files of an earlier `--no-media` run (never queued), files skipped as `bigger than N MB` when the limit is now larger (`skip_retry`); files the service fetched once (`done`), failed ones and the damaged ones (`refetch_box`) are not asked for again; with `--refresh` only the size skips (the restart queues the rest). **Reconnect**: `mcp-telegram-setup chats` re-seals and restarts the service and the gateway; an HTTP error, an unreachable gateway, a JSON-RPC (protocol) error or a tool error mentioning a connection makes `export_loop` wait (`BACKOFF` doubling, at most 30 s), open a new session (`Gateway.reconnect`, up to `TG_ARCHIVE_RECONNECT` = 180 s) and call again, at most 5 times in a row; a 401 is not retried. `status` shows the choice, the download queue (service `state.json` `pending` x the archived sizes, minus the `.part` bytes) with the time at 5 MB/s, and the files a larger `--max-file-mb` would fetch. `flock` per chat (`$ROOT/.lock-<id>`). **Folders of chats**: `--folder NAME` (a plain name, `\w[\w.-]*`) keeps the archive in `$ROOT/NAME/<chat>/`; an archive found elsewhere is moved there under the chat lock (refused when the target exists). `archives()` looks at `$ROOT/*/` and one folder level below (a directory without `.raw/` is a folder), so `list`, `path`, `status`, `render --all` and a hand `mv` into a folder all work. `--detach` = `systemd-run --user --unit tg-archive-<time> --collect` (Nice 10, idle IO).

**Pipeline** (`run`): `export_history` slices run in a thread and the export's `messages.jsonl` is merged between two calls (`import_messages`, the only moment nothing appends to it); the main thread copies finished files at any time (`import_media`: the service renames a `.part` only when complete), processes them as they arrive and renders every 5 minutes, so the archive is usable before the last big video is down and transcription overlaps the download (the account's download cap, about 5 MB/s, is the bottleneck otherwise). The chat lock is held for the whole run; a second run waits for it. **Process** (cached per message and step, failures in `.raw/process-failed.json` per step, `--retry`): whisper runs one file at a time in the main thread (the GPU) while `CPU_WORKERS` (cores/2, 2..6) threads do OCR (`OMP_THREAD_LIMIT=1` per tesseract), frame candidates and document text. Voice / video note / audio / video -> ffmpeg 16 kHz mono WAV -> `whisper-cli -l auto|LANG -oj -np -sns -t 4 --vad -vm ggml-silero-v6.2.0.bin` with `ggml-large-v3-turbo.bin` from Voxtype's model folder (fallback `ggml-small.bin`, `TG_ARCHIVE_WHISPER_MODEL`), Vulkan through `ggml-vulkan`, about 9x realtime -> `.raw/asr/<id>.json` (`v` 2, `vad`, `segments: [start, end, text]`). **VAD** (silero v6.2.0, 885098 bytes, pinned to the `ggml-org/whisper-vad` commit and sha256 in the script, downloaded once into `~/.local/share/tg-archive/models/`; `TG_ARCHIVE_VAD_MODEL` overrides, `''` = off; no network = no VAD with a warning) makes whisper hear only speech: without it silent and music videos came out as "Субтитры сделал DimaTorzok", "Thank you." and endless loops, with it a 475 s video gave 29 real phrases. `clean_segments` also drops whole segments of known inventions (`JUNK`, `JUNK_EXACT`: subtitle credits, a lone "thank you" / "music"), collapses a word repeated 4+ times and consecutive identical segments. A transcript older than `ASR_VERSION` is redone by the next `process`. videos of 15 s and longer -> frame candidates (`select` = first frame, scene change > 0.3 at least 2 s apart, one per minute of a static scene; max 80, evenly thinned; 1280 px JPEG) with `tesseract -l rus+eng` OCR each and 4x4 numbered contact sheets (`drawtext` of `n+1`) in `.raw/frames/<id>/`; photos and image documents -> OCR (`.raw/ocr/`, kept when at least 12 word characters); PDF -> `pdftotext -layout`, text-like files -> UTF-8 text (`.raw/text/`).

**Damaged files**: `import_media` checks every new file of 8 MiB and more (not disk images) for whole zero-filled 512 KiB blocks and does not import a damaged one: it goes to `.raw/refetch.json` `pending`, the next export call sends `refetch` once (then `sent`, so a file that really contains zeros is imported on the second pass); `tg-archive verify CHAT|--all` does the same for files already in the archive and removes what was made from them (transcript, OCR, frame candidates, picks); `run --verify` verifies first. File names from the service must match `^\d+-[\w.+-]+$` and are never links (import and `media_path`). **Robustness**: `run` takes the chat lock BEFORE the export thread starts (a second run waits, no two imports race); ffmpeg / tesseract output is decoded with `errors='replace'` and any exception in one processing step is recorded in `process-failed.json` instead of stopping the run; a restart is sent only once even after a `GEN-TIMEOUT`; no progress for 2 calls = a pause of `TG_ARCHIVE_BACKOFF` (5 s) doubling to 60 s, 12 calls = exit 1; `disk_low` = exit 1 with the hint; link texts built from file names and titles escape `[` `]`. **When it was said**: every transcript paragraph (`paragraphs`, at most 30 s, a break at a sentence end after 15 s) starts with `stamp()` = `**[m:ss](../media/<file>#t=<s>) · HH:MM**`: the place in the file as a W3C media-fragment link (a browser starts the player there; Obsidian may open the file at the start) and the local clock time. `recorded()` gives the start: a voice message or video note is recorded in Telegram right before sending, so sent (a forward: its original date) minus the duration; a video or audio file uses its metadata (`created_tags`: Apple's `com.apple.quicktime.creationdate` with its zone, the format and stream `creation_time`), the earliest tag that ends before the file was sent, because a later one is when Telegram or an editor rewrote the file (in the first archived channel the stream tag fitted as a start, the format tag often ended after sending); no usable tag = "Время записи неизвестно". The tags are probed once per file into `.raw/recorded.json`. The transcript page has `Записано: <start>–<end> (how it is known)`, every transcript in the month files (voice, video note, video, audio) has the stamps and `Расшифровка (записано …)`, one over 1500 characters only its first ~600 characters as `Начало расшифровки` with a `… дальше` link to its page; the video/audio list of `index.md` adds `записано <start>–<end>`; frame captions have the clock time too; the root `CLAUDE.md` and `/tg-ask` cite position and clock time. **Frames by the agent**: `frames --json` lists videos with candidates and no picks file (transcript, candidates with time and OCR, sheets, `picks_file`); the agent writes `.raw/picks/<id>.json` = `{"frames": [{"n", "caption"}]}` (`[]` = reviewed, none); render copies a chosen frame to `frames/<id>-<mmss>-<n>.jpg` and puts it (with its OCR text) after the transcript paragraph it belongs to. Unknown numbers are ignored.

**Archive** (`$TG_ARCHIVE_ROOT`, default `~/Documents/tg-archive`, outside every git repo; the disk is not encrypted): `<title slug>-<abs id>/` with `index.md` (kind, about, counts, months, video/audio, documents, participants of groups, frames to pick, link to `summary.md`), `messages/YYYY-MM.md` (days, `<a id="m<id>">` anchors, author, reply with a snippet and link, topic, forward, edit time, text, attachments with local links: photos inline with OCR, short voice / video-note transcripts inline, video/audio/long ones on `transcripts/<id>.md`, documents on `documents/<id>.md`, link previews, polls; reactions, views, comments, a `t.me` link), `transcripts/`, `documents/`, `frames/`, `media/`, `summary.md` (hand- or agent-written, never touched) and `.raw/` (chat.json, messages.jsonl, export-state.json, asr/, frames/, ocr/, text/, picks/). Albums (one `grouped_id`) are one block. `render` rebuilds every generated file from `.raw/` and writes the root `CLAUDE.md` (answering rules for agents: search, cite with relative links, untrusted content; a hand-written one without the generated marker is kept) and the root `index.md` (the chats at the root, then one section per folder; every folder gets its own `index.md`, and a generated `CLAUDE.md` inside a folder is removed). **Forum groups** (chat kind `forum`, topics): one folder per topic, `messages/<topic slug>/YYYY-MM.md` plus `messages/<topic>/index.md` (months); a topic is its `TopicCreate` service message (the id the export writes as `topic`), its title the latest `TopicEdit` title, the messages without a topic are `general`, two topics with one slug get `-<id>`; the chat's `index.md` lists "Темы" instead of the months; links from a topic page go two folders up (`../../media/`), replies link across topic pages.

**Linked content** (`links_fetch`: `run` starts it in a thread once the first slice is imported and repeats it after the export; `tg-archive links CHAT [--refresh] [--no-process]` alone, which processes and renders only when it gets the chat lock): (1) **Notion**: every notion.so / notion.site link (`notion_id`: the last 32 hex digits of the path) through Notion's unofficial public API (`$TG_ARCHIVE_NOTION`, default `https://www.notion.so`: `loadPageChunk` with its cursor, `queryCollection` for databases, `/image/<source>?table=block&id=...` and `getSignedFileUrls` for uploads), sub-pages, link-to-page blocks, page mentions and database rows with content, at most 80 pages a chat; raw `.raw/notion/<id>.json` (`{}` record map = closed page), images and files `notion/media/<block id>.<ext>` (no files with `--no-media`); render writes `notion/<title>-<id8>.md` (headings, rich text, lists, to-dos, toggles, quotes, callouts, code, tables, databases as tables, bookmarks, a YouTube block linking its transcript, the messages that link the page, the parent page). (2) **YouTube** (`YT_LINK`: watch, live, shorts, embed, youtu.be; from the messages and the Notion pages): `yt-dlp -J` metadata (title, channel, upload day, a stream's `release_timestamp`, description, chapters) and the video at up to 720p (slides stay readable) into `media/yt-<id>.mp4`; `.raw/linked.json` gives each video a negative record id, so `cmd_process` (whisper, frame candidates), `frames --json` and the picks work unchanged (`linked_records`); a video another archive already has is hard-linked with its transcript (`youtube_share`); a private or deleted one keeps its `status`, which the message shows and which is never retried (set it by hand to note why, e.g. a stream without a recording). The page `transcripts/yt-<id>.md` has the description, the chapters and every paragraph stamped with `↗` = the same second on YouTube; a stream is timed from its live start (`recorded`, source `live`). (3) **Files** (`FILE_LINKS`): Google Drive (`drive.usercontent.google.com/download?...&confirm=t`), Google Docs/Slides/Sheets exports (PDF, XLSX) and direct `.pdf` links into `media/gd-<key>.<ext>`; the name comes from `Content-Disposition` (`disposition_name`: RFC 5987 first, a plain name is Latin-1-decoded UTF-8); an HTML answer = not shared; a PDF gets its text (`documents/gd-<key>.md`), a video or audio file a transcript. (4) **Web pages** (`web_links`: not Telegram, video, Notion, Google or social sites, not a bare home page, not a sign-up / invite / promo link): telegra.ph through its API, any other page as the `<article>` / `<main>` / `<body>` text (`HtmlMd`, page chrome dropped; under 200 letters = not kept, with the reason) in `.raw/web/<key>.json`, rendered to `web/<key>.md`. Every message names what its links led to (Notion page, YouTube transcript, file and its text, page, or why not), and the chat's `index.md` lists them. Instagram is not downloaded (the owner's choice).

**Discussion group (comments)**: a channel's comments live in its linked group, where every post arrives as an automatic forward sent by the channel itself (`channel_copy`: `forwarded.post` and `from.id == forwarded.id`). Such a copy's files are the channel archive's (tens of GB of video in a big channel): `requeue_ids` never asks for them and `prune_copies` moves them from the service's `pending` to `excluded` between two calls (in place, so `state.json` keeps its owner and ACL); read a big group's history with `--no-media` first, then run it with files. Render gives every thread (the copy, its album, every message whose `topic` or reply chain leads to it) `comments/<post>.md`, with the original post linked in the channel's archive (`chan_link`), writes `.raw/threads.json` (`{channel id: {post: {page, count, date}}}`), lists the threads in `index.md` and keeps only the other messages in the month pages; the channel's render reads the threads of every archive and links each post's comments (`💬 комментарии: N`). Render both (`render --all`) after either changes.

**Remote whisper** (`tg-archive remote setup USER@HOST | status | off`): a second whisper on another machine's NVIDIA GPU over ssh (key login; `uv` there; no root): `infrastructure/tg-archive/remote-whisper/` (`run`: flock, the CUDA libraries of the venv's wheels; `transcribe.py`: faster-whisper large-v3-turbo int8_float16 with its VAD, a WAV on stdin, whisper.cpp JSON out) goes to `~/tg-whisper` with a venv of faster-whisper, nvidia-cublas-cu12 and nvidia-cudnn-cu12, checked on a second of silence; the target is kept in `$XDG_STATE_HOME/tg-archive/remote-whisper` (`TG_ARCHIVE_REMOTE_WHISPER` overrides, empty = off). `cmd_process` sorts the transcripts by length: the local whisper takes the shortest, a thread the longest from `REMOTE_MIN` (120 s; the remote loads its model per file); a remote that does not answer (`RemoteDown`) hands its job back. `tg-archive remote all` sends every file there (the local whisper only takes what a dead remote leaves; `remote long` goes back to the split; the mode is the second word of the state file, `TG_ARCHIVE_REMOTE_ALL=1` overrides). A YouTube video another archive already transcribed is copied (`youtube_asr`), checked again right before the job runs. An RTX 2060 SUPER does about 28x real time (the laptop's iGPU 6.5x).

**Agent steps** (skill `/tg-archive`): picks frames while the run is still going; for chats under about 2000 messages writes `summary.md` (topics with message links) and never copies secrets into it, only a "Sensitive data" section naming the kinds (a chat can hold passwords, keys and document photos whose OCR text is searchable: the archive is as secret as the chat). **Owner steps**: `sudo ./apply-system.sh --only mcp` once (installs `chat_export.py`, the folder and the unit change, restarts the service), then `mcp-gateway restart` (mcp-proxy reads the `toolFilter` of `gateway.json` only at start; until then tg-archive exits 3 with that hint); a chat must be in the read allowlist (join it in Telegram first, then `mcp-telegram-setup chats`; tg-archive exit 4 prints these steps and the `/tg-archive` skill relays them). **Tests**: `infrastructure/tests/tg-archive/run.sh` (doctor `tg-archive-tests`, about 2 s): fake gateway (`fake_gateway.py`: bearer token, session id, `list_chats`, `export_history` in two slices), fake `mcp-gateway` / `whisper-cli` / `tesseract`, the real ffmpeg on generated media; checks export loop, import (copies, export folder emptied, no duplicates), process caching, every relative link and anchor of the archive resolving, frame picks, summary kept, `--refresh`, `--no-media`, exit codes, the not-connected steps (unknown title, upstream's privacy-policy text), `--max-file-mb` (skip, saved choice, a larger limit refetches without a history re-read), files turned on after `--no-media`, a reconnect after HTTP 503, `--folder` (folder index, list / path, moving an archive in, a path refused), Notion pages (chunks, a sub-page, an image, a database, a closed page), YouTube (download, live start, ↗, a private video, frames), a remote whisper (and one that is down), a discussion group (no copy file asked for, thread page, links both ways), a linked web page and PDF, and a forum group (a folder per topic, a renamed topic, General, replies and media links from a topic page) (the fake keeps the service's `excluded` / `skipped` / `done` bookkeeping). `infrastructure/tests/mcp/test_chat_export.py` (in the telegram-mcp venv) runs `export()` against a fake Telethon client: slices, resume of a big file byte-identical across calls, size limit, restart without re-downloading, path-safe names, records; `test_telegram_serve.py` covers `check_env` and the registered tool surface, `run.sh` the `run` exposure with and without the folder.
