# Layout-independent binds and the shortcut reference

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section; section names quoted in the text ("Users", "Dev tools", ...) are listed there.

### Layout-independent binds (us, ua, ru; Caps toggles)
Rule: every key binding must work while the ua or ru layout is active. Hyprland needs nothing (`resolve_binds_by_sym = false`, binds match layout 1 = us). For everything else, **never hand-type Cyrillic twins**: the single physical-key map is `.config/layout/keymap.tsv`, and `.config/layout/layout.py gen` (stdlib Python, `PYTHONPYCACHEPREFIX=/tmp/pycache`) writes the committed per-tool files: `ghostty/layout-keys.conf` (Alt+physical key sends ESC + us letter: ghostty drops Alt for a Cyrillic character; plus a physical-key twin `ctrl+shift+key_a` of every ghostty keybind on a letter or punctuation key, taken from `ghostty +list-keybinds --default` and the `keybind` lines of `ghostty/config`: ghostty matches a character trigger against the character the layout produces, so Ctrl+Shift+C/V/N/T/W/Q/O/E/F/A/P/I/J never fired on ua/ru; `layout.py gen ghostty` needs the ghostty binary, reload running terminals with SIGUSR2), `tmux/tmux-layout.conf` (twins of every letter bind, read from `tmux list-keys` of a private server that loads the repo `tmux.conf`: rerun after adding tmux binds), `zsh/layout-keys.zsh` (`layout_dup_meta`, `layout_dup_keys` for vi-mode), `layout/layout-keys.sh` (`lk_rofi` for rofi `-kb-custom-N`, `lk_fzf_bind` / `lk_fzf_keys` for fzf letter binds; `vimfzf.sh` uses them for the whole NORMAL mode), `rofi/layout-keys.rasi`, and the nvim `lua/configs/layout_data.lua` (langmap + langmapper.nvim). Vimium C gets `browsers/vimium-c-mapkey.txt`; Obsidian's Vimrc Support plugin has no langmap, so `apps/obsidian/vimrc-twins.txt` holds explicit `nmap`/`vmap` twins (generic keys plus the direct twins of every `nmap` line of `apps/obsidian/obsidian.vimrc`; no INSERT twin of `jj`, Cyrillic words contain `оо`). New fzf letter binds go through `lk_fzf_bind` (or `FZF_MENU_NORMAL_BINDS`, which the library twins itself); rofi custom keys use `$(lk_rofi 'Alt+x')` (the launcher only). `layout.py convert --from us|ua|ru --to us|ua|ru [TEXT]` retypes text as the same physical keys give on another layout (`convert_text()`, used by `llm fix-layout`, see Local LLM).

Insert `jj` and its generated ua/ru twin (U+043E twice) leave Insert; other Insert text is not automatically translated. nvim also switches the keyboard itself (K3, `.config/nvim/lua/configs/layout_switch.lua`, set up from `configs/langmapper.lua`; langmap/langmapper stay as the fallback): InsertLeave remembers the active layout per buffer (`vim.b.layout_insert`) and runs `hyprctl switchxkblayout all 0`, InsertEnter (insert, replace, `c`/`s`) restores it when the keyboard is on us, `:` always gets us (also after Caps in NORMAL), `/` and `?` use the buffer's layout and return to us on CmdlineLeave, terminal buffers are left alone (only a `:` line there gets us and gives the layout back), FocusLost to another app (not another tmux pane of the same terminal class) puts back the layout nvim displaced, FocusGained in NORMAL re-applies us, VimLeave does nothing. hyprctl runs async through one queue; the instance is the cached signature, else `hyprctl instances -j` / `$XDG_RUNTIME_DIR/hypr` newest first, probed with a real `devices` call (tmux outlives Hyprland, so the env signature can be stale); no reachable instance, SSH, TTY or another user = silent no-op. `:LayoutAutoswitch [on|off|toggle]`, `<leader>uk`, `vim.g.layout_autoswitch = false`.

### Shortcut reference (keymap)
One generator, never hand-kept: `.config/keymap/keymap.py` (stdlib Python, wrapper `.local/bin/keymap`) collects every shortcut into `~/.cache/keymap/keymap.json` (rows: block, keys, description, source, optional context/note) and every view comes out of that file. Sources, all read live: Hyprland `hyprctl -j binds` (descriptions of the Lua binds incl. submaps, sorted into blocks by `rules.tsv`; a bind no rule claims lands in "Other Hyprland binds"), the leader menu (`.config/hub/leader build_menu`), tmux (a private server that loads `tmux.conf`; `list-keys -F` against a stock `-f /dev/null` server tells custom from default binds, the `-N` note of a bind is its description, so **give every new tmux bind a `-N "..."`**), zsh (`bindkey` of an interactive zsh on a pty + `.zshrc` functions with a comment and aliases), nvim (`nvim-dump.lua` headless: every mapping with a `desc`, grouped by the `<leader>` prefix in `describe.tsv`), waybar (`L: · M: · R: · Scroll:` hints of `modules.jsonc` and the bar scripts), Telegram and Vimium C json; `static.tsv` holds the committed tables for what cannot be parsed reliably (menu key lists, login screen, layout rules, zsh vi grammar), `blocks.tsv` the block order and texts, `pins.tsv` the "Start here" keys. The cache is rebuilt when a source file mtime or the live Hyprland bind table changes (about 2.5 s, otherwise 0.1 s); `keymap gen` forces it. Commands: `keymap md [--write]` (`docs/keymap.md` is generated, never edit it; `keymap check` and doctor `keymap-doc` fail when it differs from a fresh generation, a pin has no row, a block is empty or a described Hyprland bind is missing), `keymap stats`, `keymap menu` = `SUPER+/` (fzf-menu `--size large`, a fixed 24-cell keys column, the description with the matched words bold, a dim scope tag at the end; compact preview Keys / What / Where / Block / Note / Run; Tab/Shift+Tab or NORMAL `l`/`h` cycle the block shown in the header, `0` all, Enter copies the keys, `Alt+R`/`r` replays a global Hyprland bind through `df_bind_run`). **Search model** (one definition, `search()` in `keymap.py`, mirrored by `apply()` in `page.html`): fzf runs `--disabled` and `change:reload-sync(keymap rows)` (the query arrives as `FZF_QUERY`; `--nth` cannot see hidden fields, and fuzzy matching gave 160 rows for "screen shot"; `--track` is never used with reload-sync, it drops typed characters; `--no-hscroll` would disable `--freeze-right=1`, which keeps the scope tag visible); the query is split into words that must ALL match a row; a word matches a substring of the keys, the description, the block title + scope tag or the row's keywords, and a word of one or two characters only a whole key (`w` finds Super+W, not "window") or a whole word; no fuzzy matching; ties are ordered by block rank, so global Hyprland binds come before the leader menu, menus, tmux, nvim and apps. An empty query in the all view lists the pins ("Start here", scope `start`, pins.tsv order) first, then every row by (rank, index); the Audit block (`MENU_HIDDEN`) is left out of the all view and reached with Tab. `blocks.tsv` has two more columns, `scope` (the tag) and `rank`; `keywords.tsv` (`regex <TAB> words`, matched against the DESCRIPTION only, never the block title, which would hand a word to a whole block; every regex must hit a row, at most 60 rows and not every row of a block of 8+, or `keymap check` fails; anchor with `\b`) gives rows natural search words (screenshot, record, clipboard, password, volume, ...), stored as `kw` in the database (`DB_VERSION` 5). `rows` / `header` / `preview` / `cycle` / `run` read the cached JSON without the staleness check (about 20 ms per key instead of 60 ms); `KEYMAP_DB` points them at a fixture database. Tests: `infrastructure/tests/keymap/run.sh [--quick]` (fixture, live database, the real menu in a private tmux; doctor `keymap-tests`), `keymap page` = `SUPER+SHIFT+/` (hub row + leader `k`): renders `~/.cache/keymap/keymap.html` from `page.html` (Everforest tokens of the active variant, no external fonts or requests, `/` filter, `Esc`, `j k d u g G`, `[ ]` block jump by physical key so ua/ru work; regenerated when the data or the variant changes) and opens it as a new Zen window (`flatpak run app.zen_browser.zen --new-window`; Zen has the `home` filesystem permission, Chrome has not) that the `float-keymap` window rule floats and centers (class `app.zen_browser.zen`, title `^Keymap`). A new tool joins the reference by one collector in `keymap.py` or one row in `static.tsv`.
