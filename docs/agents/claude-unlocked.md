# Claude unlocked (claude-code-router)

Topic file of the agent docs. `CLAUDE.md` holds the index, the rules that apply everywhere and the file of every section.

### Claude unlocked
`claude-unlocked [CLAUDE ARGS...]` (`.local/bin/claude-unlocked`) runs Claude Code on OpenAI-compatible providers (ArliAI, Experiential Labs) through a local claude-code-router (`ccr`, npm `@musistudio/claude-code-router`, pinned 3.1.3 in `infrastructure/dev/user-tools.sh --only claude-code-router`). Ported from the owner's Ubuntu machine (`~/Programs/scripts/claude-unlocked.sh` there). Plain `claude` stays untouched: everything reaches Claude Code as environment variables (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, model tiers, output and context limits) and one `--settings` JSON (no attribution, `/model` picker of every synced model, per-model compact windows, optional goal Stop hook and image-blocking PreToolUse hook). Slim mode (default) drops MCP servers and the tools in `CLAUDE_UNLOCKED_DISALLOWED_TOOLS`.

- **Files**: `.config/claude-unlocked/env` (committed, no secrets: gateway URL, models, limits, slim, goal); `.local/share/claude-unlocked/`: `ccr-config.py` (store: seed, layout, model sync, gateway key, settings, resume model), `patch-router.py`, `router.cjs` (`CUSTOM_ROUTER_PATH`: the stop-condition check goes to the session's own model), `block-images.py`. A caller's `CLAUDE_UNLOCKED_*` variable wins over the env file.
- **Secrets**: ccr keeps provider keys in plain text in its sqlite store and has no `${VAR}` expansion at runtime (tested on 3.1.3: the upstream received the literal string). So the store lives in tmpfs: `CCR_INTERNAL_HOME_DIR=$XDG_RUNTIME_DIR/claude-unlocked` (0700, umask 077). After a reboot the first run creates it with one `ccr start`, then seeds each provider of `CLAUDE_UNLOCKED_PICKER_PROVIDERS` (default `arliai explabs`) through `envs run -g --only <NAME>_API_KEY -- python3 ccr-config.py seed NAME`; a provider without its Bitwarden `Env/global` field is left out with a hint. The gateway client key is ccr's `local-gateway` key, read from the store at every launch; it is never written elsewhere. `--cu-reseed` fetches the keys again, `--cu-stop` stops the gateway. Request logs are off.
- **Never touch `~/.claude/settings.json`**: unpatched ccr's Claude Code profile management (function `ete` in `cli.js`, path from `cu()`, `~/.claude/settings.json` via `os.homedir()`, not the internal home) rewrites it to `127.0.0.1:3456` with an `apiKeyHelper`, which cut plain `claude` off the API once. Two guards: the `cu-no-settings` patch turns `ete` into a no-op, and `ccr-config.py layout` disables `profile` (`enabled`, `claudeCode.enabled`, empty `profiles`). The launcher applies the patches before any ccr start and refuses to start ccr when the `cu-no-settings` marker is missing (e.g. after `sysup` moved ccr forward and the anchor changed). Agents test only with the tmpfs store and never run a bare `ccr` (without `CCR_INTERNAL_HOME_DIR` it creates `~/.claude-code-router`).
- **Patches** (`patch-router.py`, in place in the npm install, backup `*.orig.<time>` of the unpatched file, exit 10 = restart): `cu-ptl2` (both copies of the "All target providers failed." builder in `next-ai-gateway.js`: when the LAST attempt is a 4xx whose message or details name a context overflow, the reply becomes a 400 "prompt is too long ...", so Claude Code compacts and retries; a 5xx stays as it is, so Claude Code reports an outage instead of a fake overflow. The first version `cu-ptl` matched the whole attempts JSON and kept the status: on 2026-10-24 an explabs outage reached Claude Code as "500 prompt is too long" and it retried 10 times; `patch-router.py` upgrades a `cu-ptl` copy in place. The old `cli.js` anchor of the Ubuntu copy no longer matches 3.1.3), `cu-img` (a tool-result image becomes a text note instead of 100k+ tokens of base64), `cu-no-settings`.
- **Restart rule**: the gateway reads its config only at start. Every store write (and an applied patch) stamps `$XDG_RUNTIME_DIR/claude-unlocked/config-changed-at`; the launcher restarts the gateway when that stamp is newer than `service.json` `startedAt`.
- **Model sync** each launch: each picker provider's live `/models`; models flagged without tool support are dropped; a provider that reports context windows (explabs) gets per-model compact windows (`~/.cache/claude-unlocked/model-windows.json`) and output caps (`extraBody` `max_tokens`). A resumed chat (`-c`, `-r [id]`) starts on the model its transcript last used when the router still serves it.
- **Not ported**: the Ubuntu router's "Claude Code API" provider (Claude subscription OAuth token, WebSearch rule) and its request logs.
- **Tests** (manual, 2026-10-24): fake OpenAI upstream on 127.0.0.1, tmpfs store: seed, sync (2 models), gateway start, `claude-unlocked -p` -> `pong` with `arliai/fake-model`; overflow -> `prompt is too long (upstream context overflow): ...`.
- **explabs 500**: an explabs outage or a dead key both answer `500 internal_error` (2026-10-24: `/v1/models` and chat with the stored key and with a made-up key alike; no key gives 401). After a key rotation run `claude-unlocked --cu-reseed` in a terminal: under an agent `envs run -g` asks for human approval, and the stored key stays.
- **Owner steps**: `envs set -g ARLIAI_API_KEY`, `envs set -g EXPLABS_API_KEY` (either is enough), then `claude-unlocked`. The Ubuntu ArliAI account answered 403 "exceeded the maximum context length for FREE (30804/12288)" on 2026-10-24: the PRO plan has lapsed, so the default model fails until it is renewed or `CLAUDE_UNLOCKED_MODEL` points at an explabs model.
